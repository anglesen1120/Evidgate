# ADR-0013 — Time-boxed exception for the picomatch ReDoS advisory (GHSA-fc5q-39xc-vjpf)

Legend: ✅ verified with link · ⚠️ unverified · `[INFERENCE]` · `[DECISION]`.

## Status

accepted (2026-11-18, by the coordinator on the owner's delegation; the owner may override)

## Date

2026-11-18

## Context

`scripts/audit-deps.sh` (stage `audit-deps`, AC6 of 01.7.1-T4.2) runs `npm audit --omit=dev` and fails any finding that is not allowlisted in `scripts/exceptions.json` by advisory id with an ADR. Since 2026-11-17, develop fails that stage with:

```text
fail npm:picomatch@* high GHSA-fc5q-39xc-vjpf — not allowlisted
```

**The advisory.** ✅ [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) / CVE-2026-112366, CWE-1333 (inefficient regular expression complexity): picomatch through 4.0.7 analyses repeated single-branch extglobs incorrectly, so a pattern such as `+(*)` or `+(*a)` compiles to a regex that backtracks exponentially against a short crafted string and blocks the Node.js event loop. GitHub rates it High at CVSS v4 8.7 (`AV:N/AC:L/AT:N/PR:N/UI:N/VC:N/VI:N/VA:H`); npm audit reports CVSS v3.1 7.5 (`AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H`) — the same issue scored on two scales. nvd.nist.gov lists CVE-2026-112366 ✅.

**There is no patch.** ✅ The advisory's *Affected versions* is `<= 4.0.7` and *Patched versions* is **None**; npm still publishes 4.0.7 as `latest` and 2.3.2 as the newest 2.x (`npm view picomatch dist-tags versions`, 2026-11-18). The advisory points at [micromatch/picomatch#194](https://github.com/micromatch/picomatch/pull/194), which is still open, and its own description states that `+(*a)` remains exponential on that branch. No `overrides` entry, fork or git dependency can move the tree out of the affected range, so the choice is an allowlist entry or a red gate.

**Exposure.**

- The only `--omit=dev` chain is **web-only**: `@evidgate/web` → `@angular/localize@22.2.3` → `tinyglobby@0.2.17` → `picomatch@4.0.7`, plus `fdir@6.5.0`'s optional `picomatch` peer (`apps/web/package.json:22-29`, `package-lock.json:1529-1550,16820-16863`). `npm ls picomatch --omit=dev --package-lock-only -w <workspace>` is empty for `packages/cli`, `packages/sdk`, `packages/adapter-junit`, `packages/adapter-playwright` and `packages/test-fixtures`, so the customer-side CLI, Playwright reporter, JUnit adapter and SDK do not ship it. Root tooling (spectral, lint-staged, vitest, @angular/build, @angular/cli) is dev-only and stays in the PR review path, not this gate.
- **Build/localization tooling, not a runtime entry point.** ✅ In the published `@angular/localize@22.2.3` tarball the runtime files `fesm2022/init.mjs:7-11`, `fesm2022/localize.mjs` and `fesm2022/_localize-chunk.mjs` import no glob library; only the CLI bundles do (`tools/bundles/src/extract/cli.js:26,137`, `translate/cli.js:22,340`, `migrate/cli.js:14,71` import and call `tinyglobby.globSync`). The browser build loads `@angular/localize/init` as a polyfill (`apps/web/angular.json:40`) and localizes from the in-repo `src/locale/messages.vi.xlf` (`apps/web/angular.json:11-18,76`).
- **Who must control what.** Upstream, the extractor takes the glob from its `--source` flag (`tools/bundles/src/extract/cli.js:85-89`), tinyglobby compiles it with picomatch (`dist/index.mjs:217-219`) and matches filesystem paths discovered by the fdir crawler (`:228-236`). An attacker therefore needs to control the **glob pattern**; controlling only the matched path is not enough while the pattern is fixed. ✅ In this repository the matcher is **installed but not executed**: no script, CI job or container image invokes `localize-extract`/`localize-translate`/`localize-migrate` and nothing imports `@angular/localize/tools` (repository-wide search, 2026-11-18); extraction is `ng extract-i18n` (`apps/web/package.json:14`, an `@angular/build` builder), not those binaries. No first-party call passes request, upload or repository content into a glob either: a search of `apps/web`, `packages` and `scripts` finds no import or call of picomatch, micromatch, tinyglobby or fdir, and only test imports of `clearTranslations`/`loadTranslations` from `@angular/localize`. ⚠️ Whether the `@angular/build` `extract-i18n` builder reaches `@angular/localize/tools` internally was not traced, and the emitted bundle was not inspected (decision 6).

- **Dev/CI chain.** The dev-tree copies are also inside the affected range: picomatch 4.0.7 (vite/vitest, `@angular/build`, `@angular/cli`→`@angular-devkit/core`, `lint-staged`) and 2.3.2 (spectral→`fast-glob`→`micromatch`, a rollup util) are all `<= 4.0.7`. That chain runs in the CI `web` job (`npm ci --ignore-scripts` then the verify stages, `.github/workflows/ci.yml:207-230`) and in the review image build stage (`infra/review/Dockerfile.web:36,55`), with glob configuration taken from the repository; the workflow triggers `pull_request` (not `pull_request_target`), declares `permissions: contents: read` (`.github/workflows/ci.yml:49-50`) and references no secrets, so a fork-controlled glob configuration can at most burn runner minutes within the job timeout — something a fork-controlled script could already do.

## Decision

1. `[DECISION]` **Allowlist the advisory for 30 days.** Add to `scripts/exceptions.json` one entry keyed `GHSA-fc5q-39xc-vjpf`, naming this ADR, the package `picomatch`, the reason in decision 2 and `"expires": "2026-12-18"`. No `overrides` entry, no dependency or lockfile change, no second exception in the same commit.
2. `[DECISION]` **Residual risk accepted is build-time only.** The unfixed matcher is installed through the localization dependency but executed by nothing in this repository: no script, CI job or image build invokes the localization CLIs, and **no production, browser, server or customer-side runtime path was found** in the production closure established above (the emitted bundle was reasoned from package sources, not inspected — decision 6). The advisory requires an attacker-controlled glob pattern, which only build configuration or a developer command could supply; a committed malicious pattern is already a change under review, and that review-time exposure is the remaining risk.
3. `[DECISION]` **The exception ends early and unconditionally** when either happens:
   - a patched picomatch version is published (`npm view picomatch dist-tags versions --json` shows anything above 4.0.7, or a 2.3.x/3.x outside the advisory's range — today that set is empty, since 2.3.2 and 3.0.2 are both `<= 4.0.7`), and the lock is updated in the same change that removes this entry;
   - a new `--omit=dev` chain appears that passes an untrusted glob pattern or matched string to picomatch (for example a server route or customer CLI that globs request-controlled values).
4. `[DECISION]` **Allowlist scope: the entry matches by advisory id for any `--omit=dev` chain, so it is not chain-scoped.** ✅ `scripts/audit-deps.sh:88-110` looks the exception up by advisory id only; the `package` and `reason` fields in `scripts/exceptions.json` are informational and are never read. A future production dependency that pulls the same picomatch GHSA would therefore also be reported as exempt until the entry is removed, and decision 3's second condition is human-enforced. The 30-day expiry bounds this. A chain-scope assertion in `scripts/audit-deps.sh` (every exempted npm finding's production paths must stay inside a declared chain such as `apps/web > @angular/localize`) is recorded as **follow-up work that needs an owner decision**, because gate scripts are owner-controlled; it was not implemented here.
5. `[DECISION]` **Re-check owner and cadence.** The **coordinator** owns the re-check for the window: run
   `npm ls picomatch --all --omit=dev --package-lock-only --workspaces --include-workspace-root`
   on every PR that changes a `package.json` or `package-lock.json` while this exception is live, and on 2026-12-18 before the entry lapses (the gate stops exempting it from 2026-12-19). At those points also run `npm view picomatch dist-tags versions --json` for a patched release, and `npm audit --omit=dev` plus `scripts/audit-deps.sh --npm-only` to confirm the finding is still the exempted one with zero failing rows. Remove the entry and this ADR's allowance at once when decision 3 fires; do not extend the expiry without a new owner decision recorded here.
6. `[DECISION]` **Stated limit of the analysis.** The browser-bundle conclusion is reasoned from the published package sources and `angular.json`, not from an inspected emitted bundle: no production build exists in the tree, and one was deliberately not run for this change. A later build is the check that confirms it.

## Alternatives rejected

| Alternative | Reason rejected |
|---|---|
| Upgrade picomatch to a patched version | ✅ No patched release exists (`<= 4.0.7` affected, patched: none; latest published is 4.0.7, 2.x is 2.3.2 as of 2026-11-18) |
| `overrides` / fork / git dependency pinning a patched commit | The advisory references [micromatch/picomatch#194](https://github.com/micromatch/picomatch/pull/194), but that PR is not the fix: it is "treat a leading `?` in an extglob body as a wildcard", states "This is not a security fix", and leaves the repeated-extglob defect (the long-standing [#175](https://github.com/micromatch/picomatch/issues/175), only mitigated in #182) unfixed — `+(*a)` still takes exponential time there. Shipping an unreleased fork of a glob matcher used by the build is a larger supply-chain risk than the time-boxed exception |
| Downgrade or drop `@angular/localize` | npm's suggested `fixAvailable` is a semver-major downgrade to `@angular/localize@19.2.25`; the app's i18n contract (ADR-0002, ADR-0008) is built on Angular 22 and `$localize`, so this trades a build-time ReDoS for an unsupported framework combination |
| Move `@angular/localize` to `devDependencies` | It is a real production import: the browser build loads `@angular/localize/init` and every `$localize` message in the bundle depends on it; moving it would break `npm ci --omit=dev` installs of the workspace |
| Leave the gate red and block develop | The finding cannot be fixed by a dependency change in this repository until upstream releases a patch; a permanently red gate trains people to ignore `audit-deps` and blocks unrelated work |
| Blanket `npm audit` suppression (config flag, `--audit-level`, ignore file) | Bends the gate (AGENTS.md "never bend a gate"): it would hide every future advisory, not one reviewed id with an expiry |

## Consequences

- The `audit-deps` stage on develop goes green again while the finding is reported as `warn ... — exempted by ADR-0013`; the exemption is visible in every gate log and expires automatically on the day after 2026-12-18.
- One documented, owner-delegated acceptance of a High-severity build-time ReDoS remains until upstream ships a patched picomatch. **Renewal on 2026-12-18 is the expected outcome unless a patch ships**: the advisory was published 2026-10-19 and reviewed 2026-11-17, the registry shows no release since 2026-08-24, and the referencing PR has been open since 2026-08-13, so a fix inside 30 days is not assumed. Renewal is still an explicit owner decision recorded here, not an automatic extension.
- No application code, schema, contract, lockfile or manifest changes; no migration. The only files are this ADR, the index row and the exceptions entry.
- The exemption is advisory-id-wide, not chain-scoped (decision 4): between now and 2026-12-18 a new production dependency that pulls picomatch would keep the gate green, so the coordinator's per-PR `npm ls` re-check in decision 5 is the detection mechanism that decision 3's second condition relies on. A chain-scope assertion in `scripts/audit-deps.sh` remains follow-up work for an owner decision and was not part of this change.

## Revisit trigger

Reopen this ADR before or at 2026-12-18 (the coordinator runs the decision 5 checks on the expiry date and on any PR that changes a `package.json` or `package-lock.json`), or immediately when a patched picomatch release appears, when a new production dependency chain passes untrusted glob patterns or matched strings to picomatch, when `@angular/localize` stops being a browser polyfill dependency, or when an inspected production bundle is found to include the vulnerable matcher. Renewal is the expected outcome on 2026-12-18 unless a patch ships, and it requires a fresh owner decision with a new expiry; this ADR is not silently extendable.
