## Invariants

- ✅ Import requires `authoring:write`; export requires `authoring:read` (viewer included). Import is a `POST` of the file itself with `format` and `dry_run`, plus a required `Idempotency-Key`; the same key with the same file replays the stored report without a second audit row, a different file under that key is 409 `idempotency_conflict`. Export is a `GET` with `format`, optional `node_id` and `include`: it writes nothing, is `Cache-Control: no-store`, and its filename is fixed, never caller-derived.
- The whole file is validated before anything is written: any invalid row refuses the file and writes nothing. There is **no partial import** and no per-row skip. A refusal is a `422` `ErrorEnvelope` (`details[].index`/`.path`/`.reason`), never an `ImportResponse`: it supplies no valid/invalid totals, and at most 100 details are returned, so unreported rows are shown as unverified rather than valid. A valid file applies in one transaction under one `batch_id`; an all-unchanged file writes nothing and answers `batch_id: null`. Never claim a version from an invalid or dry-run file, and never claim “no versions exist” from a failed read.
- A `dry_run=true` request on a validating file answers the same report with no version row, no code allocation and no audit row; a file that fails validation answers `422` instead. Preview is therefore the dry run; the page must not invent a second validation authority. The report never carries cell text, so preview text is client-read from the operator's own uploaded file and is labelled non-authoritative (`[OPEN]` B2) — status and identity come only from the server report or refusal details aligned by `index`, and outcome totals only from a `200` report.
- `case.code` is the re-import identity: a code naming a live case **updates** it, one naming a soft-deleted case **restores** it, an unknown code with the project prefix creates one, and an empty code allocates a fresh number (at most once per file). This contradicts the mockup's “no upsert” copy, which is not the contract; the UI must state the real effect per row (`create` / `update` / `restore` / `unchanged`) and must never promise a duplicate-resolution policy the server does not have. A code outside the project's `case_prefix` is `code_conflict`.
- Server text normalization and validation win: NFC, code-point counts, closed `priority`/`state`/`kind` sets, 1–100 steps of ≤2 000 characters each, ≤5 000 rows and ≤5 MiB. Never truncate an over-cap file silently; show the server's `limit`/`actual` when present. An empty `state` keeps the existing stored state and new rows take the documented defaults; an import never retires an existing row.
- Export rows are emitted depth first with file-local keys `n…`/`i…`/`c…`, so two exports of an unchanged tree are byte-identical and an export re-imports as the same tree; a text cell starting with `=`, `+`, `-`, `@`, TAB, CR or LF gets one leading apostrophe on CSV/XLSX and the import strips exactly that one back. The UI must not “fix” or pre-escape values, and JSON is never neutralised.
- Export never silently widens scope: project total is context only, a node scope stays that subtree, an explicit selection needs `ids` (`OI-13-502`) and a filtered set is not expressible today. Over-cap scope is 413 with `details[].path = /node_id`, `reason = body_too_large`, never a truncated file. Scan-pending or sensitive artifacts are never downloaded from this screen, and no premium format, cross-project scope or hidden export exists.
- Null is not zero: an absent count, an unsupplied reason/version, an unmetered/unknown value or a missing author renders “Not available / not supplied” with a reason, never `0`. The page never reports a fabricated total, progress, credit or cost; it has no AI call, billing or release action.
- All imported strings, filenames and error text are untrusted plain text: no `innerHTML`, no script/URL execution, no formula evaluation, no silent row drop, and no echo of refused values. 403 and 404 never leak whether another tenant's project or case exists.
