# Evidgate v3 screen foundation

Current design for `apps/web` (owner-approved under delegation 2026-11-22; supersedes the v2 set in `../web-ui/output/`, which stays as history). These are static design mockups, not implementation. Adoption plan: story 09.10.1 in `plans/09-web-ui.md`. `shots/` holds the 1440 px dark capture of every page only; the 1440 light and 900 px captures were left out to keep the folder small, and are regenerated by opening a page with `evidgate-theme` set in local storage.

[FIXTURE.md](FIXTURE.md) is the single record, identity, UTC ledger and translation contract. These static screens do not submit decisions. [00-components.html](00-components.html) is the component sheet; [12-healing-queue.html](12-healing-queue.html) is the approved composition.

## Files and shell contract

| File | Responsibility |
| --- | --- |
| assets/tokens-v3.css | Theme, type, spacing, interaction tokens and dark-surface contrast deltas. |
| assets/components-v3.css | Shared layout, local fonts, controls, responsive states and review disclosure. |
| assets/manifest-v3.js | All 48 sibling destinations, exact sidebar membership/order, contextual parent, fixture identity and allow-listed return resolver. Classic deferred script, also works with file URLs. |
| assets/shell.js | Builds both navigation views from the manifest; account, project, breadcrumb and global screen search; theme, language and sidebar preferences. |

Do not copy nav groups, topbar, account details, global search links, sprite dependencies for shell icons, or the nav/search/notification/account popovers into pages. Keep a page's own sprite only for icons used in its **content**. Remove old page scripts/listeners that render or search global navigation or change shell persona. Keep record finders inside their product surface, labelled “Find candidate”, “Find run”, etc. Search in the topbar indexes all screens by number and both languages; it does not claim to search records.

## Screen page skeleton / migration recipe

Existing pages: keep their head, page content and product overlays; replace the corresponding shell markup with these mounts. Replace NN with the two-digit screen number. Keep no-JS fallback outside the empty mounts. The login screen (02) loads the manifest but **does not** mount a signed-in shell.

~~~html
<head><meta charset="utf-8"><meta name="viewport" content="width=device-width,initial-scale=1"><title data-en="Overview · Evidgate" data-vi="Tổng quan · Evidgate">Overview · Evidgate</title>
<link rel="stylesheet" href="assets/tokens-v3.css"><link rel="stylesheet" href="assets/components-v3.css">
<script defer src="assets/manifest-v3.js"></script><script defer src="assets/shell.js"></script></head>
<body data-page="NN"><a class="v3-skip" href="#main"><span data-en="Skip to content" data-vi="Đến nội dung">Skip to content</span></a>
<noscript><nav><a href="01-app-shell.html">Overview / Tổng quan</a> · <a href="03-run-list.html">Test runs / Lượt kiểm thử</a></nav></noscript>
<div class="v3-shell"><aside class="v3-sidebar" data-v3-sidebar></aside><div class="v3-workspace">
<header class="v3-topbar" data-v3-topbar></header><main id="main" tabindex="-1">
<!-- Page h1, product content and actions first. -->
<details class="v3-review-controls"><summary><span data-en="Design review controls" data-vi="Trạng thái bản mẫu">Design review controls</span></summary>
<div class="v3-review-controls__body"><!-- Prototype state selector and specimens. --></div></details>
</main></div></div></body>
~~~

- Use one collapsed disclosure, **last child of main, after product content**, never pinned over the viewport. Select label: **Prototype state / Trạng thái bản mẫu**. Keep live product controls outside. On 12 move extra action/state specimens inside; preserve the real detail footer.
- Set body data-scope="organization" only for an organization-wide surface; keep its scope explicit beside any consequential product control. For preview-only role switches, explicitly introduce the alternate identity first, then render a dedicated preview with data-persona="ha" or "linh". Default is Minh; viewing an audit actor, author or assigned reviewer does not switch identity.
- Groups count actual menu entries, not fictitious record totals. A linked global destination uses aria-current="page"; its contextual children use aria-current="location" on their parent. G4 Studio 17–20 is reached contextually. Shared account has one entry point in the topbar at all widths.

## Status and action hierarchy

| Meaning | Required presentation |
| --- | --- |
| Waiting / pending approval | Neutral clock + text, v3-badge v3-badge--waiting (KPI icon: v3-tile v3-tile--waiting). Not validated or successful by implication. |
| Over SLA | Clock + explicit duration and “Over SLA”; v3-badge--over-sla / v3-tile--over-sla. Reserve amber in the review workflow for actual overdue records. |
| Validated but awaiting review | Two chips, not one blended label: check + Validated (v3-badge--validated); clock + Awaiting review (v3-badge--waiting). A human Approved chip (v3-badge--approved) requires a recorded decision. |
| Primary action | One per view / active dialog: v3-btn v3-btn--primary, teal. Secondary = v3-btn outline; tertiary = v3-btn v3-btn--ghost. Do not use the legacy inverse/ink treatment for competing primaries. |
| Destructive / unavailable | v3-btn v3-btn--destructive only for destructive confirmation. Use native disabled for unavailable buttons and explain the reason nearby. Neutral disabled style in both themes; aria-disabled alone does not stop activation. |

Text ≥12 px, token colours, WCAG AA contrast (4.5:1 normal text; 3:1 large text and essential controls); visible, unobscured focus, native semantics, Escape for overlays, both languages. Use v3-block__part / v3-block--variant. Mark only text leaves with data-en/vi; accessible names use data-label-en/vi. Group status icon **and text**; original failure, completeness, outcome, proposal validation and human/release decision remain distinct. SVG charts need equivalent text. No page-level horizontal scrolling.

## Route identity and 401 return

All links, including dynamic hrefs, use the **sibling v3 file** below. Never link to ../../../../docs/design/web-ui/output/… . Carry the exact run, revision, evaluation, attempt, artifact, case, candidate and/or release binding being advertised. Destinations must consume and display that identity; when unavailable, name it and show “unavailable” rather than silently falling back to the default run, case or artifact. Preserve supported filters and yield zero matches honestly. Global navigation goes to a screen; record links go to that specific record on the screen.

Use **returnTo** as the sole login parameter. Encode the full allow-listed sibling filename plus supported query and fragment as one value, e.g. 02-login.html?returnTo=06-decision-waivers.html%3Frun%3Drun-1842%26evidence%3Dev-3 . Build it with URLSearchParams, not manual concatenation. On 02 use EvidgateV3.returnTarget(new URLSearchParams(location.search).get('returnTo')); returned .screen, .params and .href drive **both** the displayed destination/record and the actual continuation. Invalid/absent values return null: explicitly offer the neutral 01 Overview destination, with no invented run. Never use an arbitrary URL, basename-extracted path or nested return param. Pass identifiers, never credentials or sensitive form data.

Return context is **not** a fixed key list. Accept at most 24 decoded query parameters, each key once. Keys must match `^[a-z][a-z_]{0,23}$`; each value must be nonblank, at most 160 characters, contain no control characters, `://` or `..`, and must not begin with `/`. For example, `rerun_scope`, `cursor`, `actor`, `query` and `selection` follow the same rule as `run` and `evidence`. An invalid key, value, duplicate, excess parameter or unlisted destination invalidates the **whole** return (`null`); never drop a filter, open a substitute record, or redirect to the raw input.
