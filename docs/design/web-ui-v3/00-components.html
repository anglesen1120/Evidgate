Decision overlays

Use one native dialog at a time. View is 560 px; Edit is 760 px. Below 600 px, both become full-screen sheets. Approval always names a pinned hash; it never replaces the original failure.

These controls are design specimens, not grants. Nothing is submitted, approved, resent, or exported.

Implementation and review links

Load assets/dialogs-v3.js with defer. The trigger value, dialog ID and query value match exactly. Use a visible, labelled Close button with data-dialog-close. Mark the title (tabindex=−1) or first editable field autofocus. Focus returns to the opening row.

<button type="button" data-dialog-open="view">…</button> → <dialog id="view" class="v3-dialog v3-dialog--view" aria-labelledby="view-title">…</dialog>
?dialog=view?dialog=edit?dialog=decline?dialog=bulk

Use .v3-page-head with __facts and __actions. Section links and panel tablists both use .v3-tabs: no wrapping or select at 900 px. A .v3-kpi-strip joins .v3-kpi cards with dividers. A directory uses .v3-table-toolbar, .v3-table and .v3-table-foot; opt into .v3-table--stack and translated .v3-cell-label below 900 px. A .v3-rail drops below the list under 1280 px.

Use .v3-dialog--view or .v3-dialog--edit on .v3-dialog. Keep the title and footer outside the scrollable body. Small settings forms use .v3-popover on a native popover. Analytics use .v3-period-controls; stack charts below 900 px. Reuse the theme tokens, including neutral patterned series in both themes.
