## 1. Verdict

Technically the plan is strong: tenant isolation, evidence immutability, completeness ≠ outcome ≠ decision, safe-healing rules, and a §14 roll-up that adds up (502 tasks, 560.25 raw / 672.3 buffered person-days). The risks are about **delivery governance and undecided inputs**, not missing engineering detail:

1. Work runs ahead of the plan's own M0 gate (no pilot named, no interviews, no letter of intent).
2. The scope does not fit any realistic calendar, and the buffer is thin for the risk profile.
3. The differentiator (healing) rests on two undecided inputs (O4 model, O10 replay host).
4. After ~56 tasks there is still no authenticated request path and nothing demoable.
5. Several V1 value-surface items are absent (PR/branch model, GitHub check content, history baseline, notifications, CI re-run).

## 4. Re-baseline `[INFERENCE]` (arithmetic only, no forecast)

Inputs: §14 raw totals; focus factor 0.7 (meetings, review, context switching) is an assumption, not measured. 5 working days per week.

| Scope | Raw (d) | Buffer 20 % (current) | Buffer 40 % | Buffer 40 % ÷ 0.7 focus |
|---|---|---|---|---|
| M0–M3 (V1) | 433.25 | 519.9 | 606.6 | 866 |

| V2 (M4) | 113.75 | 136.5 | 159.3 | 227 |

Calendar for V1 with O10, buffer 40 %, focus 0.7 (≈899 person-days ÷ 5): **≈180 person-weeks → ≈ 90 weeks with 2 engineers, ≈ 60 weeks with 3**, assuming perfect parallelism that §5.5 of `plans/features/README.md` says is not available (lane A is one person). Without the focus factor: ≈ 126 / 84 person-weeks → ≈ 63 / 42 weeks (2 / 3 engineers). The source's 12 weeks (§4) is therefore not reachable by scope; only a cut (§5) can bring a first value-delivering milestone close.

Critical path (from `features/README.md` §5.2 and the area plans) for ingest → decision: 03.1.1 stable case identity → 05.1.1 manifest persistence → 05.2.1 run creation → 04.1.1 atomic batch ingest → 05.3.1/05.3.2 state machine and reconciler → 06.5.1 completeness → 07.2.x evaluator.
