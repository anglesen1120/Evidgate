## 1. Goal and non-goals

**Goal.** A metric pipeline that reports every FR-12-5 metric with its method, the monthly heal-rate-vs-missed-bugs guardrail on customer human labels, and the M3 exit review that ends in a written go/no-go for V2 with named conditions and an owner.

**Non-goals.** Building the measurements' sources (ledger is 12.3.1; human labels are 08.2.2; baseline kit is 12.2.1-T2); changing product behaviour on the guardrail signal — the heal-rate/missed-bug *review* is here, the kill-switch mechanics are 08.6.3; any aggregation that would hide a per-pilot failure behind a fleet average (value review is per pilot, area plan §8).

## 2. User stories and acceptance criteria

- As the owner, I read one exit document per pilot plus the cross-pilot synthesis and can point to the exact data behind every claim.
- As the Tech Lead, I see heal rate only next to missed bugs, so a "successful" pilot that ships hidden bugs is called a failure (D5).
- As a reviewer, I can rerun any metric query and reproduce the number in the review.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `docs/commercial/metrics/pilot-<p>-<period>.md` per pilot per period contains all FR-12-5 metrics (triage time, maintenance time, repeated incidents handled correctly, retention, contribution margin) each with `method`, `source query`, `value`; a missing source renders `null` + reason (T60) |
| AC2 | `repeated_incidents` counts only incidents whose product label matched the customer's later human label (00 §8.7) — a test inserts a label mismatch and proves it is excluded |
| AC3 | The monthly guardrail review file pairs heal rate with missed bugs every month; a document showing heal rate alone fails `check-value-report.py` (D5) |
| AC4 | The M3 exit review `docs/commercial/m3-exit-review.md` contains every metric with method, cost per tenant (12.4.1), churn/stop reasons, and a `GO` or `NO-GO` line with named conditions and a named owner (FR-12-13) |
| AC5 | Every number in the exit review reproduces by rerunning its named query (auditor re-run in the review checklist, area plan §7) |
| AC6 | `docs/commercial/reference-pack.md` (V2, M4) contains only customer-approved quotes — each quote carries a written-consent reference (FR-12-14) |

## 3. Contracts touched

- 00 §8.7 — implements "only human labels count as ground truth" as a query predicate; no contract change.
- T60 — the whole metric surface follows null-not-zero.
- 00 §2 — reads stay under audited `billing:read` (internal) or the owning tenant's own scope; value reports are documents, not new `/v1` surface.
- Resolved (T69): `GetPilotValueReport` composes its cross-module inputs (incidents from `Evidgate.Modules.Healing`, runs from `Runs`, ledger from `Usage`) only via the other modules' `.Contracts` read interfaces — no direct table reads across module boundaries.

## 4. Data model and migrations

None. The metric pipeline reads existing tables (`usage_ledger_entry`, `usage_rollup`, incident/label tables from 08, run/attempt tables from 05) through the modules' `.Contracts` read interfaces or, for cost lines, `GetCostPerTenant` (12.4.1). Outputs are committed documents (`docs/commercial/metrics/`, `m3-exit-review.md`) — per area plan §7 the review is a process artifact, not a stateful table. Rationale: a value report that is itself unauditable mutable state would violate the same append-only discipline the ledger follows.

## 5. API shapes (commands, queries, endpoints)

| Operation | Kind | Endpoint | Permission | Behaviour |
|---|---|---|---|---|
| `GetPilotValueReport` | `IQuery<PilotValueReport>` | `GET /internal/operator/orgs/{o}/value-report?period=` | `billing_operator` `billing:read`, audited | returns the five FR-12-5 metrics, each `{value|null, unavailable_reason, method_id, source}`; read-only tx (C1) |
| `GetGuardrailMetrics` | `IQuery<GuardrailMetrics>` | `GET /internal/operator/orgs/{o}/guardrail?period=` | `billing_operator` `billing:read`, audited | `{heal_rate, missed_bugs}` always paired — the DTO has no way to return one without the other (D5 enforced in the type) |

No writes, no outbox; both handlers are Dapper over read views. `method_id` values are the frozen identifiers from `metric-definitions.md` (12.2.1-T2) — the same definition feeds baseline and after-report (FR-12-5).

## 6. States and transitions

None. The review cadence (monthly guardrail, M3 exit) is a documented ritual; verdicts (`continue/adjust/stop`, `GO/NO-GO`) are recorded in documents and, where they change product behaviour, enacted via the kill switch (08.6.3) or quota raise (12.3.1) — never by writing report state back into product tables.

## 7. Jobs and integrations

- Inputs: baseline + frozen definitions (12.2.1-T2); weekly review logs (12.2.1-T4); ledger/rollup (12.3.1); human labels (08.2.2-T1 — the `label_source = 'human'` rows and the customer's applied labels); cost per tenant (12.4.1-T3).
- Outputs: the M3 review gates V2 start (00 §4); a `GO` with conditions names the conditions' owners; missed-bug rise → stop-signal review → heal narrowed or disabled via the kill switch (08.6.3); per-pilot value reports feed the V2 reference pack (T4) and block/enable 08.3.3 work as recorded.
- No schedules owned; the monthly report is generated by running the two queries and filing the output.

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| Audited billing reads (00 §2) | both queries run on the operator ingress under `billing:read` and write `audit_log` rows | `ValueReport_Read_IsAudited` |
| T60 | `null` + `unavailable_reason` for any metric whose source is missing; the exit review lists unavailable metrics with reasons rather than omitting them | `ValueReport_MissingSource_IsNull` |
| D5 (guardrail pairing) | `GuardrailMetrics` type cannot serialize heal rate without missed bugs | `GuardrailDto_RequiresPair` + `check-value-report.py` |
| C1/C5 | queries are read-only; no handler writes | `Queries_RunReadOnly` |
| S1 | parameterised SQL only | S1 architecture test |
| Privacy (FR-12-14) | value reports are shared with the customer only; public reuse needs written consent per quote (AC6); customer numbers never appear in shared aggregates | review checklist + consent references |
| Performance | monthly, off hot path; each query is a bounded set of statements (P3) over existing indexes | command-count assertions in the report tests |

- **Authorization:** T2.1 changes nothing here. The value-report queries run on the operator ingress under `billing:read` as the first row of this table says; the pilot measurement material under `docs/pilots/` carries no route or permission.
- **Retention/deletion:** the value report is a document derived from aggregates; no customer raw export is stored in the repo (`docs/pilots/baseline-worksheet.md`). Deletion requests follow 11.9.1 for artifacts; accounting rows are kept.
- **Telemetry:** T2.1 adds none. The metric pipeline (T1) reads existing product data, the ledger (12.3.1) and the baseline kit; no new event is introduced by the kit.
- **Failure path:** a missing metric source or baseline gives `null` + `unavailable_reason`, never 0 (T60), and the exit review lists it. Until 12.2.1-T2.2 runs there is no baseline; T1 must report baseline-dependent metrics (M1, M2) as `null`, not zero.

## 9. Test plan

| Behaviour / boundary / failure | Test (xUnit v3 + Testcontainers.PostgreSQL) |
|---|---|
| Ground truth = human labels | `RepeatedIncidents_OnlyHumanLabels_Count` — rule/model labels alone never count; a mismatch between product label and human label is excluded (AC2) |
| Metric method frozen | `ValueReport_UsesFrozenDefinitions` — `method_id` matches `metric-definitions.md` version on the baseline |
| Null-not-zero | `ValueReport_MissingSource_IsNull` (e.g. retention before the window ends) (T60) |
| Guardrail pairing | `check-value-report.py` fails a monthly file containing heal rate without missed bugs; `GuardrailDto_RequiresPair` at the type level (AC3) |
| Reproducibility | `ExitReview_Numbers_Recompute` — fixture tenant numbers equal the reported values (AC5) |
| Per-pilot not aggregate | `check-value-report.py` requires one metrics file per pilot; an aggregate-only folder fails |
| Consent gate | AC6 check: quote without consent reference fails the pack check |
| Process | exit-review checklist completeness per FR-12-13 (area plan §7 process suite) |

`scripts/check-value-report.py` validates the document set (required files, pairing rule, no bare heal rate, per-pilot presence, consent refs) — the review is partly a documents test because the deliverable *is* the document.
