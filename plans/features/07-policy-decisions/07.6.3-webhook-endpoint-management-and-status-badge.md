## 1. Goal and non-goals

**Goal.** A project admin registers, edits, rotates and disables outbound webhook endpoints without a database edit. Each endpoint is validated at write time and re-validated at every delivery (https only, public addresses only, no redirects, DNS pinned per delivery). The signing secret is shown exactly once. Rotation keeps the old secret valid for an overlap window so receivers can switch without dropping events. Delivery history is filterable per endpoint and a failed or dead-lettered delivery can be redelivered by hand. From V2 a project may opt in to a status badge URL that exposes only the decision label and its timestamp.

**Non-goals.** The signing, retry and delivery-record mechanics (07.6.2); new event types (07.8.1-T4 adds `promotion.checked` on top of this story's `event_types`); GitHub check runs (07.6.1); a badge for anything but the latest run decision of a project (no per-branch badges, no reasons, no counts); the web screens for endpoint management (09.7.1, `[OPEN]` whether a screen exists in V1, CLI/API only until then).

## 2. User stories and acceptance criteria

- As a `tenant_admin`, I register a webhook endpoint and see the signing secret once, so my receiver can verify deliveries.
- As a `tenant_admin`, I rotate a secret and both secrets verify during an overlap window, so no delivery fails during the switch.
- As a `tenant_admin`, I disable an endpoint and no further delivery is attempted to it.
- As a project owner, I opt in to a public status badge that shows only PASS, FAIL or INCONCLUSIVE and its time.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `POST /v1/projects/{p}/webhook-endpoints` creates an endpoint in state `active` and returns the signing secret once; every later read (`GET`, list, history) returns no secret and no ciphertext, only a `secret_hint` (last 4 characters) and `secret_version` |
| AC2 | Registration refuses: `http://`, URLs with userinfo, ports other than 443 or an allow-listed port, a literal IP in a blocked range, a host whose resolution contains any blocked address (422 `webhook_url_invalid` with a reason code, no address detail beyond the class) |
| AC3 | At every delivery the host is resolved again and the request goes only to a resolved public IP; a host that resolved public at registration and private at delivery is not contacted and the delivery is recorded `failed` reason `blocked_address` (DNS rebinding) |
| AC4 | A 3xx response is not followed; the delivery records `failed` reason `redirect_not_followed`; blocked ranges include loopback, RFC 1918, link-local incl. `169.254.169.254`, CGNAT, ULA, multicast, and IPv4-mapped IPv6 forms of those |
| AC5 | `POST …/{e}/rotate-secret` returns a new secret once; for the overlap window (default 24 h ⚠️ `[INFERENCE]`) deliveries carry two signatures `v1=<new>,v1=<old>`, after it only the new one; a second rotation during the window replaces the old secret and the previous one stops at once |
| AC6 | A `disabled` endpoint receives no new delivery and its pending retries are cancelled with reason `endpoint_disabled`; re-enabling does not replay the skipped deliveries (replay is manual, AC8) |
| AC7 | `GET /v1/projects/{p}/webhook-endpoints/{e}/deliveries` filters by state, event type and time range with a cursor; another org's or project's endpoint id returns 404 |
| AC8 | `POST …/deliveries/{d}/redeliver` creates a new delivery attempt with the original `Evidgate-Event-Id` (dedupe key unchanged), re-runs the SSRF guard, is audited and refuses a delivery whose endpoint is disabled (409 `endpoint_disabled`) |
| AC9 | Every create, update, rotate, disable, enable, delete and redeliver writes an audit row naming actor, endpoint, change; no row contains a secret or a ciphertext |
| AC10 | (V2) The badge is off by default; enabling it issues a per-project token URL (≥ 128 bits random) shown once; the endpoint returns only `{label, evaluated_at}` (and the same as an SVG) with no project, run or reason data; disabling or rotating the badge token makes the old URL return 404 |
| AC11 | Another tenant can never read, change, or trigger an endpoint, a delivery or a badge of this tenant (isolation suite, RLS, composite FKs) |

## 6. States and transitions

`webhook_endpoint`: `active ⇄ disabled`. Rotation does not change state; it moves `secret → previous_secret` with an expiry, and a sweep clears expired previous secrets (lazy check at signing time, no dependency on a job). `status_badge`: `disabled ⇄ enabled`; each enable issues a new token and invalidates the old one. No other state machine; delivery states are 07.6.2's.

## 7. Jobs and integrations

- Delivery path (07.6.2-T1) calls this story's `IWebhookTargetGuard.ResolveAsync(url)` which resolves DNS, filters to public addresses, returns one pinned IP and the original host for SNI and `Host`. The HTTP client connects to the pinned IP (no second resolution), `AllowAutoRedirect = false`, 5 s connect / 10 s total, body discarded after 4 KiB (T61). ⚠️ `SocketsHttpHandler.ConnectCallback` as the pinning point is to be verified against .NET 10 docs in T1.1.
- Signing reads the secret through Data Protection at send time; never cached beyond one delivery; never logged (S1–S3).
- Manual redeliver enqueues a task through the existing outbox/task queue (01.5.1) and reuses the delivery row semantics of 07.6.2-T2.
- Metrics: `webhook_ssrf_blocked_total{reason}`, `webhook_endpoint_state{state}`, `badge_requests_total{result}`; alert wiring is 10.3.1 (owner required).

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| SSRF (S4) | registration check plus delivery-time resolve, pinned IP, no redirects, port rule | AC2–AC4, T3 suite |
| Secrets (S1–S3) | show once, encrypted at rest, hint only, never in logs/audit/metrics | AC1, AC9, log-allowlist test |
| Bearer badge URL | ≥ 128-bit token, stored hashed, constant-time compare, off by default, minimal payload, `Cache-Control: no-store` | AC10 |
| Tenant isolation | RLS + composite FK + 404 for foreign ids | AC11 |
| Abuse | badge route is per-IP rate limited by 10.11.1 `unauth-ip` policy `[OPEN]` until that story lands; endpoint count per project capped (default 20 ⚠️ `[INFERENCE]`) | test `EndpointCap_422` |
| Information leak | `webhook_url_invalid` reports a reason class, never the resolved address | AC2 |

DoR review answers. **Authorization:** each command and query above names its permission; `webhook:read`/`webhook:write` are `tenant_admin` only (T61); the badge GET is token-only and returns the single label. **Retention/deletion impact:** secrets and ciphertext are deleted with the endpoint tombstone's purge `[OPEN]`; delivery rows follow T62; the badge token hash is deleted on disable; project deletion cascades to endpoints and badge by the tenant/project deletion job (06.4.4-T1). **Telemetry:** §7 metrics, trace attribute `webhook.endpoint_id` (never URL query strings), audit rows per AC9. **Failure path:** an endpoint that fails the guard records a typed failed delivery and never retries to a blocked address; a DNS outage retries under the 24 h backoff of 07.6.2; a Data Protection key-ring loss makes secrets undecryptable, the endpoint is auto-set `disabled` with an audit row and the admin must rotate (documented in the operator note).
