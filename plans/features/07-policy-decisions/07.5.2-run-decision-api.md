## 1. Goal and non-goals

**Goal.** `GET /v1/runs/{r}/decision` returns the exact evaluation revision (with `decision`, `reasons[]`, `completeness`, hashes) currently attached to a run, or an explicit `pending` result before any evidence revision has been frozen — a single, cheap, read-only lookup gated by `decision:read`.

**Non-goals.** Writing or triggering an evaluation (07.2.2, 07.5.1); release-level decisions (07.5.3); CI delivery of the same data (07.6.1); flaky-fact detail beyond passthrough (07.4.2 defines the payload fields this endpoint surfaces).

## 2. User stories and acceptance criteria

- As a `qa_engineer` or CI script, I can poll one endpoint to learn a run's decision without knowing internal evaluation ids.
- As the Tech Lead, I know this read never triggers work — it is a pure query, safe to poll frequently.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | A run with a `live` evaluation returns `200` with `{decision, completeness, outcome, reasons[], evidence_revision, policy_hash, evaluator_version, manifest_hash}` matching the stored row exactly |
| AC2 | A run with no evidence revision frozen yet returns `200 {status: "pending"}` (never `404`, never a fabricated decision) |
| AC3 | A caller without `decision:read` on the run's project gets `403` and no row is disclosed |
| AC4 | A run id in another org returns `404 run_not_found` (RLS makes it invisible, not merely forbidden) — never a cross-tenant row |
| AC5 | The endpoint issues exactly one SQL statement (no N+1) regardless of `reasons[]`/`flaky_facts[]` length |

## 3. Contracts touched

- 00 §9.3 — adds `GET /v1/runs/{r}/decision` to `contracts/openapi.yaml` (already named in the area plan's endpoint list); `x-permission: decision:read` set per T51.

## 4. Data model and migrations

No new table or column. Reads the existing `evaluation` table (owner 07.2.2-T1) filtered to the run's most recent `live` row (`mode = 'live'`, highest `evidence_revision`). No migration.

| Query source | Filter | Index used |
|---|---|---|
| `evaluation` | `org_id = current_org_id()` (RLS) AND `run_id = @r` AND `mode = 'live'` ORDER BY `evidence_revision` DESC LIMIT 1 | the existing partial unique `(org_id, run_id, evidence_revision) WHERE mode='live'` (T22) already serves this as a covering lookup — no new index needed |

## 5. API shapes (commands, queries, endpoints)

| Type | Name | Detail |
|---|---|---|
| Query | `GetRunDecisionQuery : IQuery<RunDecisionResult>` → Dapper handler, `SET TRANSACTION READ ONLY` (C1/C5) | Endpoint `GET /v1/runs/{r}/decision`, permission `decision:read` (`x-permission`, T51); `200` with the evaluation shape (AC1) or `200 {status:"pending"}` (AC2); `403` no permission; `404 run_not_found` if the run is not visible under RLS |
| — | No command | this story is read-only end to end |

## 6. States and transitions

None new. Reads `evaluation.decision ∈ {PASS, FAIL, INCONCLUSIVE}` (00 §8.5) as-is; the `pending` result is an API-level state (no row exists yet), not a persisted enum value.

## 7. Jobs and integrations

- Consumed by 07.6.1-T2 (`evidgate gate` CLI polls this endpoint) and 09.3.1 (UI run detail page) — both are downstream consumers, not built here.
- No background job: pure request/response.

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| S2 / C2 authorization in pipeline | `decision:read` permission checked by the pipeline before the handler runs; Architecture.Tests asserts the handler's declared permission matches the OpenAPI `x-permission` (T51) | `ArchitectureTests.EndpointPermissionsMatch` |
| 00 §5.4.7 / T2 tenant isolation | RLS via `evidgate.current_org_id()`; a foreign-org run id yields zero rows → `404`, never `403` leaking existence | AC4 |
| C1/C5 read-only | Handler runs in a read-only transaction, no outbox row, no write | Code review + `SET TRANSACTION READ ONLY` assertion in the handler's integration test |
| P3 no N+1 | Single parameterised SELECT; `reasons[]`/`flaky_facts[]` are JSONB/array columns returned in the same row | AC5, statement-count assertion |
| P1 hot-path budget | This is a polled endpoint (CI loops); latency budget taken from 00 §11's `decision` row, load-tested by 07.6.2-T3 | Referenced, not re-measured here (owned by 07.6.2-T3) |
| Privacy | No artifact content or secrets in the response; only ids, hashes and reason codes | — |
