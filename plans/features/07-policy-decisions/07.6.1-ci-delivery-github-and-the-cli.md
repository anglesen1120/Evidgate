## 1. Goal and non-goals

The trusted customer job reads the stored decision with `evidgate gate`. No provider delivery, external status write or repository permission is required.

## 2. User stories and acceptance criteria

| ID | Observable result |
|---|---|
| AC4 | `evidgate gate --run {r}` exits `0`/`1`/`2` for `PASS`/`FAIL`/`INCONCLUSIVE`; `--wait 30s` against a run that stays `pending` exits `2` (never `0`); a transport/auth failure exits `3`; `--json` prints `{ decision, completeness, evaluation_id, mode, url }` matching `contracts/cli.md` |
| AC5 | `GET /v1/runs/{r}/decision` returning `pending` under `--wait` polls until a decision row exists or the deadline; the deadline path is covered by a fixture test |

## 3. Contracts touched

Use the decision endpoint, the CLI exit codes and JSON contract. Outbound customer webhooks (07.6.2) are separate.

## 4. Data model and migrations

No new delivery record. The decision and evaluation are the server’s existing immutable evidence.

## 5. API shapes (commands, queries, endpoints)

A project-scoped caller reads `GET /v1/runs/{r}/decision`. The CLI may wait to a fixed deadline; it never creates or changes a decision.

## 6. States and transitions

Pending → stored decision, or deadline. Pending is not PASS. Display the actual decision and completeness in both advisory and enforcing modes.

## 7. Jobs and integrations

No distribution job, external integration or retry queue. The customer runs the CLI in its own pipeline.

## 8. Security, privacy and performance

- **Authorization:** Require the project’s `decision:read` permission.
- **Retention/deletion:** No additional retained provider deliveries.
- **Telemetry:** Record bounded gate outcomes, never credentials.
- **Failure path:** Pending timeout and transport/auth errors are not successful decisions (AC4–AC5).

## 9. Test plan

Exercise PASS, FAIL, INCONCLUSIVE, pending/deadline and transport/auth failure with the CLI. Confirm that output does not assert PASS on missing evidence.
