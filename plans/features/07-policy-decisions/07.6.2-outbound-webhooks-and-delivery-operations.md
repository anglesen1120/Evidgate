## 1. Goal and non-goals

**Goal.** When an `evaluation` row lands, every registered webhook endpoint for that org receives a signed `evaluation.created` delivery — `Evidgate-Event-Id`, `Evidgate-Timestamp`, `Evidgate-Signature: v1=<hmac-sha256(secret, timestamp + "." + body)>` — with at-least-once exponential retry for 24 h, a dead-letter set replayable by `event_id`, and a published reference receiver. The same story measures the freeze→decision latency SLI (T28).

**Non-goals.** Webhook *inbound* receivers (GitHub webhook → 03.4.1); `run.state_changed` emission (05's outbox) and `healing.candidate_changed` (V2, 08) — this story builds the shared transport on `evaluation.created` only; CI delivery (07.6.1); UI for delivery operations (09.7.1, blocked by this story); endpoint subscription UI.

## 2. User stories and acceptance criteria

- As a pilot integrator, my receiver can verify the signature and reject a stale or replayed delivery using only the published headers, so a forged notification never gates my release.
- As an operator, an endpoint that is down > 24 h produces visible dead letters I can replay by `event_id`, so no `evaluation.created` is silently lost.
- As the Tech Lead, the freeze→decision histogram is measured in the M3 load run and registered as an SLI, so decision latency is observable, not assumed.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | The reference receiver validates `v1=` signature over `timestamp + "." + body`, accepts a fresh delivery (200), and rejects a timestamp older than 5 min and a forged signature (401-style rejection recorded in the fixture) |
| AC2 | A `5xx`/timeout from the endpoint schedules `webhook_delivery` retries with exponential backoff for up to 24 h, then `dead_letter`; a replay by `event_id` creates a new attempt without duplicating the event |
| AC3 | `webhook_delivery` is unique on `(org_id, endpoint_id, event_id)`; the same `evaluation.created` event delivered to two endpoints produces two rows, and a redelivery to the same endpoint updates the same row |
| AC4 | `GET /v1/projects/{p}/webhook-deliveries` (`webhook:read`, cursor paginated) lists deliveries incl. `state`, `attempts`, `last_error` for 09.7.1's dead-letter view |
| AC5 | In the M3 load run, the `evidgate_decision_latency_seconds` histogram (`evidence_frozen_at` → `evaluation.created_at`) reports p95 < 60 s on the 10.6.1-T1 fixture; the SLI is registered in `10.3.1-T3`'s metric registry |
| AC6 | Registering or updating an endpoint whose URL uses a non-https scheme, carries userinfo, targets a port other than 443 or an allow-listed port, or resolves to a loopback, RFC1918, link-local (incl. the cloud-metadata address 169.254.169.254), CGNAT, IPv6 ULA, or multicast address is rejected 422 `endpoint_url_blocked` |
| AC7 | A delivery re-resolves the endpoint host immediately before connecting and pins the connection to that resolved address (DNS-rebinding safe): a hostname that was public at registration but now resolves to a private address is blocked at send time, recorded `retrying` with `last_error = dns_rebinding_blocked`, never delivered |
| AC8 | A delivery never follows a redirect response, enforces a 5 s connect timeout and a 10 s total timeout, and reads at most 4 KiB of the response body before closing the connection |
| AC9 | `ci_delivery` and `webhook_delivery` rows are retained for exactly as long as the `evaluation` row they reference exists — no independent expiry job deletes them (T62) |

## 4. Data model and migrations

`migrations/NNNN_decisions_webhooks.sql` (DbUp, owner role):

```sql
create table webhook_endpoint (
  id uuid primary key default gen_random_uuid(),
  org_id uuid not null,
  project_id uuid not null,
  url text not null,                        -- https only, no userinfo, port 443 or an allow-listed port (S4/T61)
  secret_ciphertext bytea not null,         -- ASP.NET Core Data Protection; plaintext returned once at creation only
  event_types text[] not null default '{evaluation.created}',
  state text not null default 'active',     -- active | disabled | deleted (soft delete preserves webhook_delivery FK history)
  created_by uuid not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  deleted_at timestamptz,
  unique (org_id, id),                      -- 00 §5.4.6 / T3
  unique (org_id, project_id, url),
  foreign key (org_id, project_id) references project (org_id, id)
);

create table webhook_delivery (
  id uuid primary key default gen_random_uuid(),
  org_id uuid not null,
  project_id uuid not null,
  endpoint_id uuid not null,
  event_type text not null,
  event_id uuid not null,                 -- evaluation.id; the dedupe key
  state text not null default 'queued',   -- queued | sending | delivered | retrying | dead_letter
  attempts int not null default 0,
  next_attempt_at timestamptz,
  last_error text,                        -- sanitised
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (org_id, id),                    -- 00 §5.4.6 / T3
  unique (org_id, endpoint_id, event_id), -- A10 dedupe (AC3)
  foreign key (org_id, endpoint_id) references webhook_endpoint (org_id, id)
);
create index webhook_delivery_list on webhook_delivery (org_id, project_id, state, created_at, id); -- P4: serves AC4's list query
alter table webhook_endpoint enable row level security;
alter table webhook_endpoint force row level security;
alter table webhook_delivery enable row level security;
alter table webhook_delivery force row level security;
create policy webhook_endpoint_tenant on webhook_endpoint using (org_id = evidgate.current_org_id());
create policy webhook_delivery_tenant on webhook_delivery using (org_id = evidgate.current_org_id());
```

`ci_delivery`/`webhook_delivery` carry no expiry column: retention follows the referenced `evaluation` row's own lifetime (T62) — no sweeper task is added by this story.

## 5. API shapes (commands, queries, endpoints)

- **Command `RegisterWebhookEndpointCommand`** → `POST /v1/projects/{p}/webhook-endpoints` (`webhook:write`, `Idempotency-Key`): the shared `WebhookUrlGuard` validates https-only, no userinfo, port 443 or an allow-listed port, then resolves the hostname and rejects a target address that is loopback, RFC1918, link-local (incl. 169.254.169.254), CGNAT, IPv6 ULA, or multicast — 422 `endpoint_url_blocked` (AC6); stores `secret_ciphertext`; returns the plaintext secret **once** in the 201 response (never again readable, never logged).
- **Query `ListWebhookEndpointsQuery`** / **`GetWebhookEndpointQuery`** → `GET /v1/projects/{p}/webhook-endpoints` / `GET /v1/projects/{p}/webhook-endpoints/{e}` (`webhook:read`, cursor list on `(created_at, id)`): never returns `secret_ciphertext` or the plaintext secret.
- **Command `UpdateWebhookEndpointCommand`** → `PATCH /v1/projects/{p}/webhook-endpoints/{e}` (`webhook:write`, `If-Match`): `url`/`event_types`/`state` (`active ↔ disabled`) changes re-run `WebhookUrlGuard`.
- **Command `DeleteWebhookEndpointCommand`** → `DELETE /v1/projects/{p}/webhook-endpoints/{e}` (`webhook:write`): soft delete (`state = 'deleted'`, `deleted_at` set); schedules no further deliveries; existing `webhook_delivery` rows keep their FK for audit history.
- **Query `ListWebhookDeliveriesQuery`** (`IQuery`, Dapper read-only tx) → `GET /v1/projects/{p}/webhook-deliveries?state=&cursor=` (`webhook:read`): keyset on `(created_at, id)`, served by `webhook_delivery_list`.
- **Task handler `WebhookDeliveryHandler`** (task type `webhook.deliver`): claim → `WebhookUrlGuard` re-resolves the endpoint host **immediately before connecting** and pins the TCP connection to that resolved address via a `SocketsHttpHandler.ConnectCallback` (DNS-rebinding safe, AC7) → sign + POST with `AllowAutoRedirect = false`, 5 s connect / 10 s total timeout, response body capped at 4 KiB (AC8), outside any transaction (P5) → `RecordWebhookDeliveryResultCommand` (second tx) → retry/`dead_letter` bookkeeping.
- **Operator:** `POST /internal/operator/webhook-deliveries/{event_id}/replay` (`platform_operator`, 00 §9.1) re-enqueues `webhook.deliver` for the dead-lettered deliveries of that `event_id`.

## 6. States and transitions

`webhook_delivery.state`: `queued → sending → delivered`; `sending → retrying → sending …` under backoff until `next_attempt_at` exceeds created + 24 h → `dead_letter`. `webhook_endpoint.state`: `active ↔ disabled` (reversible) or `active`/`disabled` `→ deleted` (terminal, T61): disabled/deleted endpoints receive nothing; queued rows for them go `dead_letter` at next fire or are skipped with a recorded reason. Delivered and dead_letter are terminal; replay creates a new attempt on the same row (attempts++), never a second `(endpoint_id, event_id)` row.

## 7. Jobs and integrations

- The evaluate handler (07.2.2-T1) writes one `webhook.deliver` outbox entry **per registered endpoint** in the evaluation transaction (C7); dispatcher → `task` queue (`FOR UPDATE SKIP LOCKED`, `available_at` carries the backoff schedule, 00 §5.3). At-least-once everywhere (A10); dedupe is the `(endpoint_id, event_id)` unique.
- HMAC-SHA256 over `timestamp + "." + body` with the per-endpoint secret decrypted from `secret_ciphertext` via ASP.NET Core Data Protection (S3, T61); `Evidgate-Event-Id` = `event_id` so receivers can dedupe replays.
- `WebhookUrlGuard` (shared utility, built once, used at registration and at every delivery, T61): scheme/userinfo/port checks plus a block list for loopback, RFC1918, link-local (incl. 169.254.169.254), CGNAT, IPv6 ULA and multicast; at delivery time it resolves the host, pins the connection to the resolved address (`SocketsHttpHandler.ConnectCallback`, DNS-rebinding safe, AC7), disables redirects, and applies the 5 s/10 s timeouts and the 4 KiB response-body cap (AC8).
- Reference receiver: a small Node 22+/TS fixture (`fixtures/webhook-receiver`, Vitest) published in-repo for integrators; implements signature verify, 5-min skew rejection, `Event-Id` dedupe.
- T3 metric: the evaluate handler emits `evidgate_decision_latency_seconds` (histogram, labels `org` hashed out — org id as a label is allowed for ops, no secrets; S3) at `evaluation` INSERT using `evidence_frozen_at` from the evidence revision.

## 11. Rollout

- No feature flag; deliveries only fire when a `webhook_endpoint` exists for the project — zero registrations means zero traffic.
- Merge order: T1 → T2 → T3 (T3 lands with the M3 load run, not before 10.6.1-T1).
- Monitoring: `webhook_delivery` state gauges, dead-letter depth alert (00 §11 operational SLIs), latency histogram from T3.
- Rollback: disable endpoints (`state = 'disabled'`) or stop the `webhook.deliver` handler; stored rows unaffected; replay path recovers deliveries after re-enable.
