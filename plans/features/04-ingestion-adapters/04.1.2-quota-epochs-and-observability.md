## 1. Goal and non-goals

**Goal.** The ingest endpoint gains its protective and diagnostic layer: per-project rate limiting and ingest quota that fail loudly with 429 + `Retry-After` (`rate_limited` for bursts, `quota_exceeded` for quota), foreign-epoch events stored as stale evidence that can never complete a job, the `producer_slot` table with token-identity binding (T9) plus `unknown_execution_key` (T10) and `after_cancel` (T12) enforcement, and the OpenAPI contract + integration tests that lock all of it down.

**Non-goals.** The usage ledger rows themselves (04.8.1), the `quota_counter` roll-up semantics owned by 12 (this story reads its contract via 01.4.1-T1 and writes ingest-side counters only), finalize semantics (05.3.2-T1 — it calls the `IProducerRegistry` check this story builds), run-create orchestration (05.2.1), agent-mode epoch management (05.7.2-T1, V2).

## 2. User stories and acceptance criteria

- As a tenant, a burst above my project's ingest rate gets a clear 429 with `Retry-After`, never a silent drop, so my CLI can back off correctly.
- As the platform, a leaked token cannot write under another shard's slot, a foreign-epoch event is kept as stale evidence but can never complete a job, and every rejection is counted and traced.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | A burst above the project's rate limit returns 429 `rate_limited` with a numeric `Retry-After` header; a project over its ingest quota returns 429 `quota_exceeded`; both refuse without committing an `event` row |
| AC2 | Run create (05.2.1 path) inserts exactly one `producer_slot` row per manifest shard in the same tenant transaction via `IProducerRegistry.RegisterSlotsAsync` |
| AC3 | The first accepted write of **any** kind — an event batch or `POST /v1/artifacts/upload-url` (06.1.2, carrying `producer_id` + `Idempotency-Key`, T85/T92) — sets `bound_token_jti` (and `bound_ci_run_ref` from GitHub `run_id`/`run_attempt` claims when present, which must equal `run.ci_run_ref` set at run create, T88); a later write or `finalize` under a different identity → 403 `producer_slot_taken` |
| AC4 | A write or `finalize` under a `producer_id` with no slot → 422 `unknown_producer` |
| AC5 | Events arriving on a canceled run are accepted with `after_cancel = true`; the run stays `canceled` (T12) |
| AC6 | An event carrying an `epoch` ≠ the job's current epoch is stored with `stale = true` and contributes `stale_epoch` to completeness `missing[]`, never `complete` |
| AC7 | Every rejection path emits one counter increment (`batch_rejected{reason}`) and the batch span carries `run_id`, `producer_id`, `request_id`; `/metrics` exposes them |
| AC8 | `contracts/openapi.yaml` documents `/v1/runs/{r}/events` (request, 200/4xx, error codes) and the served document diffs clean against it (01 contract test) |
| AC9 | `CloseSlotAsync` sets `closed_at` and stores `declared_last_sequence` + `declared_count` exactly once; a repeat call with the same identity is idempotent (returns the stored values, no error, no update); a call under a foreign identity → 403 `producer_slot_taken` (T68, T9); 05.3.2's reconciler reads the declared columns |

## 4. Data model and migrations

DbUp migration `migrations/NNNN_ingestion_producer_slot.sql` (placeholder number), owner role:

```sql
create table producer_slot (
  id uuid not null,                -- server UUIDv7
  org_id uuid not null,
  run_id uuid not null,            -- no FK here: the `run` table does not exist yet (05.2.1 adds it)
  shard_index int not null,
  producer_id text not null,
  bound_token_jti text null,       -- T9: set by first accepted write
  bound_ci_run_ref text null,      -- GitHub run_id/run_attempt composite; compared with run.ci_run_ref (T88)
  last_sequence bigint not null default 0,
  closed_at timestamptz null,      -- set by finalize via CloseSlotAsync (T68, 05.3.2-T1)
  created_at timestamptz not null default now(),
  primary key (org_id, id),
  unique (org_id, id),                              -- T3
  unique (org_id, run_id, producer_id),             -- one slot per producer
  unique (org_id, run_id, shard_index)              -- one slot per manifest shard
);
alter table producer_slot enable row level security;
alter table producer_slot force row level security;
create policy producer_slot_tenant on producer_slot
  for all to evidgate_app
  using (org_id = evidgate.current_org_id())
  with check (org_id = evidgate.current_org_id());
create index producer_slot_run on producer_slot (org_id, run_id);  -- slot list per run (P4)
```

The policy is `for all to evidgate_app`: a policy with no `TO` clause applies to `PUBLIC`, which would let `evidgate_operator` (it holds `SELECT`) read any org by setting `evidgate.org_id` (security finding from PR #51, T76).

`declared_last_sequence`/`declared_count` are **not** in this migration: per README T68 those two columns are owned by 04.1.2-T5, which adds them in its own migration:

```sql
-- 04.1.2-T5 migration (T68): declared values, written once by CloseSlotAsync
alter table producer_slot add column declared_last_sequence bigint null;
alter table producer_slot add column declared_count int null;
```

`event_slot_fk` is **not** created here: the `event` table does not exist at this migration's number, so 04.1.1-T1 adds `alter table event add constraint event_slot_fk foreign key (org_id, run_id, producer_id) references producer_slot (org_id, run_id, producer_id)` in its own `event` migration (owner decision 2026-10-10; recorded in the 04.1.1 plan T1 Notes and STATUS §6). `run_id` likewise carries no FK: the `run` table does not exist yet, so 05.2.1 adds the composite `(org_id, run_id) → run (org_id, id)` FK when it creates `run` (same deferral as 0028's `artifact`).

`quota_counter` is **not** created here (12 owns it, T45); this migration adds nothing for quota. `event.stale`/`after_cancel` columns already exist from 04.1.1's migration.

No new endpoints. Existing `POST /v1/runs/{r}/events` gains behaviours; `POST /v1/runs/{r}/finalize` (05.3.2-T1) consumes `IProducerRegistry.BindOrCheckAsync` for the identity check and `CloseSlotAsync` for the idempotent close (T68). `POST /v1/artifacts/upload-url` (06.1.2) also carries `producer_id` + `Idempotency-Key` and calls `BindOrCheckAsync`, so the first accepted write of any kind binds the slot (T85, T92).

## 6. States and transitions

- `producer_slot`: `open → closed` (`closed_at` set once by `CloseSlotAsync`; repeat calls are idempotent no-ops returning the stored declared values; never set by the event endpoint).
- `event.stale`: `false → true` at insert when `epoch` differs from the job's current epoch (CI shards have no lease, so in V1 a slot's epoch is its binding epoch; agent epochs are validated with 05.7.2-T1 in V2).
- Run: `canceled` stays terminal — `after_cancel` events never transition it (T12); `created → queued` fires when slots commit (T13, emitted by 05's run-create, not here).

## 7. Jobs and integrations
- **`IProducerRegistry`** is called by three consumers: 05.2.1's `CreateRun` command (`RegisterSlotsAsync`, same tx as the run row), 06.1.2's `upload-url` handler (`BindOrCheckAsync`, T85) and 05.3.2-T1's finalize handler (`BindOrCheckAsync` + `CloseSlotAsync`, T68). All cross-module calls go through `Evidgate.Modules.Ingestion.Contracts` only (C5 module rule, `Architecture.Tests`).
- **Observability**: OTel counters `ingest_events_accepted`, `ingest_events_duplicate`, `ingest_batch_rejected{reason}`, `ingest_quota_denied{kind}`; span attributes `run_id`, `producer_id`, `request_id`, `event_count`; histogram `ingest_batch_seconds` for the P1 budget row in 10.
- **Quota**: consumed via `IQuotaGate` (T53); the ingest counter write is local (`event_batch` + OTel), the authoritative `quota_counter` update stays in 12's roll-up path.
- V2 hook: agent epoch validation integrates with 05.7.2-T1's lease epochs without changing the `stale` flag semantics.

**Notes.** The quota half of T1.1 is wired (12.3.1-T4.4, S260): the events route asks `IQuotaGate` exactly once per batch (never per event), **after** the batch's one insert has answered how many rows it really adds, with that inserted count as the `results` quantity and the token's project as the counter; the gate's row lock is therefore held only for the tail of the transaction, and two identical racing batches reserve the batch once between them (the loser's insert adds nothing, is acked as a duplicate and asks nobody). A block is 429 `quota_exceeded` + integer `Retry-After` in the burst refusal's envelope and returns a failure, so the tenant transaction rolls the inserted events back and commits no event; a resend of a committed batch reserves nothing. The counter is the last contended row lock of the batch: the `producer_slot` high-water mark is written before the gate (it rolls back with a blocked batch), so racing batches of one producer take the slot row and then the counter, never the other way round (a 50-batch race found that order as a 40P01 deadlock). `IngestQuotaTests` covers the once-per-batch call, the block, the resend, concurrent identical batches, the operator switch and 50 racing batches that never pass the limit. A send-back makes the same call charge the organization's counter too: `IncludeTenantScope` asks for the tenant scope (null `project_id`) beside the project's, both locked tenant-first in one statement, the batch is refused when either has no room and neither scope is charged when it is refused, and the refusal's `blocked_at` stamp survives the rollback because the endpoint rewrites it afterwards through `IQuotaBlockStamp` in a scope of its own — logged and still 429 when that stamp fails.
