## 1. Goal and non-goals

**Goal.** `POST /v1/runs/{r}/reprocess` re-parses an already-stored `raw_report` artifact with a chosen `parser_version`, producing a new set of `event` rows under a fresh synthetic producer, a new `raw_report` parsing row, and — via 06's freeze and 05's persistence — a **new `evidence_revision` labelled `reprocessed`**. The previous revision, the original report bytes and the original events are never mutated, and the new revision is distinguishable from a rerun everywhere it is shown.

**Non-goals.** Reruns (`POST /v1/runs/{r}/rerun`, owner 05 — different action, different `run_id`); the freeze and revision-persistence internals (06.5.1 / 05.3.2-T5, called through their contracts); raw-report upload and first parse (04.4.1-T4, 06.1.x); the comparison read API (04.4.1-T6); UI work beyond the `reprocessed` label being exposed (09 renders it).

## 2. User stories and acceptance criteria

- As a `tenant_admin` whose parser had a mapping bug, I reprocess the stored report after the fix ships, and get a corrected evidence revision without re-running the customer's tests.
- As an auditor, the original revision hash and the original raw report are byte-identical before and after any reprocess.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `POST /v1/runs/{r}/reprocess` with a valid `raw_report_id` + `parser_version` (newer than the report's original version) returns 202 with the new `raw_report` parsing row id; the run's later `GET /v1/runs/{r}` shows a new `evidence_revision` labelled `reprocessed` once the task completes |
| AC2 | After reprocess, the previous `evidence_revision` row, its events and the raw report object are unchanged (revision hash identical); the new revision is a separate row |
| AC3 | Reissuing the same request with the same `Idempotency-Key` returns the original 202 response; a different payload under the same key returns 409 `idempotency_conflict`; a semantically identical request (same `artifact_id` + `parser_id` + `parser_version`) under a *new* key returns the existing parsing row, not a duplicate parse |
| AC4 | `raw_report_id` from another org or another run → 404; unknown `parser_version` → 422 `parser_version_unknown`; `raw_report.status = unsupported` → 422 `raw_report_unprocessable`; callers without `run:create` → 403 |
| AC5 | The reprocessed events are written under a new synthetic `producer_id` (`reprocess-<parsing_row_id>`) with sequences starting at 1 — they never collide with the original `(run_id, producer_id, sequence)` keys and never bind a `producer_slot` (the reprocess path is internal, not a CI producer per T9) |
| AC6 | A reprocess never changes the run's state machine (00 §8.1) and never marks the revision `rerun`; a canceled or incomplete run still accepts reprocess and produces a labelled revision |

## 4. Data model and migrations

No new tables. All objects are owned elsewhere:

| Object | Owner | This story's use |
|---|---|---|
| `raw_report` (id, org_id, run_id, producer_id, artifact_id, producer_kind, parser_id, parser_version, parsed_at, status) | 04.4.1-T4 | insert one new row per parsing; `unique (org_id, id)` already there (T3). Dedupe: handler checks for an existing row with the same `(org_id, artifact_id, parser_id, parser_version)` and returns it instead of parsing again (natural key, not a new constraint — recorded in the reprocess runbook note; a partial-unique index is added only if the load test shows the check needs it) |
| `report_parser` (parser_id, version) | 04.4.1-T4 | existence + version-order check for the requested `parser_version` |
| `event` | 04.1.1-T1 | new rows under synthetic `producer_id`; same uniques as normal ingest |
| `evidence_revision` | 05 | persisted by 05.3.2-T5 from 06.5.1's freeze result; labelled `reprocessed` |
| `task` queue / `idempotency_record` | 01 | outbox task `ingest.reprocess_report`; command requires `Idempotency-Key` |

Index serving the read path: lookups are by `(org_id, raw_report_id)` PK and `(org_id, run_id)` on `raw_report` — both covered by 04.4.1-T4's migration; no new index.

## 5. API shapes (commands, queries, endpoints)

| Shape | Detail |
|---|---|
| `POST /v1/runs/{r}/reprocess` | permission `run:create`; body `{ "raw_report_id": "uuid", "parser_version": "semver-string" }`; requires `Idempotency-Key`; 202 `{ "parsing_id": "uuid" }` → work is async via outbox |
| `ReprocessRawReport` command (`ICommand<ReprocessResult>`) | Pipeline C2 in order; handler: verify `raw_report` belongs to `(org_id, run_id)` → verify `parser_version` exists in `report_parser` and is newer than the report's original → natural-key dedupe → insert `raw_report` row (`status` pending parse) → outbox `ingest.reprocess_report` → commit |
| `ReprocessReportTaskHandler` (worker) | Opens tenant scope (C3); fetches raw bytes via 06's artifact interface (`IArtifactStore.GetAsync(artifact_id)` — a call outside the DB tx, P5); runs the hardened parser at `parser_version`; writes `event` rows via the same batch insert as 04.1.1-T1 (`unnest`, one round trip) under `producer_id = reprocess-<parsing_row_id>`; sets `raw_report.status = parsed|malformed`; emits the freeze trigger for 05.3.2-T5 → 06.5.1 |
| Errors | 404 `not_found` (foreign/missing run or report, T-RLS-safe) · 422 `parser_version_unknown` · 422 `raw_report_unprocessable` · 409 `idempotency_conflict` · 429 `rate_limited` |

No read/query shapes: revisions are read through `GET /v1/runs/{r}` (05) and the comparison API (04.4.1-T6).

## 6. States and transitions

- `raw_report` per parsing row: `pending → parsed | malformed | unsupported` (the area plan lists three terminal states; the pending marker exists only between command commit and task completion and is not part of the public vocabulary).
- `evidence_revision`: new immutable row each successful reprocess; `completeness` recomputed from the new event set by 06; label `reprocessed` (never `rerun`).
- Run state (00 §8.1) untouched; events from a reprocess carry no `after_cancel` semantics — they are derived, not CI-produced.

## 7. Jobs and integrations

- `task` queue row `ingest.reprocess_report` (outbox, `SKIP LOCKED`, capped retries → `dead_letter`); natural idempotency key `reprocess:<raw_report_id>:<parser_version>`.
- Calls **out**: 06 `IArtifactStore` (bytes fetch — outside the tx, P5) and 05.3.2-T5 reconcile/freeze trigger via the outbox; calls **in** from: 09 (label rendering), 12 metering (a reprocess is not a new billable batch — no `usage_ledger_entry`, billing keys are per `event_batch` per T43, and reprocess writes no `event_batch` row).

## 11. Rollout

- No feature flag: the endpoint is additive and returns 404/422 until real `raw_report` rows exist (04.4.1-T4 prerequisite).
- Monitoring: task-queue depth + dead-letter count for `ingest.reprocess_report`; a `reprocess` counter on the ingest metrics (04.1.2-T1 namespace).
- Rollback: revert the PR; already-created parsing rows and revisions are immutable evidence and stay (deleting them would itself be a reprocess-shaped operation — out of scope).
