## 1. Goal and non-goals

**Goal.** The Playwright reporter resolves every emitted `test.finished`/`test.started` to a stable case identity — `evidgate.id` annotation or sidecar manifest; an unmapped or conflicting test carries no `case_id` and gets a visible `run.log` warning (AC2) — computes `variant_hash` from the declared parameters exactly as the server does (AC3 as amended, §3), and maps Playwright outcomes (pass, fail, `timedOut`, interrupted, `skip`, `fixme`, retries) to raw + normalised statuses so that retries become `attempt_no` 1..n and `fixme`/`skip` are distinguishable and never become `passed`.

**Non-goals.** Reporter skeleton and spool writer (04.3.1-T1); shard→producer mapping (04.3.3-T1); server-side status storage and completeness reasons (04.1.x, 06); the `evidgate.id` annotation format itself (03.1.1) and sidecar filename (03.1.1-T1).

## 2. User stories and acceptance criteria

- As a QA engineer, I annotate a test with its catalog id once, and every retry and shard reports against the same `execution_key`, so attempts line up.
- As the Tech Lead, I want unmapped or conflicting identities to fail loudly in the CI log, so silent mis-attribution never reaches the decision engine.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | A test with `test.annotations` entry `{ type: "evidgate.id", description: "<uuid>" }` produces events whose `ext.case_id` is that UUID; the same id in two different tests emits a conflict warning event (`run.log`, `reason: "duplicate_case_id"`) naming both locations |
| AC2 | Annotation and sidecar manifest disagreeing for the same test location → conflict per 00 §7 (never a silent pick): the test's events carry `ext.identity_conflict = true` and no `case_id`; the reporter exits non-zero on `onEnd` unless `EVIDGATE_ALLOW_UNMAPPED=1` (mirrors 03's `allow_unverified` flag, T46) |
| AC3 | `variant_hash` = the 03.2.1 server variant hash of the declared params only (00 §3): the params are normalised exactly as `VariantNormalizer` does (sorted keys, non-identifying keys dropped, enum-like values lower-cased, secret-shaped keys/values refused) and hashed as `sha256:<hex>` over RFC 8785 (`CanonicalHash`); there is no `{project, params}` wrapper, the Playwright project name counts only when it is one of the declared params (amended by coordinator decision 2026-10-07, owner confirmed 2026-10-07, §3); two runs of the same suite on different machines produce identical `variant_hash`es, and the TS and .NET implementations agree on every vector of `fixtures/variant-hash/vectors.json` |
| AC4 | `execution_key` is computed by the server from the manifest (00 §7); the reporter sends `ext.case_id` + `ext.variant_hash` + `ext.target_env`; an event the server cannot resolve rejects the batch 422 `unknown_execution_key` (T10) — the reporter emits the keys, it does not hash `execution_key` itself unless the contract stub says so |
| AC5 | Retry N (Playwright `result.retry`) maps to `attempt_no = retry + 1`; a flaky pass (fail then pass) yields `attempt_no` 1 `failed` + 2 `passed` — never a merged status |
| AC6 | Status map: `passed→passed`, `failed→failed`, `timedOut→timed_out`, `interrupted→error`, `skipped`(annotation `skip`)→`skipped`, `skipped`(`fixme`)→`skipped` with `ext.skip_reason="fixme"`; `expectedStatus:"failed"`×`failed` outcome → `passed` with `ext.xfail=true`; raw status string preserved verbatim in `status` |
| AC7 | A test whose `fixme`/`skip` annotation appears only on a retry keeps `attempt_no` sequence contiguous (1..n, no gap) |

- [DECISION] coordinator 2026-10-07, owner confirmed 2026-10-07 (S11, 04.3.2-T1): the sidecar is `evidgate.cases.yaml` (03.1.1-T1), parsed with one exact-pinned dependency `yaml` 2.9.1 (eemeli/yaml, ISC): plain data only (core schema, no custom tags, no aliases or merge keys), size cap before parse. Ajv 8 moves from dev to runtime dependency for the sidecar schema check.
- [DECISION] coordinator 2026-10-07, owner confirmed 2026-10-07 (S11, 04.3.2-T1): `execution_key` stays server-owned (00 §7 "computed by the server from the manifest"); its byte layout is defined by 05.2.1-T3. ## 4. Data model and migrations

None server-side. Reporter-local: `sidecar` manifest file (filename fixed by 03.1.1-T1) parsed once at `onBegin` into an in-memory `location → case_id` map; conflicts resolved per AC2 at emit time.

## 5. API shapes (commands, queries, endpoints)

Library internals only (no HTTP):

| Function | Signature | Notes |
|---|---|---|
| `resolveIdentity(test)` | `TestCase → { case_id?, variant_hash, target_env, conflict? }` | annotation first, sidecar second, both → conflict |
| `mapStatus(result, annotations)` | `TestResult → { raw, normalized, skip_reason?, xfail? }` | pure function, table-driven (AC6) |
| `attemptOf(result)` | `TestResult → attempt_no` | `retry + 1` |
| Warning channel | `run.log` envelopes with `ext.warn` codes | warnings are data, not stderr-only |

## 6. States and transitions

Identity resolution state per test file: `unmapped → mapped | conflicted` (mirrors 00 §8.10 case-import identity states). Transitions are computed per test at `onTestBegin`; once `conflicted`, never re-mapped within the run. `attempt_no` strictly increments per `execution_key` within the process; a restarted shard reuses the same deterministic `producer_id` and resumes `sequence` from the checkpoint (04.3.3, T84), so a `(run, producer, sequence)` is never re-emitted and attempts never collide.

## 7. Jobs and integrations

- Consumes the annotation vocabulary and sidecar filename owned by 03.1.1-T1/03.1.3; if the sidecar spec changes, only `resolveIdentity` changes.
- Emits through the 04.3.1 spool writer; consumed by the CLI pipeline unchanged.
- Server side, `unknown_execution_key` batches (T10) are surfaced by the CLI as exit 3 with the failing indices — the reporter itself is offline.
