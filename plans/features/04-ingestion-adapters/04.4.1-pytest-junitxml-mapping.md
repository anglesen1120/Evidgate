## 1. Goal and non-goals

**Goal.** A versioned, per-producer JUnit XML mapper — pytest `junitxml` first — that parses a stored raw report defensively, emits mapped `test.finished` events (synthetic producer), records `parser_id`/`parser_version` and declared-vs-observed counts on a `raw_report` row, keeps raw statuses verbatim, and exposes `GET /v1/runs/{r}/reports/{report_id}/comparison` so every discrepancy carries a reason.

**Non-goals.** Reprocess flow itself (04.4.2-T1); evidence freeze/`evidence_revision` persistence (06/05); upload mechanics (06.1.x, 04.2.4); other producers' JUnit dialects (new `report_parser` rows, not new code); the web comparison view (09.2.1 consumes the endpoint).

## 2. User stories and acceptance criteria

- As a customer with pytest CI, I upload `junit.xml` and see my cases as events with honest statuses, so unsupported or malformed input never silently passes.
- As a reviewer, I can read a report back against its parsed events per case, so count mismatches and unmapped cases are explainable without re-parsing.
- As the Tech Lead, I want `parser_version` on every row, so a reprocess under a new parser is reproducible and auditable (D4).

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | A well-formed pytest `junit.xml` parses to one `test.finished` event per `<testcase>`: `<failure>` → `failed`, `<error>` → `error`, `<skipped>` → `skipped`, else `passed`; `time` → `duration_ms`; `classname`/`name` preserved raw in `status`/`ext`; every event carries `ext.parser = "junit-pytest/<version>"` and the row `parser_id`/`parser_version` |
| AC2 | `testsuite`/`testsuites` counter attributes (`tests`, `failures`, `errors`, `skipped`) are stored on `raw_report` as `declared_*`; parsed events counted as `observed_*`; a mismatch sets `status = parsed` but records discrepancy reasons — never a silent pass (00 §8.5 completeness input) |
| AC3 | A `case_id` resolvable via the manifest (`classname`/`name` → case identity hint per the mapping doc) yields a real `execution_key`; an unresolvable testcase emits **no** event (T10 forbids unknown keys) and is recorded as discrepancy `unmapped_case` on the report row |
| AC4 | Truncated XML (`</testcase>` mid-stream), a DOCTYPE/entity declaration, or a non-XML body → `raw_report.status = malformed`, zero events inserted, all mapped rows for the report remain `unknown` via the completeness path (never PASS, 00 §8.6); the raw bytes stay as the `raw_report` artifact |
| AC5 | XXE/entity-expansion attack input (`<!ENTITY x SYSTEM "file:///etc/passwd">`, billion-laughs) is rejected: no external fetch, parser throws under the depth/expansion caps, status `malformed`, and no bytes of the target file appear in any row or log (S5) |
| AC6 | `GET /v1/runs/{r}/reports/{report_id}/comparison` (`run:read`) returns per-case rows `{ case_ref, declared_status, observed_events, discrepancies[] }` plus summary `{ declared_*, observed_*, status }` and `raw_report_artifact_id`; raw bytes are never inlined; other-tenant report id → 404; `report_id` of a different run → 404 |
| AC7 | Two parses of the same bytes under the same `parser_version` produce identical event sets (deterministic: synthetic `producer_id = junit:<raw_report_id>`, sequence = document order); under a new version they produce a new `raw_report` row and new event set, the old rows untouched (D4, input to 04.4.2) |
| AC8 | UTF-8/UTF-16 with/without BOM, control characters and 4-byte emoji in `classname`/`name` parse or normalise without data loss; a file over the size cap is rejected at parse time `413`-equivalent → `status = malformed` with reason `too_large` |

## 3. Contracts touched

- `raw_report`/`report_parser` tables (04 §4) — implemented as specified; `raw_report` gains declared/observed counter columns (below) to serve CR-3 without re-parsing.
- `GET /v1/runs/{r}/reports/{report_id}/comparison` (00 §9.3, CR-3) — implemented exactly: `run:read`, comparison + artifact id only.
- Event insert path reuses 04.1.1-T1's single-statement `unnest` insert (T50) with synthetic producer — `unknown_execution_key` can't arise server-side because unmapped cases are skipped pre-insert (AC3).
- Resolved (T3): `report_parser` is platform-scoped registry data (no `org_id` in 04 §4) and is on the T3 platform/catalogue exception list — this plan models it platform-scoped with `unique(parser_id, version)`.

## 5. API shapes (commands, queries, endpoints)

| Operation | Type | Endpoint / trigger | Behaviour |
|---|---|---|---|
| `ParseRawReport` | `ICommand<ParseResult>` | outbox task after artifact `complete` (kind `raw_report`, `producer_kind` from manifest) — fired by 06's `complete` via `IIngestionContracts.RequestReportParseAsync` | handler: resolve parser from `report_parser` (miss → `status=unsupported`) → fetch artifact bytes **outside** the tx (P5) → hardened parse → open tenant tx → insert events (one `unnest` statement) + `raw_report` row → commit |
| `GetReportComparison` | `IQuery<ReportComparison>` | `GET /v1/runs/{r}/reports/{report_id}/comparison` · `run:read` | Dapper read-only tx; joins `raw_report` + aggregated `event` per case; 404 cross-tenant/wrong-run; ETag not required (immutable row) |
| `RegisterReportParser` | internal, migration-only | no endpoint | parser registry is data, seeded by migration; new parser version = new row |

Pipeline: full C2 order applies (telemetry → validation → tenant tx → authorization → handler); `ParseRawReport` runs under `artifact`-internal permission checked at the authorization behaviour; no `Idempotency-Key` (natural idempotency: `raw_report` row keyed by `(artifact_id, parser_version)` — re-delivery is `ON CONFLICT DO NOTHING`).

## 6. States and transitions

`raw_report.status`: `parsed | malformed | unsupported` (04 §4) — set once at insert; **immutable** (one row per parsing; reprocess adds a row, never updates — enforced by `REVOKE UPDATE` + no setters, C6). Events are append-only. Item statuses follow 00 §8.3; `unknown` is never stored — it is the completeness-level outcome for unmapped/malformed input (00 §8.5).

## 7. Jobs and integrations

- Parse task rides the shared outbox → `task` queue (00 §5.3): `SKIP LOCKED` claim, `available_at` backoff, idempotent by `(artifact_id, parser_version)`; failure → retry cap → `dead_letter`.
- Calls 06 contract to fetch artifact bytes (S3-compatible GET) — strictly before opening the tenant transaction (P5).
- On success writes an outbox row so 06's freeze/`reconciler` sees the new events (flow 3 "reconciler trigger"); on `malformed`/`unsupported` writes the row so freeze can record the `missing[]` reason (04 §5 rows).
- T48 dogfooding: Evidgate's own xUnit JUnit + Vitest JUnit outputs are fixtures for this mapper (04.6.1-T2).

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| S5 (untrusted parsers) | `XmlReader` with `DtdProcessing.Prohibit`, `XmlResolver=null`, `MaxCharactersFromEntities`/`MaxCharactersInDocument` caps, depth cap, read timeout; input size cap before parse | AC4, AC5, AC8 + `xxe.test` |
| 00 §5.4 / T2–T3 | All `raw_report` access inside `ITenantScope.BeginAsync`; RLS policies on `evidgate.current_org_id()`; `unique (org_id,id)` + composite FKs | RLS isolation test (no `set_config` → zero rows) |
| C2/S2 | `run:read` enforced in pipeline for the query; parse command authorized as internal task principal | architecture test + endpoint test |
| S1 | Dapper parameters everywhere; comparison SQL is static | code review + test |
| S3 | Raw XML bytes never logged; logs carry `request_id`, `run_id`, `report_id`, counts only (04 §6) | log assertion in parse test |
| P5 | Artifact fetch (network) happens before the DB transaction opens | `ParseRawReport` handler test asserting tx starts after fetch |
| P2/P3 | Events inserted in one `unnest` statement; comparison query = 2 statements (report row + aggregated events), asserted by command counter | integration tests |
| P4 | `(org_id, run_id, id)` index serves AC6 | `EXPLAIN` assertion |
| P1 | Parse is off the ingest hot path (async task); comparison p95 target < 500 ms on the 10 fixture | measured in 10.6.1 |
| PDPL/retention | Raw XML may contain user data (DECISIONS §7): stored as `raw_report` artifact, subject to 06 retention + sensitivity; `discrepancies` jsonb carries case ids and counts only — no message bodies | — |

- **Authorization:** `GET /v1/runs/{r}/reports/{report_id}/comparison` requires `run:read`, enforced in the C2 pipeline; `ParseRawReport` is authorized as the internal task principal under the `artifact`-internal permission (04.4.1-T1.4), never a user request.
- **Retention/deletion:** the raw report lives as a `raw_report` artifact under 06's retention and sensitivity rules; `raw_report` rows are immutable (one row per parse, `REVOKE UPDATE`, reprocess appends) and `discrepancies` carries case ids and counts only, never message bodies.
- **Telemetry:** the `parser-error rate` and `artifact-failure rate` SLIs (00 §11) count `raw_report.status` values; logs carry `request_id`/`run_id`/`report_id` and counts only, never raw XML (00 §5.7 S3).
- **Failure path:** a DOCTYPE/entity, a truncated document or an oversize input yields `raw_report.status = malformed` with zero events and a reason (`too_large`/`entity`/`malformed`), never a silent pass and never an exception escaping the handler (AC4, AC5); an unresolvable parser is `status = unsupported`.

### 04.4.1-T2 — Hardened XML parsing (M)

Depends: 04.4.1-T1.

| Sub-task | Work | Size | Done when |
|---|---|---|---|
| 04.4.1-T2.1 | `XmlReaderSettings` hardening wrapper: DTD/XXE off, resolver null, expansion/depth/size caps, timeout; UTF-8/16+BOM; control-char normalisation | S | `Xxe_Rejected`, `BillionLaughs_Capped`, `Encoding_*` green (AC5, AC8) |
| 04.4.1-T2.2 | Cap breach → typed `ReportMalformedException(reason)` (`too_large`, `too_deep`, `entity`); fuzz seed corpus run through the parser | S | boundary tests at each cap pass; no throw escapes the typed error |

Notes (hand-over from 06.3.1-T1, S37): the parser profile is published on `Evidgate.Modules.Evidence.Contracts.IParsing` — `ParseXmlReport(Stream content, long maxBytes, CancellationToken ct)` and `ParseJson(Stream content, long maxBytes, CancellationToken ct)` return the shared-kernel `Result<T>` (failure code `artifact_invalid` with a generic reason from {`dtd_prohibited`, `depth_exceeded`, `size_exceeded`, `timeout`, `malformed`}, or `payload_too_large`), and `SniffMediaType(string declaredMediaType, ReadOnlySpan<byte> prefix)` returns a media-sniff verdict. 04.4.1-T2.1 should consume this streaming, bounded, entity-free contract instead of a second `XmlReaderSettings` wrapper, so T2.2's cap breach maps to the same failure codes; `maxBytes` carries the per-kind cap. Three points bind T2.1/T2.2: (a) the profile is synchronous and its 30 s cap is cooperative (checked between reads and per node), so T2.1 passes an already-buffered, bounded stream — hard isolation is 06.3.6; (b) `ParseXmlReport` returns only after the whole document is validated and its `OpenReader()` is a sync reader (`Async = false`), so the mapper walks it with sync reads (or asks for an async variant); (c) a UTF-16/UTF-32 XML body sniffs `Mismatch` (06.3.1-T2.2 decides; AC8's UTF-16 case cannot trigger until then) and, for such encodings, a declared DTD reads `malformed` rather than `dtd_prohibited`. A JSON string holding an escaped lone surrogate (`\ud800`) parses but makes `GetString()` throw, so the mapper uses `TryGetString` (or handles `InvalidOperationException`).

## 11. Rollout

- Server-side module ships normally; parse is triggered only for artifacts with `kind=raw_report` + a `producer_kind` that resolves in `report_parser`, so existing CI-mode runs are unaffected (implicit gate).
- Merge order: T1 → T2 → T3 (M1 legs), then T4 → T5 → T6 (M2/M3 legs) per area plan milestones; 04.4.2 (reprocess) and 09.2.1 (view) build on T4/T6.
- Monitoring: `parser-error rate` and `artifact-failure rate` SLIs (00 §11) — counters per `status` value on `raw_report` inserts; `unsupported` spikes mean a new producer dialect arrived.
- Rollback: remove the seeded `report_parser` row's consumer (deploy gate); stored rows and events are immutable evidence and stay queryable.
