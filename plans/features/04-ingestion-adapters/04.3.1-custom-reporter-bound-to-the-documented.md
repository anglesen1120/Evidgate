## 1. Goal and non-goals

**Goal.** A `@evidgate/playwright-reporter` package that implements the documented Playwright reporter API (`onBegin`, `onTestBegin`, `onTestEnd`, `onEnd`), emits one event-envelope v1 line per callback into the CLI spool, declares its capability document, and refuses to run against an unsupported `@playwright/test` major version.

**Non-goals.** Case/variant identity (`evidgate.id`, `variant_hash`) — 04.3.2-T1; status semantics (retries, `fixme`, interrupts) — 04.3.2-T2; shard→producer mapping and attachments — 04.3.3; POSTing to the API — the CLI spooler does that (04.2.3-T1); the capability JSON Schemas themselves — 04.7.1-T1.

## 2. User stories and acceptance criteria

- As a customer running Playwright, I add one reporter line to `playwright.config.ts` and get envelopes written to the Evidgate spool, so the CLI can deliver them.
- As the Tech Lead, I want the reporter to hard-fail on an untested Playwright version, so we never silently mis-map a changed API.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | With `reporter: [['@evidgate/playwright-reporter', { spool_dir }]]` and the pinned `@playwright/test@1.63.x`, a run of 3 tests produces exactly one `test.started` and one `test.finished` envelope per attempt in `<spool_dir>/<run_id>/<producer_id>/` (00 §9.4 fields all present) |
| AC2 | `onTestBegin` → `test.started` (no `status`); `onTestEnd` → `test.finished` with `status` = the raw Playwright status string and `duration_ms` = `result.duration`; `onBegin`/`onEnd` produce `run.log` marker events only — no invented event types |
| AC3 | The first envelope written is the capability document (`protocol {major:1, minor:0}`, `engine {family:"playwright", version}`, `platforms`, `supports {discovery:false, step_events:true, retry:true, cancel:false}`, `mode:"full"`) validating against `contracts/adapter/capability.v1.json` |
| AC4 | Sequence numbers are per-producer monotonic and contiguous starting at 1; `event_id` is a fresh UUIDv7 per envelope, stable across a process restart only via the spool checkpoint (04.2.3) |
| AC5 | With `@playwright/test` outside the supported range (guard: `^1.63`), reporter construction throws `EvidgateUnsupportedEngineError` naming installed vs supported versions — no partial emit (04 §8 risk row) |
| AC6 | `result.steps` map to `test.step` envelopes only when `supports.step_events` is declared; a reporter configured `steps:false` emits none and still passes AC1 |

## 3. Contracts touched

- `contracts/adapter/capability.v1.json` (04.7.1-T1) — consumed; the reporter's document must validate. Any new `supports` flag is a contract change, not a local edit.
- 00 §9.4 envelope — emitted verbatim; `ext` carries `{ "schema": "playwright/1", … }` with allow-listed keys only (04 §6).
- D8 / 00 §10: engine version comes from `require('@playwright/test/package.json').version` at runtime and travels in the capability document; the package pins no engine itself beyond the guard.
- ⚠️ Open from area plan §4 (recorded, not resolved here): exact `TestResult.retry` field name, attachment field names, `--shard` syntax page — confirmed in 04.3.2/04.3.3 sub-tasks before their mapping lands.

## 4. Data model and migrations

None server-side. Reporter-local state: `spool/` envelope files `NNNNNN.jsonl` chunks + `checkpoint.json` `{ producer_id, next_sequence }` written fsync'd per batch (format shared with 04.2.3-T1's spool reader — same directory contract).

## 5. API shapes (commands, queries, endpoints)

No HTTP API — the reporter is a Node library (Node 22+, TS 6.0, `packages/adapter-playwright`, published as `@evidgate/playwright-reporter`).

| Surface | Shape |
|---|---|
| Reporter class | `class EvidgateReporter implements Reporter` — ctor options `{ spool_dir, run_id, producer_id, steps?: boolean, mode?: "full" \| "ingest_only" }`; env fallback `EVIDGATE_SPOOL_DIR`, `EVIDGATE_RUN_ID` |
| Callbacks | `onBegin(config, suite)` → capability doc + `run.log`("run_begin"); `onTestBegin(test, result)` → `test.started`; `onTestEnd(test, result)` → `test.finished` + steps; `onEnd(result)` → `run.log`("run_end", status) + fsync + checkpoint |
| Errors | never throw inside callbacks except the version guard at construction; a spool write failure throws on `onEnd` so the Playwright run reports the reporter failure instead of losing evidence silently |

## 6. States and transitions

Envelope lifecycle: composed → appended to spool file → fsync → checkpoint `next_sequence` bumped. The reporter itself is stateless across shards; `producer_id` is an input (04.3.3-T1 decides its value), not minted here. No server state machine touched.

## 7. Jobs and integrations

- Playwright test runner invokes the callbacks in-process; the reporter must return before the runner proceeds — all I/O is append+fsync, no network (S5/P5 analogue: no network inside the test process).
- Consumed by the CLI spooler (04.2.3-T1) which owns batching/POST/retry; the reporter never opens a socket.
- Validator parity (T42): the capability document and every emitted envelope are checked against `contracts/` schemas with Ajv 8 in this package's tests; the server checks the same files with Corvus — the shared `fixtures/contracts/` corpus fails either build on disagreement.

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| 04 §6 `ext` allow-list | Only declared keys (`test.title`, `test.file`, `test.location`, project name, engine version) reach `ext`; secret-looking key names (`*token*`, `*secret*`, `*password*`) are dropped and counted | `ext-filter.test.ts` |
| NFR-04-2 | Runs on Node 22+/26, Linux/macOS/Windows runners; no native deps | matrix CI job (04.6.1-T3 consumes) |
| FR-04-6 | `status` is the raw Playwright string verbatim; normalisation is server-side with `parser_version` recorded | AC2 asserting raw string pass-through |
| S3 | Reporter never sees tokens (no network); spool dir created `0700`; envelope files `0600` | `spool.test.ts` mode assertion |
| Performance | Per-callback work is O(1): JSON serialise + append; no buffering of the whole suite in memory (long suites must not grow RSS) | `memory.test.ts`: over 10k appends the `SpoolWriter` pending batch never exceeds `DEFAULT_FLUSH_THRESHOLD` (no RSS assertion) |
| Retention/deletion | Spool files are consumed/deleted by the CLI (04.2.3); reporter deletes nothing | — |

## 11. Rollout

- Merge behind no flag; the package is inert until a customer lists it in `reporter:`. Merge order: after 04.7.1-T1 schemas; before 04.3.2 (identity/status) and 04.3.3 (shards/attachments) extend the same class.
- Monitoring: none at runtime (in-process library); failures surface as Playwright reporter errors.
- Rollback: remove the reporter line from the customer config; no server state involved.
