## 1. Goal and non-goals

**Goal.** An org can register a SAML 2.0 IdP (metadata URL or pasted XML + signing certificate), users log in SP-initiated through it, assertions map to `user_identity (provider, subject)` where `provider` = the per-connection `saml` code, and the session produced is the same `session` row + `__Host-` cookie model as 02.3.2. Just-in-time membership policy is configurable per connection (bind-by-invite only, or bind-by-domain) — in both modes a SAML assertion can bind a membership only in the connection's **own org** and, in `domain` mode, only for the connection's **DNS-verified** domains (T75).

**Non-goals.** IdP-initiated SSO (rejected: `InResponseTo` cannot be validated — recorded in §3); SCIM/directory sync; SLO (single logout — V3 accepts session-side logout only); OIDC providers (02.3.1); UI screens (09, V3); SAML for CLI/CI (never — interactive browser flow only).

## 2. User stories and acceptance criteria

- As a `tenant_admin`, I paste my IdP metadata and my Entra/Okta users can log in — landing in the same session model as OIDC users.
- As a security reviewer, forged or replayed assertions are rejected, and a SAML login can never claim a session in another org.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | Happy path against a test IdP (fixture-signed assertion): `POST /v1/auth/saml/{conn}/acs` validates signature + conditions → `user_identity (saml:<conn>, NameID)` upsert → `member_orgs` → membership check → `session` + `__Host-` cookie |
| AC2 | Tampered assertion (modified attribute, wrong/missing signature, expired `NotOnOrAfter`, `NotBefore` future > 60 s skew, wrong `Audience`/`Recipient`, missing `InResponseTo`) → 401 `token_invalid`/`saml_rejected`; XML with DTD/external entities rejected before parse (S5) |
| AC3 | Replay: the same assertion id presented twice → 401 `token_replayed` (assertion ids cached per connection for the assertion lifetime + 10 min) |
| AC4 | Tenant binding: the connection resolves the org **pre-tenant** via `evidgate_resolve` (T1) keyed on the connection id in the ACS path; assertions can never select another org |
| AC5 | JIT policy `invite_only` (default): uninvited user → 403 `no_membership`; a SAML assertion binds a `pending` invite only in the connection's **own org** and only when the asserted email domain is DNS-verified on that connection (T75). Policy `domain` additionally accepts any member of the connection's verified domains — never an invite of another org nor an unverified domain (cross-org negative test) |
| AC6 | `user_identity.subject` is stored as `connection_id ‖ NameID` — a NameID from another connection is a different subject (D3: no cross-org identity merge) |
| AC7 | SP metadata endpoint `GET /v1/auth/saml/{conn}/metadata` serves entity id, ACS URL, and our signing cert; rotating the SP cert keeps the old cert valid for a published overlap window |
| AC8 | Org admin CRUD on the connection: `POST /v1/orgs/{o}/sso/saml` (metadata URL fetch is SSRF-guarded: allow-list scheme https, private/link-local ranges blocked — S4), `PATCH`, `DELETE`; built-in deny: connection for another org → 404 |

## 3. Contracts touched

- `user_identity.provider` gains the form `saml:<connection_id>` (02.3.1's check constraint `provider ∈ {github, google}` is extended by migration — a schema change to the §4.5 exception table, recorded here).
- New permission strings appended to `contracts/permissions.json` (owner 02.2.1): `sso:read`, `sso:write` on `tenant_admin` — flagged as a catalogue addition, refinement of 00 §2.
- Recorded — IdP-initiated SSO is refused by design (no `InResponseTo`); if a pilot customer needs it, an unsolicited-response allowlist is a CR against this plan.
- Recorded — the area plan lists `user_identity` providers as `{github, google}`; `saml:<conn>` extends that enum — consistent with the enum being per-row text, flagged for the integrator.

## 4. Data model and migrations

`migrations/NNNN_identity_saml.sql` (new table is tenant-scoped business data):

- `saml_connection`: `id uuid`, `org_id not null` → `organization`, `entity_id text`, `sso_url text`, `idp_certificate bytea` (PEM/DER), `metadata_url text null`, `sp_certificate_id`, `jit_policy text` (`invite_only|domain`), `domains text[]` (DNS-verified at setup, T75 — an unverified domain never binds), `nameid_format`, `status text` (`active|disabled`, cf. `ci_binding` lifecycle §8.9), `created_at`, `updated_at`, `version`. Constraints: `unique (org_id, id)` (T3), `unique (entity_id)` (one IdP entity per platform), `unique (org_id)` for V3 (one SAML connection per org — raise via CR if needed). Index `(org_id, status)`.
- `saml_assertion_seen`: `id uuid`, `org_id`, `connection_id`, `assertion_id`, `expires_at`; `unique (connection_id, assertion_id)` — the replay cache (T7 pattern); purged daily.
- `user_identity` migration: extend provider check to allow `saml:%`.
- RLS: `ENABLE` + `FORCE` + `org_id = evidgate.current_org_id()` policy (same migration — helpers exist since 02.6.1-T1, an M1 prerequisite of M5).

## 5. API shapes (commands, queries, endpoints)

| Command / Query | Endpoint | Permission | Codes |
|---|---|---|---|
| `CreateSamlConnectionCommand` / `UpdateSamlConnectionCommand` / `DeleteSamlConnectionCommand` | `POST/PATCH/DELETE /v1/orgs/{o}/sso/saml` | `sso:write` (`tenant_admin`) | 201/200/204; 404; 409 `entity_id_taken`; 422 `saml_metadata_invalid`; `Idempotency-Key` + `If-Match` per 00 §9.1 |
| `GetSamlConnectionQuery` (Dapper) | `GET /v1/orgs/{o}/sso/saml` | `sso:read` | 200; certificate fingerprints shown, never keys |
| `SpMetadataQuery` | `GET /v1/auth/saml/{conn}/metadata` | public (metadata is public by design) | 200 XML |
| `StartSamlLogin` | `GET /v1/auth/saml/{conn}/login` | public | 302 to IdP with signed `AuthnRequest`; `request_id` recorded for `InResponseTo` |
| `CompleteSamlLoginCommand` | `POST /v1/auth/saml/{conn}/acs` | public, pre-tenant | 302 to app or 401/403 per AC2–AC5 |

ACS flow: parse+validate XML (DTD/XXE off, S5) → resolve org via `evidgate_resolve.saml_connection(connection_id)` (T1 — new resolver function added to 02.6.1's schema via this migration) → open tenant scope → verify signature/`InResponseTo`/conditions/replay → upsert `user_identity` → membership/JIT check → `ISessions.Create` → `__Host-` cookie.

## 6. States and transitions

`saml_connection.status`: `active → disabled` (admin toggle) and `active → deleted` (org deletion path); `disabled` → ACS returns 403 `sso_disabled`. No other transitions; cert rotation is a field update audited like any PATCH.

## 7. Jobs and integrations

- `saml-assertion-purge` Cronos task: deletes `saml_assertion_seen` rows past `expires_at` (assertion lifetime + 10 min, T7 pattern).
- IdP metadata refresh (optional): when `metadata_url` set, a daily task refetches and diffs the cert — on change, audit row + security event; never silently swaps trust anchors (auto-swap is a 11-reviewed decision; V3 default = alert only).
- `evidgate_resolve.saml_connection(connection_id)` SECURITY DEFINER function (schema owned by 02.6.1-T3) ships in this story's migration.

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| S5 (untrusted parsers) | SAML XML parsed with DTD/external entities off, depth/size caps, signature required before attribute read; signed XML required (no unsigned assertion path) | `SamlParseTests.XxeRejected`, `UnsignedRejected` |
| T1 / 00 §5.4.8 | ACS is pre-tenant; org resolved via `evidgate_resolve` on the connection id, not on assertion content | `SamlAcsTests.ForeignOrgConnection404`-style isolation test (AC4) |
| T75 invite scope | SAML binds memberships only inside the connection's own org and only for its DNS-verified domains; invite secret + verified-email rules of 02.1.2 still apply | `SamlBindTests.ForeignInviteNeverBinds`, `UnverifiedDomainNoBind` (AC5) |
| FR-02-4 / D3 | identity key `(saml:<conn>, NameID)`; email from assertion is a claim, not a key; invite bind still requires a match (AC5) | `JitTests.*` |
| T38 | resulting session is the standard cookie+antiforgery model | reuse `CookieAttributeTests` fixture |
| S3/S4 | IdP certs/secrets never logged; metadata fetch through the SSRF-guarded allowlist client | `MetadataFetchTests.PrivateRangeBlocked` (AC8) |
| P5 | no HTTP call inside a DB tx (metadata fetch happens in the admin command *before* the tx or in the refresh task) | code review + `P5Tests` convention |
| Replay defence | `unique (connection_id, assertion_id)` + `InResponseTo` requirement | AC3 test |
| Privacy/PDPL | stores NameID + email + optional display attributes only (02 §6 minimum); connection config is tenant data | — |
| Retention/deletion impact | `saml_connection` deleted with the org (T16); assertion cache rows purge daily | — |

## 11. Rollout

- V3/M5: ships after the V2 review gate; flag `saml_enabled` per org (default off) until the first pilot completes a security pass.
- Order within the task: T1.1–T1.2 (config exists, unreachable) → T1.3–T1.4 (ACS live) → T1.5–T1.6 (policies + hardening).
- Monitoring: `saml_login` counter by `{connection, result}`; assertion-reject rate per connection; metadata-refresh drift alerts.
- Rollback: set connection `disabled` (instant, per org) or revert endpoints; tables additive.
