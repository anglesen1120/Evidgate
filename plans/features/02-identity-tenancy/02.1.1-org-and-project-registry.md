## 1. Goal and non-goals

**Goal.** `organization` and `project` exist as the root of every tenant hierarchy, with RLS-ready schema (`unique (org_id, id)` on `project`, composite-FK targets), CQRS commands/queries for create/read/update, scope enforcement (org from the authenticated principal, project id in the URL must match the token scope), and quota/limit columns consumed later by plan 12.

**Non-goals.** RLS policies themselves, `evidgate` helper functions and `evidgate_resolve` (02.6.1); membership and invites (02.1.2); the permission catalogue (02.2.1); the `environment` table and the `project.default_environment_id` FK target (05.1.2-T1); UI screens (09.7.1); metering arithmetic (12).

## 2. User stories and acceptance criteria

- As a `tenant_admin`, I create and rename projects under my org so my repositories can be onboarded.
- As any member, I read my org and its projects; a project in another org is indistinguishable from a missing one.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `project` carries `unique (org_id, id)` and `unique (org_id, slug)`; `organization` carries `unique (slug)` — verified by querying `pg_constraint` in the migration test |
| AC2 | `POST /v1/orgs/{o}/projects` with a slug already used in the same org → 409 `slug_taken`; the same slug in another org succeeds |
| AC3 | `GET /v1/projects/{p}` for a project id of another org → 404 `not_found`, and one `audit_log` row is written for the denied lookup (02.7.1 mechanism, asserted once available; until then the 404 alone is asserted) |
| AC4 | A token scoped to project A calling `PATCH /v1/projects/{B}` → 403 `project_scope_mismatch` (00 §9.1) |
| AC5 | `PATCH` with a stale `If-Match` → 412 `precondition_failed` with the current `version` in `error.details`; correct `If-Match` bumps `version` |
| AC6 | `POST` mutations with a repeated `Idempotency-Key` and identical payload return the original response; changed payload → 409 `idempotency_conflict` (T11) |
| AC7 | With the tenant GUC unset (or empty), `select` on `organization`/`project` as `evidgate_app` returns 0 rows — RLS is `ENABLE` + `FORCE` with the app policy created by 02.1.1-T1 (fail-closed before and after 02.6.1); `evidgate_operator` also returns 0 rows until 02.8.1's grant-gated operator policy exists (T76) |
| AC8 | `POST /v1/orgs` grants the creator **both** `tenant_admin` and `release_approver` membership roles in the same transaction (T98 — a pilot may be one person); either role can later be reassigned to another member subject to the last-admin guard |

- Recorded — `POST /v1/orgs` grants the creator `tenant_admin` **and** `release_approver` memberships (T98), which write `membership`/`membership_role` — tables owned by 02.1.2-T1 (build order solves it: 02.1.2-T1 lands before this command is exercised; noted here, not silently resolved).
- Recorded — the area plan lists `02.1.1` in 02.2.1's "Depends on" and vice versa (task-level DAG is acyclic: 02.1.1-T1 → 02.2.1-T1/T2 → 02.1.1-T2); recorded, harmless.
- Recorded — the `allowed_email_domains` cap of 64 entries is a contract addition of this task (00 §5.7 S3 asked only for input limits); the migration check and §4 both carry it.
- Recorded — a malformed `evidgate.org_id` value (not a UUID, not empty) makes `evidgate.current_org_id()` raise `22P02` instead of returning NULL. Fail-closed and accepted: 00 §5.4.7/T2 specify only the unset/empty case, and the GUC is set by the scope primitive (02.6.2), never by request input.
- Recorded — keyset predicate (D8, for 02.1.1-T2), superseding the earlier note: the list query is two statements (`TenancyReadSql.ProjectsFirstPage` with no cursor predicate, `TenancyReadSql.ProjectsNextPage` with the row comparison), because the previous single statement's `(@cursor is null or (created_at, id) > (@cursor…))` form could not be an index condition. On the pinned `postgres:18.6` with `enable_seqscan = off` and 40 seeded rows, the next page's plan is `Index Scan using project_org_status_created_id_idx` with `Index Cond: ((org_id = …) AND (status = 'active') AND (ROW(created_at, id) > ROW(…)))` — the row comparison is now an index condition, not a residual `Filter`. 02.1.1-T2's statement-budget test therefore counts one statement per page.
- Recorded — the app role holds no DELETE on either registry table (M1W3-05): select/insert/update, plus an explicit `revoke delete`, because 0001's `alter default privileges` grant DELETE on every table `evidgate_owner` creates in `public` and a `grant` cannot take it away. Removing an organization or a project is the `status = 'deleted'` transition (a command, audited by 02.7.1) or the T16 operator route, never a lost row.
- Recorded — `version` is incremented by the database, not by a command (M1W3-01): migrations 0004/0005 attach the shared `set_updated_at_and_version` BEFORE UPDATE trigger (`updated_at = now()`, `version = old.version + 1`), and the EF write model treats the column as store-generated on update, so no command sets either column and 02.1.1-T2's `If-Match` compare-and-swap compares the token the server wrote.
- Recorded — the Dapper read path's process-wide prerequisites (M1W3-02): `DefaultTypeMap.MatchNamesWithUnderscores`, a `DateTimeOffset` handler (Npgsql reports `timestamptz` as `DateTime`) and a `string[]` handler (`text[]` arrives as `System.Array`). `AddEvidgateTenancy` sets all three; without them Dapper cannot even select a positional record as a materialization target, and the `TenancyReadSql` column order stays equal to the DTO constructor's parameter order because that is what Dapper matches against.
- Recorded — `POST /v1/orgs` (02.1.1-T2) must seed `evidgate.org_id` with the freshly generated org id before inserting the row: the app policy's `WITH CHECK (id = evidgate.current_org_id())` rejects an unset-tenant insert (T2 fail-closed).

- Recorded — **implementation notes of 02.1.1-T2/T3 (2026-10-03)**, all logged in 00 §15:
  - **`POST /v1/orgs` authorization.** The org does not exist yet, so no membership can hold `organization:write` in it. The handler carries `[AuthenticatedMember]` instead of `[Permission]`; the C2 authorization stage grants it only to a `Member` principal with a user id (a service token or an operator is 403). The exception is closed by name: `ArchitectureRules.AuthenticatedMemberAllowlist` holds exactly `CreateOrganizationCommandHandler`, and the architecture test fails any other handler carrying it or a handler carrying both gates. In the spec the route is `x-permission: authenticated` (a reserved literal next to `none`) with `x-auth: user_session`.
  - **Org id and idempotency.** The C2 pipeline opens its transaction and its tenant-keyed idempotency lookup in the request tenant, which a new org does not have. The endpoint therefore derives the org id from (principal user id, `Idempotency-Key`) as a SHA-256-based RFC 9562 version 8 UUID (`OrganizationIds.For`) and publishes it as the request tenant. A retry with the same key and body lands in the same tenant and replays (AC6); a changed body is 409 `idempotency_conflict`. Reusing a key after its record expired (≥ 24 h) hits `organization_pkey` and is also 409 `idempotency_conflict`. The user id comes from the principal, never from input, so a caller can only derive ids in its own key space. Org ids are therefore not UUIDv7; `organization` is keyed by `id` alone and small.
  - **Founder membership (AC8).** `membership.invited_email` is NOT NULL (0011), so the creator's membership needs an address. `RequestPrincipal` gains `VerifiedEmail` (filled by 02.3.1 login, never by input), and a member without one is refused with 403. Identity exports `IOrganizationFounder` (Identity.Contracts). Tenancy calls it in the same transaction as the org insert; it writes one `active` membership plus `tenant_admin` and `release_approver` grants. The membership tables stay Identity's.
  - **`GET /v1/orgs` is deferred to 02.6.1-T3.** Listing the caller's orgs crosses tenants, so it needs `evidgate_resolve.member_orgs`. Under RLS a membership join can only return the request's own org, so the route is not mapped rather than shipped wrong. 02.6.1-T3 adds it.
  - **AC3 audit row deferred to 02.7.1-T1.** The `audit_log` table does not exist yet. As the AC allows, the 404 alone is asserted, and 02.7.1 adds the denied-lookup row.
  - **Quota check is two statements (bug found by `ConcurrentCreatesNeverExceedMaxProjects`).** A single `select … (select count(*) …) … for update` passed 8 of 8 concurrent creates against `max_projects = 3`. Under READ COMMITTED the count read the snapshot taken before the statement waited for the lock. The gate now locks the org row (`ProjectCreateGate`), then counts in a separate statement (`ActiveProjectCount`) whose snapshot includes every create that committed meanwhile.
  - **Scope and status.**
    - `{o}` other than the request org → 404.
    - Principal `ProjectScope` or request project other than `{p}` → 403 `project_scope_mismatch`, checked before any read.
    - Deleted org or project → 404.
    - Mutation under a suspended org → 409 `org_suspended`.
    - PATCH bodies change only `name`, `slug`, retention and (org) `allowed_email_domains`; status transitions stay with the operator route of T16 / a later command (§6).
  - **429 `Retry-After`.** 00 §9.2 requires it on every 429/503, so the C8 `ResultEndpointFilter` now sets a default `Retry-After: 60` when the route did not set one.
  - **Shared cursor.** The keyset cursor moved from Identity's internal `ReadCursor` to `SharedKernel.Api.KeysetCursor`, used by roles, memberships and projects.

## 4. Data model and migrations

`migrations/NNNN_identity_organization.sql` + `migrations/NNNN_identity_project.sql` + `migrations/NNNN_tenancy_quota_columns.sql` (DbUp, owner role; module `Tenancy` owns `project`, `Identity` owns `organization` — both live under plan 02 tables):

`organization` (platform exception, T4): `id uuid pk` (UUIDv7, app-generated), `name text not null`, `slug text not null unique` (`^[a-z0-9][a-z0-9-]{1,62}$` check), `status text not null default 'active'` (`active|suspended|deleted`), `retention_default_days int`, `allowed_email_domains text[]`, `max_projects int`, `max_seats int`, `created_at`, `updated_at`, `version int not null default 1` (concurrency token). RLS `ENABLE` + `FORCE`; the app policy `id = evidgate.current_org_id()` and the permissive owner policy are created by 02.1.1-T1 itself (policy work moved ahead of 02.6.1-T1); the `evidgate_operator` policy is deferred to 02.8.1's grant-gated work (T76).

`project` (business table): `id uuid`, `org_id uuid not null` → `organization(id)`, `name`, `slug`, `status text default 'active'`, `default_environment_id uuid null` (composite FK `(org_id, default_environment_id)` added by 05.1.2-T1 once `environment` exists), `retention_days int null` (overrides org default), `monthly_run_quota int null`, `created_at`, `updated_at`, `version`. Constraints: `unique (org_id, id)`, `unique (org_id, slug)`. Indexes: `(org_id, status, created_at, id)` serving `GET /v1/orgs/{o}/projects` cursor pagination. `ENABLE` + `FORCE` RLS; the app policy `USING/CHECK (org_id = evidgate.current_org_id())` and the owner policy are created by 02.1.1-T1; the `evidgate_operator` policy is deferred to 02.8.1 (T76), so the role's `SELECT` grant reads 0 rows until a support grant exists.

Policy-ownership note (recorded, M1 wave 3): the tenant-policy template shipped with the tables in 02.1.1-T1 — `ENABLE` + `FORCE`, the tenant `USING`/`WITH CHECK` (`id = evidgate.current_org_id()` on the `organization` exception), and a permissive `evidgate_owner` policy because FORCE applies to the owner too. The `TO evidgate_operator` policy is deliberately **not** created here: 02.8.1 owns it as the grant-gated `evidgate.operator_grant_ok` form (T76). 02.6.1-T1 still owns the `evidgate` helpers, the `evidgate_resolve` schema, the boot self-check and the CI lint over later tables. The feature order therefore reads: 02.1.1-T1 (base policies) → 02.6.1-T1 (helpers, lint, self-check) → 02.8.1-T1 (operator policy).

`[DECISION]` slug grammar decided (DECISIONS §8.1 D-A1): `^[a-z0-9][a-z0-9-]{0,61}[a-z0-9]$`, shipped by 02.1.1-T2 in `migrations/0012_tenancy_slug_grammar.sql`, which replaces the 0004/0005 checks (the old `^[a-z0-9][a-z0-9-]{1,62}$` accepted a trailing hyphen, `ab-`). The command validators use the same expression (`TenancyRules.SlugPattern`).

Quota columns (02.1.1-T3.1) ship in `migrations/0013_tenancy_quota_columns.sql`: `organization.max_projects`, `organization.max_seats`, `project.retention_days`, `project.monthly_run_quota`, all nullable (null = no limit / inherit), quotas `>= 0`, retention `> 0`.

`allowed_email_domains` is capped at 64 entries by the migration check (`cardinality(...) <= 64`) — the contract addition recorded in §3.

`idempotency_record` (owner 01, T11) is used by commands; no business-table unique on the key.

## 5. API shapes (commands, queries, endpoints)

Commands (`ICommand<T>`, EF Core 10 write model, Mediator pipeline C2; mutations on `POST`/`PATCH` carry `Idempotency-Key`; `PATCH` requires `If-Match`):

| Command / Query | Endpoint | Permission | Codes |
|---|---|---|---|
| `CreateOrganizationCommand` → `OrganizationDto` | `POST /v1/orgs` | authenticated user (`[AuthenticatedMember]`, `x-permission: authenticated`, §3); creates org + creator `tenant_admin` + `release_approver` memberships in one tx (T98) | 201; 401 no caller; 403 service token / no verified email; 409 `slug_taken`, `idempotency_conflict`; 422 invalid slug |
| `GetOrganizationQuery` (Dapper, read-only tx) | `GET /v1/orgs/{o}` | `organization:read` | 200, 404 |
| `UpdateOrganizationCommand` | `PATCH /v1/orgs/{o}` | `organization:write` | 200; 404; 412; 409 `slug_taken` |
| `ListMyOrganizationsQuery` | `GET /v1/orgs` | session user | **Deferred to 02.6.1-T3** (§3): resolves via `evidgate_resolve.member_orgs(user_id)` (T4); not mapped until then |
| `CreateProjectCommand` | `POST /v1/orgs/{o}/projects` | `project:create` (`tenant_admin`) | 201; 409 `slug_taken`; 429 `quota_exceeded` when `max_projects` reached |
| `ListProjectsQuery` (keyset `(created_at, id)`) | `GET /v1/orgs/{o}/projects` | `project:read` | 200 `{items, next_cursor}` |
| `GetProjectQuery` | `GET /v1/projects/{p}` | `project:read` | 200; 404 (cross-tenant id is 404, AC3) |
| `UpdateProjectCommand` | `PATCH /v1/projects/{p}` | `project:write` (T21) | 200; 403 `project_scope_mismatch`; 404; 412 |

Queries run under `ITenantScope.BeginAsync(orgId)` with `SET TRANSACTION READ ONLY` (C5); org id comes from the authenticated principal — never from the URL alone; `{o}` in the path must equal the principal's org else 403/404.

## 6. States and transitions

`organization.status`, `project.status`: `active → suspended → active`, `active|suspended → deleted` (deletion itself is the operator route of T16, owned by 06/10/11 — here only the column and the read filter). Suspended orgs still return read data; mutations get 409 `org_suspended`. Every transition is a command (audited by 02.7.1).

## 7. Jobs and integrations

- None of its own. `evidgate_resolve.member_orgs(user_id)` (02.6.1-T3) backs `GET /v1/orgs` (T4).
- Quota columns (`max_projects`, `max_seats`, `monthly_run_quota`, `retention_*`) are storage + the `ITenantLimits` contract surface read by plan 12 enforcement; no metering here.

## 8a. Security and performance review (2026-10-03)

Two independent AI reviewers worked from this spec package and the diff (SOLO-PATH §3). Neither found a critical or high issue. The reviewers' severities are kept as given.
