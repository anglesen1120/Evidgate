## 1. Goal and non-goals

**Goal.** `organization` and `project` exist as the root of every tenant hierarchy, with RLS-ready schema (`unique (org_id, id)` on `project`, composite-FK targets), CQRS commands/queries for create/read/update, scope enforcement (org from the authenticated principal, project id in the URL must match the token scope), and quota/limit columns consumed later by plan 12.

**Non-goals.** RLS policies themselves, `evidgate` helper functions and `evidgate_resolve` (02.6.1); membership and invites (02.1.2); the permission catalogue (02.2.1); the `environment` table and the `project.default_environment_id` FK target (05.1.2-T1); UI screens (09.7.1); metering arithmetic (12).

## 2. User stories and acceptance criteria

- As a `tenant_admin`, I create and rename projects under my org so my repositories can be onboarded.
- As any member, I read my org and its projects; a project in another org is indistinguishable from a missing one.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `project` carries `unique (org_id, id)` and `unique (org_id, slug)`; `organization` carries `unique (slug)` — verified by querying `pg_constraint` in the migration test |
| AC2 | `POST /v1/orgs/{o}/projects` with a slug already used in the same org → 409 `slug_taken`; the same slug in another org succeeds |
| AC3 | `GET /v1/projects/{p}` for a project id of another org → 404 `not_found`, and one `audit_log` row is written for the denied lookup (02.7.1 mechanism, asserted once available; until then the 404 alone is asserted) |
| AC4 | A token scoped to project A calling `PATCH /v1/projects/{B}` → 403 `project_scope_mismatch` (00 §9.1) |
| AC5 | `PATCH` with a stale `If-Match` → 412 `precondition_failed` with the current `version` in `error.details`; correct `If-Match` bumps `version` |
| AC6 | `POST` mutations with a repeated `Idempotency-Key` and identical payload return the original response; changed payload → 409 `idempotency_conflict` (T11) |
| AC7 | With the tenant GUC unset, `select * from project` as `evidgate_app` returns 0 rows once policies exist; before 02.6.1 lands, RLS is enabled-but-policy-less (fail-closed, also 0 rows) |

## 4. Data model and migrations

`migrations/NNNN_identity_organization.sql` + `migrations/NNNN_identity_project.sql` + `migrations/NNNN_tenancy_quota_columns.sql` (DbUp, owner role; module `Tenancy` owns `project`, `Identity` owns `organization` — both live under plan 02 tables):

`organization` (platform exception, T4): `id uuid pk` (UUIDv7, app-generated), `name text not null`, `slug text not null unique` (`^[a-z0-9][a-z0-9-]{1,62}$` check), `status text not null default 'active'` (`active|suspended|deleted`), `retention_default_days int`, `allowed_email_domains text[]`, `max_projects int`, `max_seats int`, `created_at`, `updated_at`, `version int not null default 1` (concurrency token). RLS `ENABLE` + `FORCE`; policy `id = evidgate.current_org_id()` added by 02.6.1-T1.

`project` (business table): `id uuid`, `org_id uuid not null` → `organization(id)`, `name`, `slug`, `status text default 'active'`, `default_environment_id uuid null` (composite FK `(org_id, default_environment_id)` added by 05.1.2-T1 once `environment` exists), `retention_days int null` (overrides org default), `monthly_run_quota int null`, `created_at`, `updated_at`, `version`. Constraints: `unique (org_id, id)`, `unique (org_id, slug)`. Indexes: `(org_id, status, created_at, id)` serving `GET /v1/orgs/{o}/projects` cursor pagination. `ENABLE` + `FORCE` RLS; policies `USING/CHECK (org_id = evidgate.current_org_id())` added by 02.6.1-T1 — until then RLS is enabled with no policy (fail-closed, zero rows).

`idempotency_record` (owner 01, T11) is used by commands; no business-table unique on the key.

## 5. API shapes (commands, queries, endpoints)

Commands (`ICommand<T>`, EF Core 10 write model, Mediator pipeline C2; mutations on `POST`/`PATCH` carry `Idempotency-Key`; `PATCH` requires `If-Match`):

| Command / Query | Endpoint | Permission | Codes |
|---|---|---|---|
| `CreateOrganizationCommand` → org id + `version` | `POST /v1/orgs` | authenticated user (`organization:write`); creates org + creator `tenant_admin` membership in one tx | 201; 409 `slug_taken`; 422 invalid slug |
| `GetOrganizationQuery` (Dapper, read-only tx) | `GET /v1/orgs/{o}` | `organization:read` | 200, 404 |
| `UpdateOrganizationCommand` | `PATCH /v1/orgs/{o}` | `organization:write` | 200; 404; 412; 409 `slug_taken` |
| `ListMyOrganizationsQuery` | `GET /v1/orgs` | session user | 200; resolves via `evidgate_resolve.member_orgs(user_id)` (T4) once 02.6.1-T3 lands |
| `CreateProjectCommand` | `POST /v1/orgs/{o}/projects` | `project:create` (`tenant_admin`) | 201; 409 `slug_taken`; 429 `quota_exceeded` when `max_projects` reached |
| `ListProjectsQuery` (keyset `(created_at, id)`) | `GET /v1/orgs/{o}/projects` | `project:read` | 200 `{items, next_cursor}` |
| `GetProjectQuery` | `GET /v1/projects/{p}` | `project:read` | 200; 404 (cross-tenant id is 404, AC3) |
| `UpdateProjectCommand` | `PATCH /v1/projects/{p}` | `project:write` (T21) | 200; 403 `project_scope_mismatch`; 404; 412 |

Queries run under `ITenantScope.BeginAsync(orgId)` with `SET TRANSACTION READ ONLY` (C5); org id comes from the authenticated principal — never from the URL alone; `{o}` in the path must equal the principal's org else 403/404.

## 6. States and transitions

`organization.status`, `project.status`: `active → suspended → active`, `active|suspended → deleted` (deletion itself is the operator route of T16, owned by 06/10/11 — here only the column and the read filter). Suspended orgs still return read data; mutations get 409 `org_suspended`. Every transition is a command (audited by 02.7.1).

## 7. Jobs and integrations

- None of its own. `evidgate_resolve.member_orgs(user_id)` (02.6.1-T3) backs `GET /v1/orgs` (T4).
- Quota columns (`max_projects`, `max_seats`, `monthly_run_quota`, `retention_*`) are storage + the `ITenantLimits` contract surface read by plan 12 enforcement; no metering here.
