> Contracts: project-scoped ingest and declared CI metadata (00 §§8–10); D-NO-GITHUB removes provider trust and delivery.

## 1. Goal and non-goals

Exchange a project ingest token for a short-lived producer credential. The provider JWT grant, bindings and issuance ledger are removed; 02.11.1 owns their cutover.

## 2. User stories and acceptance criteria

A trusted job with a valid project token can ingest for that project. Revoked, rotated-out, expired, malformed or wrong-project credentials fail. No branch, repository or workflow name grants access.

## 3. Contracts touched

`POST /v1/ci/token` accepts the ingest-token grant; see 02.4.2 for secret lookup, rotation and revocation. Remove the provider JWT shape without changing the survivor.

## 4. Data model and migrations

Retain project ingest-token records, peppered hashes, project scopes and normal retention. The integration-only tables and dependent definers are retired by 02.11.1, not recreated here.

## 5. API shapes (commands, queries, endpoints)

A trusted job exchanges the ingest token and receives a scoped `ci_producer`. The service rejects the former provider login shape. No repository binding is created or read.

## 6. States and transitions

Project credential states and permitted rotation overlap follow 02.4.2. A producer bearer expires at its own deadline; revoking the parent prevents new exchanges, not already-issued tokens.

## 7. Jobs and integrations

No provider network request or issuer-key refresh. Retain normal credential rate limits and audit; 02.11.1 retires the issue-ledger purge.

## 8. Security, privacy and performance

- **Authorization:** Scope the producer to the authenticated project and allowed permissions, never a declared ref.
- **Retention/deletion:** Retain ingest-token hashes and exchange audit per project policy, not raw tokens.
- **Telemetry:** Count exchange outcomes; no secret, branch, token or repository as a label.
- **Failure path:** Reject invalid or expired credentials without falling back to another grant.
