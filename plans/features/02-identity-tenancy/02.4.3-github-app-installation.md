## 1. Goal and non-goals

**Goal.** Record one Evidgate GitHub App (single App, many installations) and bind one installation per organization. The installation id is stored per org; a short-lived installation token is minted on demand from an RS256 app JWT and cached in memory below expiry, never persisted. An uninstall or suspension disables every integration that uses the installation, and every change is audited. The single-App decision (T1) covers 07.6.1-T1 (check runs), 03.4.1/03.4.2 (catalog webhooks, healing branch/PR), 08.6.x (healing PR approval flow, via 03.4.2-T1) and 05.5.2-T3 (re-run trigger).

**Non-goals.** OIDC exchange and `ci_binding` (02.4.1); check-run delivery (07.6.1), catalog sync and PR creation (03.4.x), re-run trigger logic (05.5.2); the webhook receiver and `webhook_delivery` dedupe (03.4.1-T2) — this story only supplies its lifecycle event handler; GitHub Enterprise Server (not in V1 [OPEN]); web UI for install (09.x).

## 2. User stories and acceptance criteria

- As a tenant admin, I install the Evidgate GitHub App on my GitHub organization and see its state and permissions in Evidgate.
- As a security reviewer, I know no installation token or private key is stored in the database or logs, and an uninstall stops all GitHub-dependent features.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `POST /v1/github/installations/start` returns an install URL carrying a single-use `state` bound to `(org_id, user_id)`, TTL 10 min; callback with a missing, expired, replayed or foreign `state` returns 400 `state_invalid` and writes no row |
| AC2 | Callback `GET /v1/github/installations/callback?installation_id&state` verifies the installation via the GitHub API (⚠️ `GET /app/installations/{id}` with the app JWT) and upserts `github_installation (org_id, installation_id, account_login, account_id, permissions, state='active')`; one active installation per org; an `installation_id` already bound to another org returns 409 `installation_bound` |
| AC3 | `InstallationTokenProvider.Get(org_id, permissions, repository_ids)` mints via ⚠️ `POST /app/installations/{id}/access_tokens` requesting only the permission subset the caller feature declares; the token is held in memory only, reused until 5 min before `expires_at` (⚠️ GitHub tokens last 1 h), and a second call inside that window makes zero HTTP calls |
| AC4 | No installation token and no private key appears in any table, log line, audit row, outbox payload or exception message (log-allowlist and DB-scan tests) |
| AC5 | Webhook `installation` `deleted`, `suspend` and `unsuspend`, and `installation_repositories` `removed`, update `state` (`active → suspended → active`, `active → deleted`) idempotently by delivery id; suspended or deleted installations make `Get(...)` fail with 409 `installation_unavailable` |
| AC6 | On `suspended`/`deleted`, dependent `ci_binding`/`git_repo_binding` rows for the removed repositories are set disabled in the same transaction and one `notification` outbox event is emitted to org admins |
| AC7 | Every state change and callback writes an audit row (`github_installation.create/suspend/unsuspend/delete`, `actor_type` user or system); cross-tenant read of `github_installation` returns 0 rows under `evidgate_app` |

## 5. API shapes (commands, queries, endpoints)

| Kind | Name | Endpoint | Permission | Codes |
|---|---|---|---|---|
| Command | `StartGitHubInstall : ICommand<{url}>` | `POST /v1/github/installations/start` | `ci_binding:write` | 200 · 409 `already_installed` |
| Command | `CompleteGitHubInstall : ICommand<InstallationDto>` | `GET /v1/github/installations/callback` | session + state binding | 302/200 · 400 `state_invalid` · 409 `installation_bound` |
| Query | `GetGitHubInstallation : IQuery<InstallationDto>` | `GET /v1/github/installations` | `project:read` | 200 `{installation_id, account_login, state, permissions}` · 404 |
| Command | `DisconnectGitHubInstall : ICommand<Unit>` | `DELETE /v1/github/installations/{i}` | `ci_binding:write` | 204 · 404 (does not uninstall at GitHub; disables bindings) |
| Command | `ApplyInstallationEvent : ICommand<Unit>` | internal, from 03.4.1-T2 receiver | system (post-resolver) | idempotent no-op on replay |

Internal service `IGitHubInstallationTokens.GetAsync(orgId, feature, ct)` returns `{token, expires_at}`; callers never receive the app JWT. Mutations carry `Idempotency-Key`; list fields exclude nothing sensitive (no secrets exist in the row).

## 6. States and transitions

`active → suspended` (event `suspend`) · `suspended → active` (`unsuspend`) · `active|suspended → deleted` (event `deleted` or admin disconnect). `deleted` is terminal; reinstall creates a new row. Dependent bindings are disabled on `suspended`/`deleted` and are **not** auto-re-enabled on `unsuspend` [OPEN] (admin re-enables, avoiding silent resume). Each transition writes audit and an outbox notification.

## 7. Jobs and integrations

- GitHub API via typed `HttpClient`, RS256 app JWT (`Microsoft.IdentityModel.JsonWebTokens`), 10 min max lifetime ⚠️, no Octokit (T46); retry with jitter on 5xx/secondary rate limit ⚠️.
- Single-App permission matrix (T1 ADR) per feature, minimal: checks (07.6.1) `checks:write` ⚠️; catalog (03.4.1) `contents:read`, `metadata:read`; healing PRs (03.4.2/08.6) `contents:write`, `pull_requests:write`; re-run (05.5.2-T3) `actions:write` ⚠️. Each feature requests only its subset when minting, and a missing grant yields `installation_unavailable`-style 409 `permission_not_granted`.
- Reconcile task (Cronos, unique fire key, 00 §5.3): daily `GET /app/installations` ⚠️ compares state to stored rows to repair missed webhooks.
- Upgrade of the App's permission set triggers GitHub re-consent; the `installation` `new_permissions_accepted` event ⚠️ updates `permissions`.

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| 00 §5.7 S3 | private key in the secret store only, read at startup into memory, rotated per runbook; installation tokens in-memory cache only; redaction filter for `ghs_` and JWT patterns | AC4 tests |
| T1 / §5.4.8 | webhook path resolves tenant via `SECURITY DEFINER` resolver; `search_path = ''` (T80); webhook HMAC `X-Hub-Signature-256` verified before any parse (03.4.1-T2) | resolver audit test |
| CSRF / OAuth | `state` nonce stored hashed, single-use, bound to org and user | AC1 |
| Authorization | `ci_binding:write` for start/disconnect; callback requires the same session; app JWT never exposed | 403 + callback tests |
| Performance | token mint = 1 HTTPS call per org per ~55 min; per-org single-flight lock avoids stampede | concurrency test: 50 callers, 1 HTTP call |
| Retention/deletion | `github_installation` is tenant data deleted with the org (11.x erasure); `github_install_state` purged after expiry; audit rows follow audit retention; GitHub-side uninstall is the customer's | deletion test |
| Telemetry | metrics `github_installation_state{state}`, `github_token_mint_total{result}`, `github_webhook_event_total{event}`; alert on mint failures per org | metric asserts |

DoR answers: **authorization** — `ci_binding:write`/`project:read`, callback session-bound; **retention/deletion** — see table; **telemetry** — above; **failure path** — GitHub down: mint returns 503 `github_unavailable`, callers (07.6.1 delivery, 03.4 sync) retry via their own outbox/task; missed webhook: reconcile task repairs state.

## 11. Rollout

- Flag `github_app_enabled` per environment (default off until the App is registered and the ADR key owner is named); additive tables and endpoints. 07.6.1, 03.4.x and 05.5.2-T3 consume `IGitHubInstallationTokens` and stay dark without an active installation.
- Monitoring: `github_token_mint_total{result="error"}` alert, installation `suspended` count, reconcile drift count.
- Rollback: disable the flag; rows are tenant data and remain. Revoking the App private key at GitHub is the emergency stop (invalidates all minting); document in the key-custody runbook.
