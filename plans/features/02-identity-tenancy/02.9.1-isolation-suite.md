## 1. Goal and non-goals

**Goal.** The M1 exit gate: a permanent test suite that proves, against real PostgreSQL 18, that no API call, foreign key or RLS path lets one tenant read, write or infer another tenant's data. Two fully populated orgs with deliberately overlapping names/slugs are the fixture; the suite runs in CI on every merge.

**Non-goals.** Load/performance testing (10); penetration testing beyond these seams (11.7.1 builds on this suite); the tables' functional correctness (each module's own tests).

## 2. User stories and acceptance criteria

- As the Tech Lead, I can point to one CI job as proof that tenant isolation held for this merge.
- As a developer adding a table or endpoint, the suite extends mechanically: register the table/endpoint, get the cross-tenant assertions free.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | For every `/v1` GET endpoint taking an object id, a request authenticated to org B using an org-A id returns 404 (never 403-with-leak, never the row); the suite enumerates endpoints from `contracts/openapi.yaml` so a new endpoint without coverage fails |
| AC2 | For every mutation endpoint, an org-B token on org-A `{o}`/`{p}` routes → 403 `project_scope_mismatch` or 404; list endpoints return only own-org items and `next_cursor` never crosses orgs (page through the full list) |
| AC3 | For every tenant table (auto-discovered from `information_schema` minus the §4.5 exception list), a direct insert with a foreign `org_id` referencing a composite FK target is rejected; and `SELECT` as `evidgate_app` with the GUC unset returns 0 rows while the same query with it set returns exactly that org's rows |
| AC4 | `relforcerowsecurity` is true on every business table; `rolbypassrls` is false for `evidgate_app` and `evidgate_operator`; both asserted from `pg_class`/`pg_roles` per table/role |
| AC5 | Platform-scope tables behave as designed and nothing more: `user`/`user_identity`/`session` are unreachable via tenant APIs; catalogue rows (`permission`, built-in `role`/`role_permission`, built-in `template`) are readable by every org but not writable by `evidgate_app` |
| AC6 | The suite runs as `evidgate_app` (never owner — §7) inside CI on `Testcontainers.PostgreSQL`; the M1 gate is a required check and a failure names the violating table/endpoint |

## 4. Data model and migrations

None (test-only story). Fixtures: two orgs `acme`/`acme-2` with colliding slugs on projects/memberships; 3 users × 5 role combinations; one `ci_binding` with test JWKS; one active + one revoked ingest token; one expired support grant; one session per user — the 02 §7 fixture set, built as a reusable `IsolationFixture` (xUnit collection fixture over Testcontainers.PostgreSQL 18, Respawn between test classes).

## 5. API shapes (commands, queries, endpoints)

None. The suite consumes the public API surface:

| Suite | Mechanism |
|---|---|
| `ApiIsolationTests` | `WebApplicationFactory`-style host + real DB; HTTP calls with org-A/org-B sessions and `ci_producer` tokens; endpoint inventory parsed from `contracts/openapi.yaml` |
| `CompositeFkTests` | parameterized per discovered tenant table; attempts `INSERT` with foreign `org_id` through the app connection |
| `RlsIsolationTests` | direct `NpgsqlConnection` as `evidgate_app` (`SET ROLE`), toggling `set_config('evidgate.org_id', …)` per case |

## 7. Jobs and integrations

- CI wiring: the suite is a distinct xUnit collection (slower, DB-heavy) invoked by the 01.7.1 pipeline; **required** for the M1 milestone gate (00 §4) and for every merge thereafter.
- Extensibility contract for later modules: a table registers itself in `IsolationFixture` via `information_schema` auto-discovery (no manual list to forget); an endpoint is covered automatically by the OpenAPI enumeration — a module only adds path-parameter producers for its ids.

## 9. Test plan

The suite **is** the test plan; the named cases:

| Behaviour / boundary / failure | Test |
|---|---|
| Other-tenant id → 404 | `ApiIsolationTests.GetById_ForeignOrg_404` (per GET endpoint) |
| Scope mismatch → 403 | `ApiIsolationTests.TokenScope_OtherProject_403` |
| List never leaks | `ApiIsolationTests.List_OnlyOwnOrg_FullPagination` (incl. counts: page every org-B list to exhaustion under org-A data present) |
| Cross-org FK | `CompositeFkTests.Insert_ForeignOrgId_Rejected` (per table) |
| Unset GUC → 0 rows; set → exact | `RlsIsolationTests.Guc_Unset_ZeroRows`, `…_Set_OwnRowsOnly` (per table) |
| FORCE RLS + role flags | `RlsIsolationTests.ForcedRls_And_NoBypassRls` |
| Catalogue semantics | `CatalogueTests.ReadableByEveryOrg_NotWritableByApp` |
| `organization` scope | `OrganizationTests.OnlyCurrentOrgVisible` |
| Platform tables unreachable | `PlatformScopeTests.SessionUserIdentity_NotReachableViaV1` |
| Resolver surface | `ResolverTests.AppRole_ExecuteOnly_NoDirectReads` |
| Endpoint coverage drift | `CoverageTests.EveryOpenApiRoute_HasIsolationCase` (fails listing uncovered routes) |

## 11. Rollout

- Lands in M1 as the milestone's exit gate (00 §4): M1 does not close while any case is red or any endpoint/table is uncovered.
- Monitoring: CI failure message names the offending table/endpoint; runtime budget watched to keep the gate fast (≤ 10 min ⚠️ measure).
- Rollback: n/a — test-only; a red suite means a product bug, never a reason to disable the gate.
