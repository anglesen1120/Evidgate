## 1. Goal and non-goals

**Goal.** A human reaches an authenticated session through authorization-code + PKCE only: Google Workspace via OIDC (ID token verified against issuer JWKS, `email_verified` honoured) and GitHub via OAuth2 (no ID token — subject = numeric user id from `GET /user`, email = verified entries of `GET /user/emails`; T6). Identity is bound to `(provider, subject)`; a pending invite binds on verified-email match (02.1.2-T2); an optional per-org `allowed_email_domains` allowlist restricts Google logins. No password credential exists anywhere.

**Non-goals.** Cookie/antiforgery mechanics, session expiry/rotation internals and session-list endpoints (02.3.2 — this story creates the `session` row but owns the login protocol, not the session lifecycle); SAML (02.3.3, V3); invites (02.1.2); login UI pages (09.1.1); MFA/step-up (11 hook only). The own-profile read and the locale preference write (`GET`/`PATCH /v1/me`, T3) are in scope.

## 2. User stories and acceptance criteria

- As a user, I click "Sign in with GitHub/Google" and land in my org with a session; I never type a password into Evidgate.
- As a `tenant_admin`, only my org's email-domain allowlist can join via Google.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | Full happy paths pass against mocked providers: Google OIDC (JWKS-verified ID token) and GitHub OAuth2 (code exchange → `GET /user` id → `GET /user/emails` verified) both end with a `session` row and a `__Host-` cookie set |
| AC2 | A forged/tampered ID token (bad signature, wrong `iss`, wrong `aud`, expired, `nbf` future beyond 60 s skew, unknown `kid`) → 401 `token_invalid`; JWKS refetches once on unknown `kid` (single-flight) then still fails closed |
| AC3 | A user with no membership and no pending invite completes provider login → 403 `no_membership`, no session cookie issued |
| AC4 | Pending invite binds iff provider-verified email equals `invited_email` (02.1.2 AC2); GitHub `GET /user/emails` verified entries only — a primary-but-unverified email never binds |
| AC5 | `allowed_email_domains` non-empty on the org → Google login with an off-list verified domain gets `no_membership` (invite may still exist; domain gate applies at bind) |
| AC6 | Same email at both providers creates two `user_identity` rows; they merge onto one `user` only after explicit confirm (09 flow) — never auto-merged (D3) |
| AC7 | `contracts/openapi.yaml` contains no password field/path (grep-able contract test); no password column on any table |
| AC8 | Provider outage/timeout → 503 `Retry-After`; existing sessions unaffected (02 §5) |
| AC9 | `GET /v1/me` returns the session user's `id`, `email`, `display_name`, `preferred_locale` (`null` until set) with `ETag` = `user.version`; `PATCH /v1/me {preferred_locale}` accepts only `vi`/`en` (else 422 `locale_invalid`), needs `If-Match` (stale → 412) and `X-XSRF-TOKEN`, rejects any other field with 422 `field_not_patchable`; no session → 401; a user can never read or change another user's profile (no id in the route) |

## 4. Data model and migrations

`migrations/NNNN_identity_user.sql` (platform-scoped exception tables, D12 — no `org_id`, no org RLS; access via membership):

- `user`: `id uuid pk`, `email citext` (plain index on `lower(email)` — non-unique, D3/T6), `display_name`, `status text` (`active|disabled`), `last_login_at`, `created_at`, `updated_at`.
- `user_identity`: `id uuid pk`, `user_id` → `user(id)`, `provider text` (`github|google`; `saml` added by 02.3.3), `subject text`, `email_at_provider citext`, `linked_at`; `unique (provider, subject)`.
- `session`: `id uuid pk`, `user_id`, `created_at`, `last_seen_at`, `expires_at`, `absolute_expires_at`, `ip inet`, `user_agent`, `revoked_at`, `rotated_from` — created here so login can insert; 02.3.2-T1 owns semantics.
- T1.4, `migrations/0042_identity_login_resolvers.sql`: `session.cookie_hmac bytea not null` (32 bytes) and `session.pepper_version integer not null`, the `session_cookie_hmac_key` unique index the cookie lookup uses, and the two `SECURITY DEFINER` writers `evidgate_resolve.login_upsert_identity` / `session_create` (audit-deferred, [DECISION D-S75-Q4]).
- T3, `migrations/NNNN_identity_user_profile.sql` (expand-only): `user.preferred_locale text null check (preferred_locale in ('vi','en'))` and `user.version int not null default 1` with the `set_updated_at_and_version` trigger (00 §7, 0004 precedent).

## 5. API shapes (commands, queries, endpoints)

Cookie-flow routes (not in 00 §9.3 core list; defined in 02 §4.2 + `contracts/openapi.yaml`):

| Route | Handler | Notes |
|---|---|---|
| `GET /v1/auth/oidc/{provider}/start` | ASP.NET Core OIDC/OAuth handler | creates `state`, `nonce`, PKCE verifier in a short-lived `SameSite=Lax` cookie; `provider ∈ {github, google}`; post-login `returnUrl` allowlist (app-origin paths only) |
| `GET /v1/auth/oidc/{provider}/callback` | auth handler + `CompleteLoginCommand` | verify → upsert `user`/`user_identity` → `member_orgs` → `BindPendingMemberships` (not built: 02.3.1-T2, [DECISION D-S75-Q3]) → membership check → `session` insert → `__Host-` cookie → redirect; landed parts and their order in the T1.4 Notes |
| `POST /v1/auth/logout` | `LogoutCommand` | revokes current session (mechanics in 02.3.2) |
| `GET /v1/me`, `PATCH /v1/me` | `GetMyProfileQuery`, `UpdateMyProfileCommand` | user id from the session principal only; PATCH = `preferred_locale` only, `If-Match`, audited as `user.locale_changed` |

`CompleteLoginCommand` (`ICommand<LoginResult>`): the only writer of `user`/`user_identity`; idempotent by `(provider, subject)` upsert (no `Idempotency-Key` needed — replay-safe by natural key + `state` one-time use). Queries: none public; `member_orgs` is a resolver call (T1), not a Dapper query over `membership`.

## 6. States and transitions

`user.status`: `active → disabled` (admin/operator path, later stories); login by a `disabled` user → 403 `account_disabled`. `user_identity` has no states (linked once, `linked_at`); unlinking is out of V1 scope. Session states are 02.3.2's (`active → revoked|expired`, 00 §8.9).

## 7. Jobs and integrations

- Outbound calls: GitHub `POST /login/oauth/access_token`, `GET /user`, `GET /user/emails`; Google token + JWKS endpoints — all via `IHttpClientFactory` typed clients with timeouts + resilience handlers (P6), allow-listed hosts (S4), **never inside the DB transaction** (P5): the callback does provider calls first, then opens the tenant tx for the upsert/session insert.
- JWKS cache with TTL + single-flight refresh (02 §5).
- Consumes: `evidgate_resolve.member_orgs` (02.6.1-T3), `BindPendingMemberships` (02.1.2-T2), `ISessions.Create` contract (02.3.2-T1 — for task-order purposes the contract lands with the `session` table here; the implementation detail stays 02.3.2's).

**DoR review answers** (00 §12, `plans/features/README.md` §6):

- **Authorization:** login routes are pre-tenant and need no permission; the callback admits a user only with an active membership or a bound invite (AC3) resolved through `evidgate_resolve.member_orgs`. `GET`/`PATCH /v1/me` (T3) take the user id from the session principal only — no id in the route, so no other user's profile is reachable; PATCH needs `X-XSRF-TOKEN`.
- **Retention/deletion:** `user`, `user_identity` and `session` rows follow 11's retention rules; `preferred_locale` is one more column on `user` and is erased with it; `disabled` users keep identities for audit.
- **Telemetry:** login success/failure counters by provider and failure `code`, JWKS refresh counter, 503 rate on provider outage; no email, token or subject in any log or metric attribute.
- **Failure path:** bad or expired tokens → 401 `token_invalid`, no membership → 403 `no_membership` with no cookie, provider outage → 503 `Retry-After` with existing sessions untouched; a profile PATCH with a stale `If-Match` → 412, an invalid locale or field → 422 and nothing is written.

- **Result semantics.** An empty `Bound` is "stay pending, nothing bound" and is **not** an error — the login turns it into the existing 403 `no_membership`. `EmailVerified == false` or an empty email queries nothing at all. A failure is 429 `quota_exceeded` (limit name `max_seats`) when the org has no free seat; that org then binds nothing, while other orgs of the same call may already have bound (each org is its own transaction), so the login must not treat a 429 as "retry the whole call" without accepting partial success.
- **The invite-token transport is this task's decision.** The binder only parses the value (`InviteTokenFormat.TryParse`: `evgi_<12-char prefix>_<base64url 256-bit secret>`, max 80 chars); where the login reads it from — a link fragment the web client forwards, a query parameter, or a short-lived cookie set by the landing route — is open here. Whatever the transport, the token may not reach the session row, a log line, the `returnUrl` or an error message.
- **`hd` must be captured** from the Google ID token (an absent claim stays null). Today no login file reads it, so AC8's verified-domain path is callable but unreachable; the binder requires `Provider == "google"`, a non-empty `HostedDomain` equal to the verified email's domain (ordinal-ignore-case) and the org's `invite_autobind_verified_domain` opt-in, which itself has no write API yet (STATUS §6).
