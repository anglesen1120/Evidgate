## 1. Goal and non-goals

**Goal.** Close review S3: today rate limits exist per project on ingest and on `/v1/ci/token` only. Add a layered in-application edge that runs with no WAF: Kestrel request-body, header and timeout limits (slowloris, oversized bodies cut before routing); per-IP limits on unauthenticated routes (login callback, `POST /v1/ci/token` failures, `POST /v1/webhooks/github`, invite activation, viewer token); per-org limits on read endpoints and on presign issuance (`POST /v1/artifacts/upload-url`); every refusal is a typed 429/413/431/408/503 with `Retry-After` where applicable. An abuse test runs in CI at M2. Whether a managed WAF/CDN sits in front is recorded as dependent on O3, with the list of what runs without it.

**Non-goals.** Per-project ingest quota and its counters (04.1.2-T1); billing quotas and plan tiers (12); volumetric DDoS absorption (provider/CDN, `[OPEN]` on O3); soak and back-pressure at load (10.6.1-T4, M4); authentication logic (02); bot detection or CAPTCHA.

## 2. User stories and acceptance criteria

- As the operator, an anonymous flood cannot exhaust the API or the database.
- As a tenant, another tenant's heavy reading or presign loop does not starve my requests.
- As the owner, I know exactly what protection exists without a WAF.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | A body above the route's limit is refused 413 `payload_too_large` before it is fully read; default JSON routes ≤ 1 MiB, ingest batches per 00 §9.3, no route without an explicit limit |
| AC2 | A request with headers above the Kestrel limit gets 431; a client that sends the body slower than the minimum data rate or exceeds header/request timeouts is disconnected (408 or connection close); other requests stay served |
| AC3 | More than N failing `POST /v1/ci/token` calls from one IP in the window return 429 `rate_limited` with `Retry-After`; valid calls from other IPs are unaffected; the limiter keys on the proxy-validated client IP (forwarded headers only from the configured trusted proxy) |
| AC4 | The same per-IP limiter covers the other unauthenticated routes (GitHub webhook, invite activation, viewer token, health/metrics excluded) with route-specific budgets in config |
| AC5 | Per-org read limit: one org exceeding its read budget gets 429 `rate_limited` + `Retry-After` while a second org's reads succeed at the same moment |
| AC6 | Presign flood: more than the per-org (and per-project slot) issuance budget per minute returns 429; unissued URLs never create `pending_upload` rows beyond the budget |
| AC7 | Every 429 carries `Retry-After` (integer seconds), the §9.2 envelope, `X-Request-Id`; no response leaks the limit key (IP, org id) in the body |
| AC8 | Limit state is bounded: the partitioned limiter evicts idle keys and memory stays under a documented cap under a 100 000-distinct-IP spray |
| AC9 | The decision record names the WAF/edge stance (dependent on O3), what runs without it (AC1–AC8) and what it does not cover (volumetric attacks, TLS termination limits); owner reads it as `[OPEN]` O3 |

## 4. Data model and migrations

None. Limiters are in-process (single API instance in V1, `[INFERENCE]`). `[OPEN]` for scale-out: with more than one API instance, per-IP/per-org counters are per instance (effective budget is N× the setting) unless a shared store is added; V1 documents the multiplier and does not add a shared counter. ## 5. API shapes (commands, queries, endpoints)

| Kind | Name | Endpoint | Permission | Codes |
|---|---|---|---|---|
| Middleware | `IngressLimits` (Kestrel config + `UseRateLimiter` policies) | all routes | n/a | 408 · 413 · 429 · 431 · 503 with `Retry-After` |
| Policy | `unauth-ip` | `/v1/ci/token`, webhook, invite, viewer token, login callback | none | 429 |

| Policy | `org-presign` | `POST /v1/artifacts/upload-url` | `artifact:write` | 429 |
| Config | `Limits__*` | `infra/config-matrix.json` | operator | — |

No new routes. The org policy key is resolved after authentication (org from the token); the per-IP policy runs before authentication.

## 6. States and transitions

None persisted. A limiter partition is `open → throttled → open` by window; throttled requests do no work (no DB call, no tenant scope opened, no audit row; counters only). Retries by well-behaved clients follow `Retry-After` (00 §9.2).

## 7. Jobs and integrations

- Kestrel: `MaxRequestBodySize` global default plus per-endpoint overrides, `MaxRequestHeadersTotalSize`, `MaxRequestHeaderCount`, `RequestHeadersTimeout`, `KeepAliveTimeout`, `MinRequestBodyDataRate`, `MinResponseDataRate`. ⚠️ Property names and defaults from ASP.NET Core docs, to be verified and cited in T1.1.
- `Microsoft.AspNetCore.RateLimiting` partitioned limiters (sliding or token-bucket), `OnRejected` writes the §9.2 envelope and `Retry-After`. ⚠️ API shape verified in T1.1.
- Forwarded headers: honoured only from `KnownProxies`/`KnownNetworks` in config; in compose the dev proxy is trusted, otherwise the socket address is used (never trust `X-Forwarded-For` blindly).
- Metrics: `ingress_rejected_total{policy,status}`, `ingress_limit_keys` gauge; alert in 10.3.1-T5 on a sustained rejection rate for `unauth-ip` (owner and runbook link required).
- WAF/edge (T3): `[OPEN]` O3. Without a provider, compose and any single-host staging run with the in-app limits only, with TLS and a reverse proxy (`[INFERENCE]` Caddy/nginx) config optionally adding connection limits; a managed WAF, bot rules and volumetric protection are listed as provider-dependent.

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| Fail fast, cheap | rejection before auth lookups for per-IP policy; no DB work when throttled | AC3, benchmark in T2.3 |
| Tenant fairness | partition by org after auth | AC5 |
| No information leak | generic bodies, no limit key in the response | AC7 |
| IP privacy | client IPs held in memory only as limiter keys, hashed in metric labels never; not written to logs by default (GDPR/PDPL-minimal; ⚠️ IP as personal data under PDPL to be confirmed by 11) | log-allowlist test |
| Memory bound | idle partition eviction | AC8 |
| Availability | health/metrics endpoints are outside the limiter so probes still work | test `HealthEndpoints_NotThrottled` |

DoR review answers:

- **Authorization:** the limits apply before and independently of permissions; no new permission.
- **Retention/deletion impact:** nothing persisted; no IP stored.
- **Telemetry:** as §7; trace attribute `limit.policy`.
- **Failure path:** a mis-set limit that blocks legitimate CI is visible as `ingress_rejected_total` spike and fixed by config without a deploy (config reload `[INFERENCE]`, else a redeploy); the limiter errors fail open for per-org read policy and fail closed for `unauth-ip` (documented).
