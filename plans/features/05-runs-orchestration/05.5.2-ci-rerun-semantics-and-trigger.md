## 1. Goal and non-goals

Customer CI initiates a rerun and declares its run identifier, attempt and selected shards. Evidgate links attempts without initiating jobs or treating those labels as proof of identity.

## 2. User stories and acceptance criteria

A higher attempt creates a child without mutating its parent. Repeated creation is idempotent. Only the authenticated slot owner may write or finalize; a matching declared identifier does not confer authorization. A partial attempt never becomes full-regression evidence.

| ID | Observable result |
|---|---|
| AC1 | Higher producer-declared attempt creates a child with `rerun_scope = ci_attempt`. |
| AC2 | Only the authenticated producer may write to its attempt’s slot. |
| AC3 | Partial re-run: attempt 2 with only shard `shard-1` executing creates a run labelled as a subset (`ci_attempt` + `shard_selection`); it is never accepted as full-regression evidence (00 §8.1) |
| AC4 | A credential from another producer cannot write to this slot; late writes do not reopen completed runs. |
| AC5 | Replaying the same creation is idempotent; a stale attempt is refused. |
| AC8 | After `POST /v1/runs/{r}/cancel`, the CLI observes `canceled` within one poll interval (default 10 s ± 20 % jitter) and stops its shard; a poll failure never cancels locally by itself |
| AC9 | A shard running longer than `shard_max_duration` (stored in the manifest) is stopped by the CLI and reported as a producer event with reason `shard_timeout`; the run's `missing[]` names that shard before the collection deadline |

## 3. Contracts touched

Run creation accepts declared attempt metadata; the customer initiates the job. T4 polls the normal run-read endpoint for cancellation. There is no provider dispatch contract.

## 4. Data model and migrations

Keep parent run id, declared CI identifiers/attempt and selected shards scoped to the project. An earlier attempt’s evidence is immutable; declared metadata does not supply an authenticated slot owner.

## 5. API shapes (commands, queries, endpoints)

Use authenticated run create, slot write, finalize, and cancel/read. There is no API that starts a customer CI workflow.

## 6. States and transitions

A new attempt is a new child run. Canceled/terminal parents stay terminal. Partial or timed-out attempts explicitly list missing shards.

## 7. Jobs and integrations

Only the customer scheduler starts work. The CLI polls for cancellation with backoff and enforces the manifest’s shard timeout.

## 8. Security, privacy and performance

- **Authorization:** Project token and authenticated slot owner authorize each write; a declared attempt is not a credential.
- **Retention/deletion:** Attempts and selections follow run retention; no external job credential or dispatch log.
- **Telemetry:** Count cancellations, timeouts and missing shards without raw CI identifiers.
- **Failure path:** Refuse stale attempts; polling errors do not cancel locally. Partial evidence never yields PASS.

## 9. Test plan

Cover AC1–AC5, AC8 and AC9: child creation, ownership and idempotency; partial reruns, late writes, cancellation and timeouts. No dispatch fixture.
