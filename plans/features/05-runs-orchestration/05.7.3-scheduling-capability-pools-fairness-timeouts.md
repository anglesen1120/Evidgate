## 1. Goal and non-goals

**Goal.** Jobs are claimed only by pools whose capability document satisfies the job's `capability_requirement` (protocol major, platform, engine family + exact version, `supports.cancel`); a fair scheduler serves queued jobs — weighted round-robin across tenants, oldest-first inside a tenant — under per-pool and per-tenant concurrency caps; queue timeout and execution timeout are distinct outcomes; a job no pool can satisfy becomes `unschedulable` with the unmet requirement; and suites declaring `environment_requirements.data_isolation = shared` serialise on an epoch-fenced `environment_lock`, while CI-mode runs record "lock not enforced".

**Non-goals.** Lease mechanics and heartbeat (05.7.2); JobSpec (05.7.1); the agent binary and its registration tokens (05.7.4, 02.5.1); Android device pools (05.8.1); the queue-timeout **sweep** task (05.10.1 — this story ships the fields, the `MarkJobQueueTimeout`/`ExpireEnvironmentLock` domain methods the sweeper calls, and the claim-time lazy path).

## 2. User stories and acceptance criteria

- As a tenant admin, my jobs run on pools that can actually execute them, so a missing engine version fails fast instead of queueing forever.
- As the platform operator, shared capacity rotates fairly across tenants, so one busy tenant cannot starve the others.
- As a QA engineer whose suite shares mutable data, my job holds the environment exclusively, so two runs never corrupt each other's data.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `POST /v1/orgs/{o}/agent-pools` + `GET` manage pools (`pool_key`, `capacity_group`, `concurrency_cap`, `capability`); a capability document failing the 04.7.1-T2 schema → 422 `capability_invalid`; duplicate `pool_key` → 409 |
| AC2 | `ICapabilityMatcher.Satisfies(requirement, capability)` is pure and total: rejects wrong `protocol.major`, missing `platforms[]` entry, wrong `engine.family`, mismatched exact `engine.version`, `supports.cancel=false` when required; unit-matrix test covers each clause |
| AC3 | Claim offers only matching jobs: a queued job requiring Playwright `1.4x` is never leased to a pool declaring another version; the unsatisfiable job is set `unschedulable` with `unmet_requirement` recorded (at enqueue or first claim scan) |
| AC4 | Fairness: with capacity shared across two tenants and equal weight, 20 claims interleave ≤ ±1 per tenant per group window; `oldest-first` inside a tenant; per-pool `concurrency_cap` and per-tenant-per-group cap are never exceeded (active-lease count in the claim SQL) |
| AC5 | Timeouts are distinct: `queue_timeout_at` expiry sets `job.outcome = queue_timeout` and releases scheduling (terminal for the attempt, `attempt_count` preserved); `execution_timeout_at` bounds the lease — heartbeats never extend past it, expiry re-queues under a new epoch (05.7.2 path) |

## 3. Contracts touched

- `contracts/openapi.yaml`: new operations `POST/GET /v1/orgs/{o}/agent-pools` (`x-permission: agent_pool:write` / `agent_pool:read` — **new permissions, contract addition flagged here**) and `GET /v1/jobs/{j}` (`run:read`); claim request already exists (05.7.2). Error codes `capability_invalid`, `unschedulable`, `env_lock_timeout`.
- `Evidgate.Modules.Orchestration.Contracts`: `ICapabilityMatcher`, `IEnvironmentLockWriter`, `IJobScheduler` (enqueue + matching), `PoolCapability` DTOs — consumed by 05.7.4, 05.8.1, 02.5.1, 03.6.1.
- `run` table gains `environment_lock_required`/`lock_enforced` (read via existing `GET /v1/runs/{r}`).
- **Design note — cross-tenant fairness vs RLS:** fairness across tenants is only implementable because `capacity_group` caps and rotation state live on the `agent_pool` rows of the claiming tenant — cross-tenant shared pools would need an RLS exception (00 §5.4.8 does not cover scheduler reads). Design adopted: capacity groups are tenant-level (`org_id` always set); "across tenants" fairness is realised per group by the platform creating a pool row per tenant in the same `capacity_group` and the scheduler rotating group service order — cross-tenant counts are never read inside a tenant transaction; the platform's hosted-pool control plane (group caps) is a future `/internal` concern. If true multi-tenant pools are required, a T1-style resolver CR is needed — flagged, not invented.
- No change to 00 §8.2; `job.outcome` (new column) refines terminal detail without adding states.

## 4. Data model and migrations

`migrations/NNNN_orchestration_agent_pool.sql` (T1):

- `agent_pool` (`id`, `org_id`, `project_id null`, `pool_key`, `capacity_group`, `concurrency_cap int`, `capability` jsonb (validated), `state ('active','disabled')`, `version`): `unique (org_id, id)` (T3), `unique (org_id, capacity_group, pool_key)`; index `(org_id, capacity_group)`; RLS helpers (T2).
- `capacity_group_window` (`org_id`, `capacity_group`, `tenant_seq bigint`, `last_served_seq bigint`, `served_count int`) — fairness bookkeeping per tenant+group; `unique (org_id, capacity_group)`; updated inside the claim transaction (one upsert).

`migrations/NNNN_orchestration_job_outcome_envlock.sql` (T3/T4):

- `job` additions: `outcome text null` (`queue_timeout|lease_lost|canceled|completed`), `unmet_requirement text null`; index `(org_id, state, pool) WHERE state='queued'` already from 05.7.2.
- `environment_lock` (`id`, `org_id`, `environment_id`, `job_id`, `epoch`, `acquired_at`, `expires_at`, `state ('held','released','expired')`): `unique (org_id, id)` (T3); unique partial `(org_id, environment_id) WHERE state='held'` — one holder per environment; composite FKs `(org_id, environment_id)`, `(org_id, job_id)` (T3).
- `run` additions: `environment_lock_required bool not null default false`, `lock_enforced bool null`.

## 6. States and transitions

`job` follows 00 §8.2 unchanged; `outcome` records *why* a terminal/loss transition happened (`queue_timeout`, `lease_lost`, `canceled`, `completed`). `unschedulable` terminal at enqueue or first matching scan. `environment_lock`: `held → released | expired` (terminal; a job may hold successive locks only as new epochs). `agent_pool.state`: `active → disabled` (disable is audited; in-flight leases unaffected).

## 7. Jobs and integrations

- Outbox task `orchestration.dispatch_jobs` (natural key `(run_id)`) performs agent-mode enqueue (05 §4 agent-mode `queued` transition) — idempotent.
- `IQuotaGate` (12.3.1 contract) not used here: pool caps are scheduler state on `job_lease`/`capacity_group_window`, not metering.
- The 05.10.1 sweeps call `MarkJobQueueTimeout` (queue deadline) and `ExpireEnvironmentLock` (dead lock holder); both are no-ops when already resolved (lazy path shares the same methods).
- 05.8.1 device pools reuse `ICapabilityMatcher` + caps with a device requirement dimension; 03.6.1 (draft dry runs) and 02.5.1 (agent registration) consume the pool contracts; 09.7.1 reads `GetJobQuery`/`unschedulable` for the operator UI.
