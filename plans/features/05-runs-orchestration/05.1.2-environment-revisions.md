Recorded deviations: (1) the body has its own contract schema (64 KiB cap) and the error code for its violations is `environment_revision_invalid`; (2) `revision_hash` covers `{base_urls, dependency_versions, secret_refs}` with the references sorted and deduplicated — the display name is not configuration; (3) identical content answers 200 with the stored revision and makes it current again (a revert is a pointer move, not a new row); (4) AC5's "re-posting the same `revision_no` → 409" is an optional `revision_no` in the body checked against the next number (409 `revision_conflict`), before the identical-content answer; numbering itself is serialised by locking the environment row (`lock_timeout` 5 s → 503); (5) `environment.current_revision_id` has no FK (it would close a cycle); a trigger keeps it on one of the environment's own revisions and keeps id/org/project/key immutable; (6) `environment_revision` also carries `project_id` with a composite FK, and `created_by` is the audit actor text; (7) the create route takes `{e}` as the environment key (`^[a-z0-9][a-z0-9_-]{0,63}$`) and creates the environment on its first revision; `GET` answers 304 to a matching `If-None-Match` and is `Cache-Control: private, immutable`; (8) the create is 6 statements (`lock_timeout`, environment upsert, lock, slot read, insert, pointer move), not ≤ 4: the slot read merges dedupe and numbering, and the pointer move is skipped when nothing changes; (9) the route reads the raw body (401 first without a caller) and the handler parses and validates it after the permission check (§8a).

## 1. Goal and non-goals

**Goal.** A project environment is versioned into immutable `environment_revision` rows holding only secret-free configuration — base URLs and the dependency versions that affect results — plus secret *references* (never values), each carrying a stable `revision_hash` (`sha256:` over RFC 8785). A run locks exactly one revision; a revision referenced by a run or manifest can never be edited — a new revision is appended instead (FR-05-14).

**Non-goals.** The V2 environment lock for `data_isolation = shared` suites (05.7.3-T4 — this story deliberately carries no local isolation flag; the lock reads the suite revision's declaration, 03 §4); secret *value* storage or resolution (02/secret store); run-side locking of the revision (05.2.1-T1).

## 2. User stories and acceptance criteria

- As a tenant admin, I append an environment revision when a base URL or a dependency version changes, so evidence is always attributable to an exact environment.
- As the platform, I refuse to store secrets in a revision and refuse to mutate a referenced revision, so replayed evidence cannot be reinterpreted.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `POST /v1/projects/{p}/environments/{e}/revisions` with valid config → `201 {revision_id, revision_no, revision_hash}`; `revision_no` increments monotonically per environment |
| AC2 | `revision_hash` is `sha256:<hex>` over the RFC 8785 canonical document and stable across field orderings (golden vectors) |
| AC3 | A payload containing a secret *value* (any non-`secret:`-schemed entry in `secret_refs`, or a value matching the secret-pattern list in `base_urls`/`dependency_versions`) → `422 environment_revision_invalid`, reason `secret_value_detected`, value never echoed |
| AC4 | `GET /v1/environment-revisions/{id}` → `200` with `ETag: "<revision_hash>"`, permission `run:read`; other-tenant id → `404` |
| AC5 | A revision is immutable: no update route exists; `UPDATE`/`DELETE` as the app role is revoked; re-posting the same `revision_no` → `409` |
| AC6 | `project.default_environment_id` carries the composite FK `(org_id, default_environment_id) → environment (org_id, id)`; naming an unknown environment/revision at run create (05.2.1) → `422` |
| AC7 | Only `environment:write` may create revisions; `run:read` (any member with it) may read (`403` otherwise) |

## 4. Data model and migrations

`migrations/NNNN_orchestration_environment.sql` (DbUp, owner role):

```sql
create table environment (
  id uuid primary key,
  org_id uuid not null,
  project_id uuid not null,
  environment_key text not null,
  name text not null,
  current_revision_id uuid,
  created_at timestamptz not null default now(),
  unique (org_id, id),                                   -- T3
  unique (org_id, project_id, environment_key)
);

create table environment_revision (
  id uuid primary key,
  org_id uuid not null,
  project_id uuid not null,
  environment_id uuid not null,
  revision_no int not null,
  base_urls jsonb not null,
  dependency_versions jsonb not null,
  secret_refs text[] not null default '{}',              -- 'secret:' references only, never values
  revision_hash text not null check (revision_hash like 'sha256:%'),
  created_by uuid not null,
  created_at timestamptz not null default now(),
  unique (org_id, id),                                   -- T3: target of environment's FK
  unique (org_id, environment_id, revision_no),
  unique (org_id, environment_id, revision_hash),        -- dedupe identical config
  foreign key (org_id, environment_id)
    references environment (org_id, id)
);
alter table environment
  add constraint environment_current_rev_fk
  foreign key (org_id, current_revision_id)
  references environment_revision (org_id, id);

alter table project add column default_environment_id uuid;
alter table project add constraint project_default_env_fk
  foreign key (org_id, default_environment_id)
  references environment (org_id, id);

alter table manifest add constraint manifest_env_rev_fk
  foreign key (org_id, environment_revision_id)
  references environment_revision (org_id, id);

alter table environment enable row level security;
alter table environment force row level security;
alter table environment_revision enable row level security;
alter table environment_revision force row level security;
create policy environment_tenant on environment
  using (org_id = evidgate.current_org_id())
  with check (org_id = evidgate.current_org_id());
create policy environment_revision_tenant on environment_revision
  using (org_id = evidgate.current_org_id())
  with check (org_id = evidgate.current_org_id());
revoke update, delete on environment_revision from evidgate_app;  -- C6
```

Read query `GET /v1/environment-revisions/{id}` is by PK — no extra index. `environment.current_revision_id` update is allowed (pointer, not content) but revision rows themselves are append-only.

## 5. API shapes (commands, queries, endpoints)

| Kind | Name | Endpoint | Permission | Notes |
|---|---|---|---|---|
| Command | `CreateEnvironmentRevisionCommand : ICommand<EnvironmentRevisionResult>` | `POST /v1/projects/{p}/environments/{e}/revisions` | `environment:write` | Upserts the `environment` row (by `environment_key`/`{e}`), computes `revision_hash`, inserts revision with next `revision_no`, updates `current_revision_id` — one transaction. 201 `{revision_id, revision_no, revision_hash}`. Canonically identical re-post → `200` with the existing revision (dedupe unique). `revision_no` replay → `409` |
| Query | `GetEnvironmentRevisionQuery : IQuery<EnvironmentRevisionDto>` | `GET /v1/environment-revisions/{id}` | `run:read` | Dapper, read-only tx; `ETag: "<revision_hash>"`; cross-tenant → `404` |

Errors: `environment_revision_invalid` (422), `forbidden` (403), `not_found` (404), `idempotency_conflict` (409 on `Idempotency-Key` replay with different payload, §9.1). `Idempotency-Key` required on the POST (creates a resource, §9.1).

## 6. States and transitions

None beyond append-only growth: `environment_revision` has no lifecycle states — immutable on insert (like `fixture_revision`, §8.10). `environment.current_revision_id` is a mutable pointer, not a state machine.

## 7. Jobs and integrations

- Consumed by 05.2.1-T1: run create locks exactly one `environment_revision` (by manifest or by `project.default_environment_id`) and stores the composite FK on `run`.
- Consumed by 05.7.3-T4 (V2): the environment lock resolves its environment through these rows; the `data_isolation = shared` flag stays on the suite revision (03 §4), never here.
- `Evidgate.Canonicalization` for `revision_hash` (same vectors as 05.1.1-T3).

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| §5.4 1–3, T2, T3 | `org_id` + `unique (org_id, id)` + composite FKs on both tables; `FORCE RLS` with helper-based policies | `EnvironmentRevision_CrossTenant_404`; 02.6.1-T2 lint |
| §5.5 C2/S2 | `environment:write` on the command, `run:read` on the query; authz only in the pipeline | `CreateRevision_NoWritePermission_403`, `GetRevision_NoReadPermission_403` |
| §5.5 C6 | revision immutable: no setters, `REVOKE UPDATE, DELETE`, no update route | `EnvironmentRevision_UpdateDelete_Revoked` |
| S3 secrets | `secret_refs` schema- and check-validated to `secret:` references only; rejection never echoes the value | AC3 |
| §5.7 P3/P5 | create is one tx of ≤ 4 statements (environment upsert, revision_no read, insert, pointer update); no external call | `CreateRevision_CommandCounter` |
| §9.1 | `Idempotency-Key` required; canonical request hash via `idempotency_record` (T11) | `CreateRevision_SameKeySameResult` / `_DifferentPayload_409` |
| Privacy/retention | base URLs may embed internal hostnames (tenant-scoped business data); no personal data; deleted only with the tenant | RLS tests |
| Authorization | `environment:write` on `CreateEnvironmentRevisionCommand`, `run:read` on `GetEnvironmentRevisionQuery`, both enforced by the C2 pipeline; another tenant's revision is 404, a project-scoped credential reading another project's revision is 404 | `Permissions_WriteNeedsEnvironmentWrite_ReadNeedsRunRead`; `GetEnvironmentRevision_Etag_IsRevisionHash_With304_AndIsolation` |
| Retention/deletion | Revisions are deleted only with the tenant or project (T16 operator path); until then append-only (trigger + revoked grants); no separate retention policy | `EnvironmentRevision_UpdateDelete_Revoked_AndThePointerAndProjectKeys_HoldAtTheDatabase` |
| Telemetry | Standard request span and the module activity; no configuration value, URL or secret reference in a log line or metric label | code review |
| Failure path | Schema violation or secret value 422 `environment_revision_invalid` (position only), unknown project 404, numbering mismatch 409 `revision_conflict`, lock wait over 5 s 503 `unavailable`; the environment row, revision and pointer are written in one transaction or not at all | §9 tests |

## 8a. Review (2026-10-03, security + performance, from the spec package)

| # | Finding | Severity | Resolution |
|---|---|---|---|
| 1 | Body parse and schema ran before authorization; a lone surrogate gave a 500 | High | Fixed as in 05.1.1 §8a: 401 before reading, parse/schema in the handler after the permission check, unstorable text is 422 `invalid_value` |
| 2 | Identical content returned 200 before the optional `revision_no` check, so a stale caller could silently move the pointer back | Medium | Fixed: the `revision_no` check comes first (409 `revision_conflict`) |
| 3 | `lock_timeout` was set after the environment upsert, so a concurrent first create waited unbounded on the unique key | Medium | Fixed: set first; a lock timeout on the upsert is 503 too |
| 4 | `FOR UPDATE` blocked FK `KEY SHARE` checks (`project.default_environment_id`) | Low | Fixed: `FOR NO KEY UPDATE` |
| 5 | The slot read probed the hash twice; `environment_revision_env_idx` duplicated `environment_revision_no_key`; the project FK had no referencing index | Low | Fixed: one lateral probe; the duplicate index dropped; `(org_id, project_id)` index added |
| 6 | Org-scoped FKs let a revision, a default environment or a manifest point into another project of the same org | Low | Fixed: same-project triggers on `environment_revision` insert, `manifest` insert and `project.default_environment_id` update (the FKs keep the 00 §5.4.6 `(org_id, id)` shape, which the schema scanners enforce) |
| 7 | URL hosts and the display name were not secret-scanned; schema-error paths could echo map keys; `GET` cached for good after revocation; a deleted project's revisions stayed readable | Low | Fixed: host labels and name scanned, keys masked as `*`, `Cache-Control: private, max-age=3600, immutable`, deleted projects excluded |

Deferred, recorded in OI-05-15: a per-project quota on environments and revisions, rate limiting. The create is now 5 statements on `environment*` (upsert, lock, slot, insert, pointer) plus `lock_timeout` — `CreateRevision_CommandCounter` pins it.
