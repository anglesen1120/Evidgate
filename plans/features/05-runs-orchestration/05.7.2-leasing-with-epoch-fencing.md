## 1. Goal and non-goals

**Goal.** Runner jobs live in our own `job`/`job_lease` tables (D5 — never the internal `task` queue). `POST /v1/agents/jobs/claim` grants one agent a 90 s lease in a short `FOR UPDATE SKIP LOCKED` transaction; every new lease bumps `epoch`; `POST /v1/jobs/{j}/heartbeat` extends only the current epoch's lease; an expired lease frees the job to be re-claimed under a new epoch; events and heartbeats carrying an old epoch are fenced — stale events are stored as stale evidence and never complete the job.

**Non-goals.** Capability matching semantics (claim filters by pool only; full matching is 05.7.3-T1/T2); fairness/caps/timeouts/`unschedulable` (05.7.3); the expired-lease **sweeper** that re-queues dead jobs (05.10.1-T2 — expiry is lazy at next claim/heartbeat here); the agent client (05.7.4); JobSpec schema (05.7.1, consumed).

## 2. User stories and acceptance criteria

- As the platform, I issue at most one live lease per job, so two agents never execute the same job.
- As an agent, I renew my lease by heartbeat and learn immediately (409) when I lost the job, so I stop wasting work.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `POST /v1/agents/jobs/claim` with `{pool, capability}` returns 200 `{job_id, lease_id, epoch, expires_at (leased_at + 90 s), job_spec}` for a queued job in that pool; empty pool → 200 `{job: null}` |
| AC2 | 50 concurrent claims for one queued job: exactly one returns the job, the other 49 get `{job: null}` — no double lease, verified by a stress test |
| AC3 | `POST /v1/jobs/{j}/heartbeat` with `{lease_id, epoch}` for the live lease → 200, `expires_at` advanced by 90 s; heartbeat for a superseded `epoch`/`lease_id` → 409 `stale_lease`; heartbeat for a finished/canceled job → 409 `job_finished` |
| AC4 | A lease with no heartbeat past `expires_at`: the **claim transaction itself** first re-queues up to 10 same-pool jobs whose live lease has `expires_at < now()` — `FOR UPDATE SKIP LOCKED`, each re-queue writes `epoch + 1` and marks the old lease `expired` (T89) — then claims; the sweeper (05.10.1-T2) remains the backstop for pools with no claim traffic |
| AC5 | Job state transitions follow 00 §8.2 exactly: `queued → leased → running → finished`, `lost` on lease expiry (re-queued as a new lease), `canceled`; history kept per epoch in `job_lease` |
| AC6 | Ingest events carrying `epoch < current`: stored with `stale_epoch = true` and never counted toward job completion — contract hook `IJobEpochResolver.CurrentAsync(job_id)` consumed by 04's event commit (missing reason `stale_epoch_only`, 00 §8.5) |
| AC7 | No database lock is held while a test runs: the claim transaction ends when the lease row commits; a test proves claim latency < 50 ms at p95 under the 50-claim storm (budget, 00 §11 ⚠️ tune after measurement) |

## 4. Data model and migrations

Migration `migrations/NNNN_orchestration_job_lease.sql`:

- `job` (`id`, `org_id`, `run_id`, `shard_id`, `pool`, `capability_requirement` jsonb, `job_spec_hash`, `state text check (state in ('queued','leased','running','finished','lost','canceled','unschedulable'))`, `queue_timeout_at`, `execution_timeout_at`, `attempt_count`, `version`, `created_at`): `unique (org_id, id)` (T3), `unique (org_id, run_id, shard_id, attempt_count)`; composite FK `(org_id, run_id)`; partial index `(org_id, pool, created_at, id) WHERE state = 'queued'` serving the claim scan **and its `ORDER BY created_at, id`** without a sort (T89, P4).
- `job_lease` (`id`, `org_id`, `job_id`, `agent_id`, `epoch`, `leased_at`, `heartbeat_at`, `expires_at`, `outcome text check (outcome in ('active','completed','expired','released'))`): `unique (org_id, id)` (T3), `unique (org_id, job_id, epoch)`; composite FK `(org_id, job_id)`; partial index `(org_id, job_id) WHERE outcome = 'active'` — at most one live lease enforced in the claim transaction; history rows retained per epoch.
- `job.job_spec_hash` is a text reference to `job_spec.job_spec_hash` (05.7.1; content-addressed, deliberately no FK).
- RLS via `evidgate.current_org_id()` on both tables (T2).

## 5. API shapes (commands, queries, endpoints)

| Op | Type | Route / handler | Detail |
|---|---|---|---|
| `ClaimJobsCommand` | `ICommand<ClaimResult>` | `POST /v1/agents/jobs/claim` · `x-permission: job:claim` · agent service identity (tenant + pool bound) | One short tenant tx (T89): **(a)** re-queue up to 10 same-pool jobs whose live lease has `expires_at < now()` — `SELECT … FOR UPDATE SKIP LOCKED LIMIT 10`, per job: `job_lease.outcome='expired'`, job back to `queued`, `epoch + 1`; **(b)** `SELECT … FROM job WHERE state='queued' AND pool=@pool AND (queue_timeout_at IS NULL OR queue_timeout_at > now()) ORDER BY created_at, id FOR UPDATE SKIP LOCKED LIMIT 1` → insert `job_lease (epoch = prev+1, expires_at = now()+90 s)` → set job `leased`, bump `version` → commit → return spec via `IJobSpecReader` **after** commit (P5). Capability argument is recorded for 05.7.3; matching predicate lands there |
| `HeartbeatJobCommand` | `ICommand<HeartbeatResult>` | `POST /v1/jobs/{j}/heartbeat` · `x-permission: job:execute` | Verify `(job_id, epoch, lease_id)` is the live lease and `agent_id` = caller → update `heartbeat_at`, `expires_at = now()+90 s`, optionally set job `running`/`finished` by payload `status`; stale epoch → 409 `stale_lease`; terminal job → 409 `job_finished` |
| epoch resolution | `IJobEpochResolver` (contract) | consumed by 04's event commit | returns `(current_epoch, lease_outcome)` per `job_id` — one indexed read |
| `GetJobQuery` | `IQuery<JobDetail>` | internal/read model (05.7.3 surfaces publicly) | job + current lease + epoch for tests and diagnostics |

Errors (00 §9.2): 404 unknown/other-tenant job; 403 `agent_forbidden` (agent pool/tenant mismatch); 409 `stale_lease`/`job_finished`. No `Idempotency-Key` on heartbeat (frequency cap + natural key `(job_id, epoch)` covers replays); claim is naturally idempotent via `SKIP LOCKED`.

## 6. States and transitions

Job (00 §8.2): `queued → leased → running → finished`; `leased`/`running` → `lost` when the lease expires unresolved (then re-queued for a new lease — `attempt_count + 1` on re-claim); `queued`/`leased`/`running` → `canceled` (05.4.1 cancel propagation); `unschedulable` terminal (05.7.3). `job_lease` per epoch: `active → completed | expired | released`. Domain aggregate `Job` guards every transition; each transition writes audit + outbox.

## 7. Jobs and integrations

- `Evidgate.Modules.Ingestion` event commit calls `IJobEpochResolver` before writing events with `job_id`: `event.epoch < current` → stored `stale_epoch = true`, excluded from reconcile counts (missing reason `stale_epoch_only`, 00 §8.5).
- Cancel (05.4.1) flips leased/running jobs to `canceled`; agents see it via heartbeat `job_finished` and the cancel signal (05.7.4).
- Expired-lease sweeper (05.10.1-T2) scans `expires_at < now() AND outcome = 'active'` — the lazy path in AC4 and the sweeper share one `ExpireLease` domain method.
- In-claim expiry recovery (T89): expired leases are recovered inside the claim transaction — capped at 10 re-queues per claim so the hot path stays bounded (P3); the sweeper is the backstop for pools with no claim traffic.
- Outbox `job.claimed`/`job.lost` events feed metrics and the run lifecycle (`running` at first claim, 05 §4).
