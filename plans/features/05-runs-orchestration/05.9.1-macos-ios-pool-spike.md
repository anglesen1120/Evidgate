## 1. Goal and non-goals

**Goal.** Produce a written findings note answering whether Evidgate should build a macOS/iOS device pool (XCUITest via a real or virtualized macOS runner) in V3: code-signing feasibility for CI-driven builds, pool sizing/cost at pilot scale, and a device-lease reuse assessment against the model shipped in 05.8.1. Deliverable is the note plus a go/no-go recommendation — no code.

**Non-goals.** Building the macOS runner pool, an XCUITest adapter, or any iOS device-lease table (all out of scope until a go decision and a follow-up story exist); Android device leasing (05.8.1, already shipped); hosted-runner cost/security (05.9.2, a separate spike).

## 2. User stories and acceptance criteria

- As the Tech Lead, I need a dated, evidence-backed note before committing engineering time to iOS support, so the V3 backlog is prioritized on real numbers, not a guess.
- As the owner, I need a go/no-go recommendation with the assumptions stated, so a "no" can be revisited when a paying customer asks.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | A findings note exists at `docs/spikes/05.9.1-macos-ios-pool.md` covering: (a) code-signing model for CI-triggered builds (manual profile vs Apple's cloud signing vs `fastlane match`) with the constraint each implies for an unattended pool, (b) pool sizing formula and a cost estimate at 3 concurrency tiers (1, 5, 20 concurrent devices/simulators) using real list prices for the chosen macOS host option, (c) whether 05.8.1's `device_lease` schema (device UDID hash, reset policy, app checksum, Appium-style port allocation) covers an iOS simulator/device pool as-is or needs a schema delta, (d) a go/no-go recommendation with the assumptions and the trigger condition ("build when ≥ N pilot customers need iOS") |

| AC4 | The note is reviewed by the Tech Lead and the recommendation is recorded as a `[DECISION]` or `[OPEN]` line in this file's §3, not silently assumed |
