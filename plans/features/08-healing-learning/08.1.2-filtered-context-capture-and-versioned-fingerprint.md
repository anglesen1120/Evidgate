## 1. Goal and non-goals

**Goal.** Each incident stores its debugging context — masked error text, filtered DOM and accessibility snapshots, the old locator, a trace pointer and the case/suite/environment revision ids — as `ready`-gated artifact references with checksums, plus a versioned `fingerprint` that is stable across dynamic ids, locales and attribute reordering.

**Non-goals.** The `incident`/`incident_attempt` tables and freeze wiring — 08.1.1; the retrieval query that consumes `fingerprint` — 08.2.1; redaction of outbound LLM context — 08.5.3 (V2); the viewer — 09.x. Masking here is *storage-time* hygiene, not the provider-egress redaction pipeline.

## 2. User stories and acceptance criteria

- As a test maintainer, I open an incident and see the error, the DOM as it was, the locator that failed and a trace link, without ever seeing a credential or typed password.
- As the Tech Lead, I can group the same break across runs by one hash, and I can bump the fingerprint algorithm without rewriting history.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | An incident created from a failing Playwright attempt links `dom_artifact_id`, `a11y_artifact_id`, `trace_artifact_id` only when those artifacts are `ready` (T31); pending/missing artifacts leave the column null and are counted by the settle task |
| AC2 | `error_text` and any stored snapshot excerpt are masked before insert: fixture secrets (`EVIDGATE_TEST_*`, `password`-type input values, `data-sensitive` nodes) never appear in `incident` columns or the stored filtered snapshot |
| AC3 | `content_hash` = `sha256:` over the RFC 8785-canonical context bundle; re-capturing identical context yields the same hash |
| AC4 | Two runs of the same test broken the same way — differing only in generated ids, timestamps, attribute order or locale strings — produce the same `fingerprint` with `fingerprint_version = 'fp1'`; a different failure produces a different fingerprint |
| AC5 | A `NNNN` migration adds the context columns with composite FKs to `artifact`; `fingerprint` is indexed for retrieval |
| AC6 | At collection deadline + late window, the settle task moves `context_state` `pending → complete` (all expected artifacts `ready`) or `partial` (at least one expected artifact missing/`rejected`), with a recorded reason list |
| AC7 | The backfill task computes fingerprints for pre-existing `fingerprint is null` incidents idempotently and in bounded batches |

## 4. Data model and migrations

`migrations/NNNN_healing_incident_context.sql`:

- `ALTER TABLE incident` adds: `error_text text`, `error_class text` (normalised, e.g. `locator_not_found`, `assertion_mismatch`, `timeout`), `old_locator text`, `locator_strategy text` (`role`, `label`, `test_id`, `text`, `css`, `xpath`), `dom_artifact_id uuid`, `a11y_artifact_id uuid`, `trace_artifact_id uuid`, `content_hash text`, `redaction_report_hash text`, `fingerprint text`, `fingerprint_version text`, `context_missing jsonb` (reason codes for absent context), `context_settled_at timestamptz`.
- Composite FKs `(org_id, dom_artifact_id)` / `(org_id, a11y_artifact_id)` / `(org_id, trace_artifact_id)` → `artifact (org_id, id)` (00 §5.4.1).
- Indexes: `(org_id, project_id, fingerprint)` for 08.2.1 retrieval (P4); `(org_id, context_state) where context_state = 'pending'` partial index for the settle scan.
- Immutability: the 08.1.1 trigger is extended so context columns cannot be rewritten once `content_hash` is set, except `context_state`/`context_settled_at`/`context_missing` (settle writes) and `fingerprint`/`fingerprint_version` (backfill writes).

## 5. API shapes (commands, queries, endpoints)

No new HTTP endpoints. Internal shapes:

| Shape | Kind | Trigger | Result |
|---|---|---|---|
| `CaptureIncidentContext` | `ICommand<Unit>` | `record_incidents` continuation / `incident.created` outbox task | writes context columns + `content_hash` + `fingerprint` on `incident` |
| `SettleIncidentContext` | `ICommand<int>` | Cronos schedule task `incident_context_settle` | transitions `pending → complete \| partial`, returns rows settled |
| `BackfillFingerprints` | `ICommand<int>` | one-shot `task` row (ops or post-deploy) | updates `fingerprint`/`fingerprint_version` in batches, returns count |

Queries: the 08.1.1 `GetIncident`/`ListIncidents` DTOs gain `fingerprint`, `context_state`, `error_class`, `locator_strategy` fields (additive contract change, `contracts/openapi.yaml` updated).

## 6. States and transitions

- `context_state: pending → complete | partial` (T31). `pending` while at least one expected context artifact is not yet `ready` and the settle deadline (collection deadline + late window from the evidence revision's policy) has not passed. `complete` = every expected artifact `ready`. `partial` = deadline reached with missing/rejected artifacts; `context_missing` records the reasons.
- `fingerprint_version` is monotonic per incident; recomputation under a new version sets both columns and never mutates a row whose version already equals the current spec.

## 7. Jobs and integrations

- `incident_context_settle`: Cronos schedule (e.g. every 5 min); firing inserts one `task` row with unique `(schedule_name, fire_at)` — `ON CONFLICT DO NOTHING`, no leader (00 §5.3); the handler settles incidents whose revision deadline + late window has passed.
- `fingerprint_backfill`: one-shot task, batches of 500 `where fingerprint is null`, idempotent.
- Artifact readiness is read through the Evidence module's read contract (06.1.1-T1), never a direct table join across modules (00 §5.5 module boundary).

## 11. Rollout

- Expand-only migration; safe before the capture task ships. The settle schedule is registered with the worker's schedule table and is idempotent by fire key.
- Monitoring: count of `context_state = partial` incidents (signal of artifact flakiness), settle task lag, backfill progress count.
- Rollback: disable the two schedules/tasks and revert; stored context is inert data; masking cannot be "un-applied" — rollback only stops new writes.
