## 1. Goal and non-goals

**Goal.** Every incident carries at most one current label from `product_defect | test_drift | environment | data_issue | unknown` with `label_source ∈ {rule, model, human}`; deterministic rule triage proposes a label at capture time with evidence references; a human may override; only human labels are ground truth; `unknown` enables no automation; triage time is measured per project.

**Non-goals.** Model-sourced labels — `label_source = model` exists in the enum but no writer ships until the 08.5.1 LLM gateway (V2); the triage queue UI — 09.4.1; triage-time reporting views — 12.5.1 consumes the metric emitted here.

## 2. User stories and acceptance criteria

- As a QA engineer, a fresh incident arrives with a proposed label and the evidence that produced it, so I can confirm or correct it in one action.
- As the Tech Lead, I know which labels a human actually approved, so ground-truth metrics and sensitive-case approvals are never computed from guesses.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | At most one `incident_label` row per incident has `superseded_by is null` (partial unique index); any concurrent second insert fails, never silently overwrites |
| AC2 | `POST /v1/incidents/{i}/label` with `{label, reason?}` and `If-Match` on the incident `version`: writes a `label_source = human` row superseding the current label, moves `state open → triaged(label)`, audits actor/reason — stale `If-Match` → 412 with the current revision id in `error.details` (00 §9.1) |
| AC3 | A rule label never supersedes a human label; a human label supersedes rule/model; same-source relabel requires a new request (supersession order enforced in the handler) |
| AC4 | `label = unknown` leaves the incident `triaged(unknown)` but generation gating (`IIncidentContextGate`-adjacent check) refuses automation for `unknown` regardless of source — verified by the generation-gate test in 08.3.1 calling this contract |
| AC5 | An invalid `label` value → 422 `label_invalid`; missing permission → 403; other-tenant incident → 404 |
| AC6 | Histogram `incident_triaged_at - incident.created_at` (metric `healing_triage_seconds`) is emitted per triage, tagged by `label_source`, enabling 12.5.1's per-project triage-time report |
| AC7 | The rule table is deterministic and total: every captured incident gets exactly one rule evaluation producing one label + `evidence_refs`; an incident with no matching rule gets `unknown` (source `rule`) |
| AC8 | `POST /v1/incidents/{i}/label` accepts optional `assignee_membership_id` (T66): it must name an `active` membership of the same org, else 422 `assignee_invalid`; the assignee is stored on `incident` and audited. `POST /v1/incidents/{i}/close` with `{reason}` (required, ≤ 500 chars) and `If-Match` moves `triaged → closed`, sets `closed_at`/`closed_by`/`close_reason`, audits and writes an `incident.closed` outbox row; closing an `open` incident returns 409 `incident_not_triaged`, a second close returns 409 `incident_closed`; labels and attempts stay unchanged |

## 4. Data model and migrations

`migrations/NNNN_healing_incident_label.sql`:

- `incident_label`: `id`, `org_id`, `incident_id`, `label text not null check (label in ('product_defect','test_drift','environment','data_issue','unknown'))`, `label_source text not null check (label_source in ('rule','model','human'))`, `evidence_refs jsonb` (pointers: artifact ids, event ids, rule ids), `reason text`, `created_by uuid`, `created_at`, `superseded_by uuid` (self-FK to `incident_label (org_id, id)`), `version int`.
- Constraints: `unique (org_id, id)` (T3); composite FK `(org_id, incident_id)` → `incident (org_id, id)`; **partial unique** `unique (org_id, incident_id) where superseded_by is null` — one current label (AC1); `check (label_source != 'model' or true)` — column allows `model`, no writer ships in V1.
- Indexes: `(org_id, incident_id)` via the partial unique; `(org_id, created_at)` for the triage-time metric roll-up (P4).
- RLS + `FORCE ROW LEVEL SECURITY` via `evidgate.current_org_id()` (T2); audit rows on every label write (T8).

`migrations/NNNN_healing_incident_assign_close.sql` (T4, expand-only, on 08.1.1's `incident`): `assignee_membership_id uuid null` with composite FK `(org_id, assignee_membership_id)` → `membership (org_id, id)`; `closed_at timestamptz null`, `closed_by uuid null`, `close_reason text null check (char_length(close_reason) <= 500)`; `check ((state = 'closed') = (closed_at is not null))`; index `(org_id, assignee_membership_id) where assignee_membership_id is not null` for the inbox owner filter.

## 5. API shapes (commands, queries, endpoints)

| Shape | Kind | Endpoint / trigger | Permission | Codes |
|---|---|---|---|---|
| `EvaluateIncidentRules` | `ICommand<Unit>` (internal) | `incident.created` outbox task | system | n/a |
| `LabelIncident` | `ICommand<LabelResult>` | `POST /v1/incidents/{i}/label` `{label, reason?}` + `If-Match`, `Idempotency-Key` | `healing:triage` | 200 · 403 · 404 · 409 `idempotency_conflict` · 412 stale ETag · 422 `label_invalid` |
| `GetCurrentLabel` | `IQuery<IncidentLabel?>` | used by `GetIncident` DTO + generation gate | `healing:triage` (via incident read) | — |
| `CloseIncident` | `ICommand<Unit>` | `POST /v1/incidents/{i}/close` `{reason}` + `If-Match`, `Idempotency-Key` | `healing:triage` | 200 · 403 · 404 · 409 `incident_not_triaged` / `incident_closed` / `idempotency_conflict` · 412 stale ETag · 422 reason missing or too long |

- `LabelIncident` runs the C2 pipeline (telemetry → validation → tenant tx → authorization → idempotency → handler → outbox → commit); the handler checks supersession order (AC3), updates `incident.state` to `triaged(label)`, bumps `incident.version`, writes the audit row (T8) and an outbox `incident.labeled` row.
- Automation gate contract (`Evidgate.Modules.Healing.Contracts.IIncidentAutomationGate`): `AllowsGeneration(incident)` = `context_state != pending` artifacts-ready check (08.1.2-T5.2) **and** `label = test_drift` **and** `label != unknown` — `unknown` hard-blocks regardless of source (AC4, FR-08-4).

## 6. States and transitions

- `incident.state`: `open → triaged(label)` on the first label write (any source); `triaged → triaged` on supersession; `triaged → closed` by `CloseIncident` (T4, human only). `closed` is terminal in V1; a rule label arriving after close is recorded in history but does not change `state`.
- `incident_label`: append-only history with a single `superseded_by is null` head; supersession sets the old head's `superseded_by` to the new row id in the same transaction.

## 7. Jobs and integrations

- Rule triage runs as a worker `task` (`evaluate_incident_rules`, key `(org_id, incident_id)`) fired by `incident.created` (08.1.1-T1.3); deterministic, idempotent — a re-run finds the label already set and no-ops unless superseded by a human (which it must never overwrite, AC3).
- Emits `healing_triage_seconds` histogram consumed by 12.5.1 reporting.
- Emitted `incident.labeled` outbox rows are the trigger 08.3.1 generation listens to.

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| 00 §5.4 rules 1, 3, 6, 7 + T2, T3 | `incident_label` carries `org_id`, composite FK, `unique (org_id, id)`, forced RLS | Isolation.Tests cross-tenant label write → 404/0 rows |
| S2 + T51 | `healing:triage` on `LabelIncident` via pipeline attribute; `x-permission` parity asserted | `Architecture.Tests` |
| 00 §9.1 | `If-Match` → 412 with current `version` in `error.details`; `Idempotency-Key` on the mutation | `label_stale_etag_412`, `label_idempotent_replay` tests |
| T8 | every label write audits actor, reason, incident id into the per-org hash chain | audit-chain verify test |
| P3, P4 | `LabelIncident` = 1 select (label head) + 2 writes; partial unique + `created_at` index in the same migration | statement-count assertion in `label_incident` test |
| P5 | no network inside the label transaction | transaction-boundary review |
| FR-08-4 | `unknown` gate + precedence order in domain code, not in SQL convention only | `unknown_never_enables`, `human_supersedes_rule` unit tests |
| S3 | `reason` text is capped (500 chars) and never logged raw | redaction list check |
| Retention/deletion | label rows are tenant data; covered by tenant deletion (T16 path) | stated |

**DoR review answers** (00 §12, `plans/features/README.md` §6):

- **Authorization:** `LabelIncident` and `CloseIncident` carry `healing:triage` through the C2 pipeline (S2, T51 parity); the assignee must be an `active` membership of the request org (422 `assignee_invalid`); another org's incident is 404 through RLS; rule triage runs as a system task, never as a user.
- **Retention/deletion:** labels, assignee and close fields are tenant data deleted with the tenant (T16 path); label history is append-only and is never pruned separately.
- **Telemetry:** `healing_triage_seconds` histogram by `label_source`, rule-label distribution counter, dead-letter depth of `evaluate_incident_rules`; reason text is never logged.
- **Failure path:** stale `If-Match` → 412 with the current version, idempotent replay returns the first response, invalid label → 422, close of an `open` or already `closed` incident → 409 and no write; a failed rule task dead-letters and is replayable.
