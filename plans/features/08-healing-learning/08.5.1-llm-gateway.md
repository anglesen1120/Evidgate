## 1. Goal and non-goals

**Goal.** One provider-adapter gateway: JSON-schema-constrained output, per-call timeout, per-tenant/project budget with a hard stop, model/prompt version recorded on every call, and model-sourced triage treated only as a hypothesis (`label_source = model`) — never ground truth.

**Phase (CR-D-2).** G1. The first consumer is the authoring generation pipeline `13.3.1` (requirement → checklist → test case), which is why this story no longer waits for sandbox candidate validation (`08.4.3`): T1 depends on `12.3.1-T1` only (usage ledger) and T3 waits for the triage label model of `08.2.2-T1` and is G3. The healing consumers follow later: `08.3` in G3 and `08.5.4` in G4.

**Non-goals.** Redaction pipeline internals and per-tenant opt-in gating (08.5.3 — this story assumes redaction runs before egress but does not build the redaction pipeline itself, only the call-point contract for it); untrusted-context containment specifics beyond the interface seam (08.5.2); the Playwright healer (08.5.4); the apply/PR flow (08.6.x).

## 2. User stories and acceptance criteria

- As the platform, every LLM call is schema-constrained, timed-out, budgeted and attributable to a project/incident/candidate, so cost and risk are bounded and auditable.
- As a Tech Lead, a model-sourced label is visibly a hypothesis, never authorises anything by itself (D4).

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | A call whose response fails the declared JSON Schema is retried once (bounded) then fails closed with `llm_schema_violation`; no partial/best-effort candidate is created |
| AC2 | A call exceeding the per-call timeout is aborted (`IHttpClientFactory` resilience handler) and recorded `status = 'timeout'`; no retry beyond the bounded resilience policy (P6) |
| AC3 | Per-tenant/project budget: `UPDATE healing_llm_call... ` style atomic check (mirroring T32) stops further calls once the period budget is spent — 0 rows / hard stop → `budget_exceeded`, no call is placed |
| AC4 | Every `healing_llm_call` row carries `project_id`, `purpose`, `model`, `prompt_version`, `tokens`, `cost`, `status`, plus `incident_id`/`candidate_id` for the purposes that have one (T30) |
| AC5 | Model-sourced triage writes `incident_label` with `label_source = 'model'`; it never sets `unknown`-guard bypass and never itself authorises a candidate action (FR-08-4/D4) |
| AC6 | Provider secrets (API keys) are read only from the secret store, never logged, never in `healing_llm_call` columns (S3) |
| AC7 | An authoring generation call is recorded with `purpose = 'authoring_generation'`, `project_id` set, `incident_id`/`candidate_id` null, and its `healing_llm_call.id` is what `authoring_version.ai_run_id` (`13.3.1-T2`) stores, so every generation is attributable and costed |

## 4. Data model and migrations

- `healing_llm_call` (area §4.1, `migrations/NNNN_healing_llm_call.sql`): `org_id`, `id`, `unique (org_id, id)`, `project_id` composite FK `(org_id, project_id)` → `project`, `incident_id` composite FK `(org_id, incident_id)` → `incident` (nullable for `authoring_generation`), `candidate_id` nullable composite FK `(org_id, candidate_id)` → `healing_candidate` (nullable — a triage-hypothesis call may precede any candidate), `purpose text check (purpose in ('authoring_generation','triage_hypothesis','candidate_generation'))`, `check (purpose = 'authoring_generation' or incident_id is not null)` (an authoring call serves a project generation, not an incident), `model text`, `prompt_version text`, `tokens int`, `cost numeric(12,6)`, `status text check (status in ('ok','timeout','schema_violation','budget_exceeded','error'))`, `redaction_report_hash text null` (populated once 08.5.3 lands; nullable now so this story is independently buildable), `created_at`. Index `(org_id, project_id, created_at)` for budget-window sums and `(org_id, project_id, purpose, created_at)` for cost reporting.
- `healing_llm_budget` (new, `migrations/NNNN_healing_llm_budget.sql`): `org_id`, `project_id`, `period_cap_cost numeric`, `period_cap_tokens int`, `period text check (period in ('daily'))`, `used_cost numeric`, `used_tokens int`, `period_start date`; composite FK `(org_id, project_id)` → `project`; RLS via `evidgate.current_org_id()`. Consumed atomically: `UPDATE healing_llm_budget SET used_cost = used_cost + @cost, used_tokens = used_tokens + @tokens WHERE org_id=@org AND project_id=@p AND period_start=@today AND used_cost + @cost <= period_cap_cost RETURNING id` — mirrors T32's `healing_quota` pattern for the budget hard stop.

## 5. API shapes (commands, queries, endpoints)

- No `/v1` endpoint (internal gateway only, invoked by 13.3.1-T2 authoring generation, 08.2.2 triage and 08.5.4 candidate generation).

| Shape | Detail |
|---|---|
| Command `InvokeHealingLlm` (`ICommand<LlmCallOutcome>`) | Inputs `project_id`, `incident_id`, `candidate_id?`, `purpose`, `prompt_version`, prompt payload (already redaction-wrapped by the caller per 08.5.2/08.5.3 seam); atomically reserves budget (`healing_llm_budget`) in the same transaction as the pre-call `healing_llm_call` row (`status='ok'` optimistic, corrected post-call), calls `IHealingLlmProvider.CompleteAsync` outside the transaction (P5), then a second short transaction records final `status`/`tokens`/`cost` |
| `IHealingLlmProvider` | `CompleteAsync(request, jsonSchema, timeout, ct) → { json, tokens, cost, model }`; implementations: `MockHealingLlmProvider` (tests, deterministic fixtures) and the real provider adapter (built once O4 closes — not part of this story's Done-when) |
| Output validation | Corvus.Json.Validator validates the response against the caller-declared JSON Schema before it is accepted; one bounded retry (same request, fresh call) on schema violation, then `llm_schema_violation` |
| Errors (internal) | `budget_exceeded`, `llm_schema_violation`, `llm_timeout`, `llm_provider_error` — mapped to `insufficient_evidence`/`unavailable` by the caller (08.5.4/08.6.3), never surfaced as `/v1` HTTP errors from this story |

## 6. States and transitions

- No new candidate/incident states. `InvokeHealingLlm` outcome feeds:
  - triage: writes `incident_label(label_source='model')` (00 §8.7 label rule — human still supersedes) — advisory only (D4).
  - candidate generation (08.5.4 consumes): outcome feeds candidate creation, still bounded by existing `proposed → validated → …` machine.
  - authoring generation (13.3.1-T2 consumes): the outcome is the schema-validated checklist / test-case payload handed back to the caller; no incident, label or candidate state is touched.
- `healing_llm_budget` is a rolling daily counter, reset by a Cronos schedule `(schedule_name='llm-budget-reset', fire_at)` unique fire key (00 §5.3 pattern), not a state machine.

## 7. Jobs and integrations

- Cronos schedule resets `healing_llm_budget.used_cost/used_tokens` at period boundary — idempotent fire via unique `(schedule_name, fire_at)`, no leader (00 §5.3).
- Cost rows are read by 12.3.1's ledger/report pipeline (cost per accepted fix, area FR-08-18) — this story emits the attributable rows; aggregation is 12.3.1's.
- Consumed by 13.3.1-T2 (authoring generation: `purpose = 'authoring_generation'`, the payload is the requirement text/documents/images already redacted by 08.5.3 and opt-in-approved), 08.5.2 (wraps prompts before they reach `IHealingLlmProvider`), 08.5.3 (redaction happens before `InvokeHealingLlm` is called — the gateway assumes its input is already redacted and opt-in-approved; it does not itself call the redaction pipeline, keeping this story's scope to gateway mechanics per FR-08-10), 08.6.3 (provider failure → `unavailable` degradation), 08.7.2 (model/prompt version on lineage rows).

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| P6 | `IHttpClientFactory`-based provider adapter, per-call timeout + bounded retry (Polly-style resilience handler) | `InvokeHealingLlm_Timeout_Aborts` (AC2) |
| P5 | Provider HTTP call happens outside the DB transaction; budget reserve/commit are separate short transactions | Transaction-scope test |
| S3 | Provider API key from secret store only; never in `healing_llm_call` columns, logs, or exception messages | Log-redaction + schema test (AC6) |
| S4 | Provider egress via an allow-listed `HttpClient` base address only — no user-supplied URL | Egress-allowlist unit test |
| T30 attribution | `project_id`/`incident_id`/`candidate_id` on every row | AC4 |
| D4 (safety) | Model output only sets `label_source='model'` or feeds a candidate through the existing validator (08.4.x) — gateway grants no authorisation itself | `ModelLabel_NeverAuthorisesDirectly` test (AC5) |
| Budget hard stop (mirrors T32) | Atomic `UPDATE … WHERE used_cost + @cost <= cap RETURNING`; 0 rows → no call placed | `InvokeHealingLlm_BudgetExceeded_NoCallPlaced` (AC3) |
| NFR-08-1 | Provider outage (mocked failure) never blocks ingest/evaluate — only healing degrades | `ProviderError_DoesNotAffectIngestPath` (integration) |
| 00 §5.4 RLS | `healing_llm_call`/`healing_llm_budget` `org_id`-scoped, composite FKs, `unique (org_id,id)` | Cross-tenant isolation test |
| Authorization | Internal gateway only — no `/v1` route; callers are the 13.3.1-T2 authoring generator, the 08.2.2 triage path and the 08.4 candidate generator with a tenant-resolved `(org_id, project_id)`; the provider key is read by the worker identity from the secret store, never by a tenant principal; tenant opt-in (`08.5.3-T3`) and credit (`08.5.5-T2`) are checked before any provider call | AC6, AC7; cross-tenant isolation test |
| Retention/deletion impact | `healing_llm_call` and `healing_llm_budget` are project-scoped rows removed by tenant/project deletion (06.4.4, 06.4.5) and covered by the 08.7.2-T2 cascade; no prompt or completion body is stored, so nothing else needs purging | §4; 08.7.2-T2 |
| Telemetry | `evidgate.healing.llm_calls_total{status}`, `llm_cost_total{project}`, budget-remaining gauge (§11); labels carry no incident id, prompt text or personal data | §11; NFR-11-2 |
| Failure path | Provider timeout / 429 / invalid JSON → bounded retry, then `status = 'timeout'` or `'schema_violation'` and no candidate, credit refunded once (08.5.5-T2); budget or credit exhausted → `budget_exceeded` / `ai_credit_exhausted` with no provider call; provider down → healing resolves `unavailable` (08.6.3-T2) while ingest and evaluation continue (NFR-08-1) | AC1–AC3; `ProviderError_DoesNotAffectIngestPath` |

## 11. Rollout

- Feature flag: `healing.llm_gateway.enabled` defaults **off**; real provider adapter is not wired until O4 closes — the mock adapter is the only implementation this story ships against.
- G1 consequence: `13.3.1` generation cannot run on the mock, so O4 (provider, region, egress) must close before the first real generation call; the concrete `IHealingLlmProvider` registration is configuration plus 08.5.3's opt-in gate, with no contract change, and the plan 11 transfer assessment (`11.8.1-T5`) is a precondition of that first call.
- Merge order: T1 → T3.
- Monitoring: `evidgate.healing.llm_calls_total{status}`, `llm_cost_total{project}`, budget-remaining gauge.
- Rollback: revert; disabling the flag returns healing to shadow/rules-only generation (08.3.1) with no data loss.
