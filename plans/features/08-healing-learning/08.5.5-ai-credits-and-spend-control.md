## 1. Goal and non-goals
**Goal.** A tenant can use the model only while it has AI credit and has opted in. Every call consumes credit exactly once under the key `ai:<call_id>`. Evidgate alone holds the provider key. A per-tenant cap, a global daily cap and the kill switch each stop model calls within one request.

**Non-goals.** Gateway mechanics, schema validation and the per-project budget (08.5.1); redaction and the opt-in record (08.5.3, consumed here as a gate); the ledger schema (12.3.1); prices and invoicing (O5 `[OPEN]`, 12.4.1). This story names no provider or model: both are chosen by 08.5.5-T4 and recorded in its decision memo.

## 2. User stories and acceptance criteria
- As a tenant admin, I see my credit balance and usage and am told with `ai_credit_exhausted` when credit runs out, with no hidden spend.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | Replaying the same call (`ai:<call_id>`) consumes credit once: one `consume` entry and one ledger row with `metric = 'ai_credit'`, however many retries or settles |
| AC2 | Balance below the reserve amount returns `ai_credit_exhausted`; the provider mock records 0 requests |
| AC3 | A tenant without an approved, unrevoked opt-in (08.5.3-T3) gets no provider call and no reserve; revoking opt-in stops the next call |
| AC4 | N concurrent calls against a balance that covers K < N never drive `balance` below 0 and exactly K reach the provider |
| AC5 | A failed or timed-out provider call is refunded once (one `refund` entry); replay does not refund twice |
| AC6 | The provider key never appears in any DB row, log line, trace attribute, exception message, artifact or API response (canary-string scan) |
| AC7 | Per-tenant cap, global daily cap and kill switch each reject the next call with no provider request, in the same request that observes them |
| AC8 | All credit amounts are `bigint` micro-units; no float or `numeric` type appears in the credit tables, DTOs or math (property test: sum of entries = balance) |
| AC9 | When the cost of a call is unmetered, the stored and shown cost is `null` with `unavailable_reason`, never 0 (T60) |
| AC10 | Alert at 80 % of the global daily cap fires once per day; operator adjustments above the threshold need a second, different operator |

## 4. Data model and migrations
`migrations/NNNN_ai_credit.sql` (NNNN = next free number at build), module `Evidgate.Modules.Healing`, run as owner:

- `ai_credit_account`: `id`, `org_id`, `unique (org_id, id)`, `unique (org_id)`, `balance_micro bigint not null check (balance_micro >= 0)`, `reserved_micro bigint not null check (reserved_micro >= 0)`, `period_cap_micro bigint null`, `period_spent_micro bigint not null`, `period_start date`, `created_at`, `updated_at`, `version`. Composite FK `(org_id)` → `organization`; FORCE RLS via `evidgate.current_org_id()`.
- `ai_credit_entry` (append-only, `REVOKE UPDATE, DELETE` from the app role): `id`, `org_id`, `account_id` composite FK `(org_id, account_id)`, `kind check (kind in ('grant','reserve','consume','refund','expire','adjust'))`, `amount_micro bigint not null`, `call_id uuid null` composite FK `(org_id, call_id)` → `healing_llm_call`, `billing_key text null`, `reason text`, `actor`, `created_at`; accounting records, kept like the 12.3.1 ledger. `unique (org_id, billing_key)` where `billing_key is not null` and `unique (org_id, call_id, kind)` make consume and refund once-only.
- `ai_spend_global` (not tenant data, `org_id` absent, listed in `contracts/rls-exceptions.txt` with a reason): `day date primary key`, `cap_micro bigint`, `spent_micro bigint`, `alerted_at timestamptz null`; written only by the gateway role.
- `healing_llm_call.cost` (08.5.1) stays nullable; this story adds `cost_micro bigint null` and `unavailable_reason text null` (T60). No column anywhere stores a key or key reference value.

## 5. API shapes (commands, queries, endpoints)
| Operation | Kind / endpoint | Permission | Behaviour |
|---|---|---|---|
| `ReserveCredit` | `ICommand`, module contract | gateway only | One tx: `UPDATE ai_credit_account SET balance_micro = balance_micro - @r, reserved_micro = reserved_micro + @r WHERE org_id=@o AND balance_micro >= @r AND (period_cap_micro IS NULL OR period_spent_micro + @r <= period_cap_micro) RETURNING` (row lock) plus the `reserve` entry keyed `ai:<call_id>`; 0 rows → `ai_credit_exhausted`, no call |
| `SettleCredit` / `RefundCredit` | `ICommand`, module contract | gateway only | Second short tx after the provider call (P5): `consume` with actual micro-cost and the ledger row, or `refund` of the reserve; both guarded by `unique (org_id, call_id, kind)` |
| `GetAiCredit` | `GET /v1/orgs/{o}/ai-credit` (`IQuery`, Dapper) | `usage:read` (`tenant_admin`) | `{balance_micro, period_cap_micro, usage[]}`; unmetered values `null` + `unavailable_reason` |
| `GrantAiCredit`, `AdjustAiCredit` | `POST /internal/operator/orgs/{o}/ai-credit` | `billing:write`, audited, two-person above threshold | Appends `grant`/`adjust`; threshold is config, approver ≠ author (CHECK-enforced) |
| `SetGlobalAiCap` | `PUT /internal/operator/ai-spend/global-cap` | `billing:write`, audited | Sets `ai_spend_global.cap_micro` for the day; no key material in the request or response |

Errors: `ai_credit_exhausted`, `ai_spend_cap_reached`, `healing_unavailable` (kill switch, via 08.6.3) as §9.2 envelopes; none echoes a key.

## 6. States and transitions
Per call: `reserved → consumed` or `reserved → refunded`; each state is one append-only entry, so replays are no-ops. Tenant credit: `active` while `balance_micro > 0`; `exhausted` is derived (never stored). The kill switch overrides everything: it is evaluated first, before opt-in, caps and balance, and returns `healing_unavailable` with no reserve entry.

## 7. Jobs and integrations
- Call order inside `InvokeHealingLlm`: kill switch → opt-in gate (08.5.3) → global cap → tenant cap and balance reserve → redaction (08.5.3) → provider → settle or refund.
- 80 % global-cap alert via the 01.5.1 alert sink, once per day (`alerted_at`). Cronos schedules (unique `(schedule_name, fire_at)`): `ai-credit-period-reset` (per-tenant period spend), `ai-credit-reserve-reaper` (refunds a `reserve` older than the call timeout plus margin once, for crashed workers), `ai-credit-expiry` (writes `expire` entries if a grant has an expiry `[OPEN]`).
- The provider key is read from the secret store (10.1.1-T2) at call time; rotation per 10.7.1-T4 needs no redeploy and no downtime. Egress goes only to the allow-listed provider base address (S4).
- Provider and model: chosen by 08.5.5-T4 from the evaluation corpus; the no-retention term and processing region are verified there. Any provider claim (pricing, retention, region) is ⚠️ until the memo cites a source.

## 8. Security, privacy and performance
| Rule | How this story meets it | Proven by |
|---|---|---|
| S3 (secrets) | Key only in the secret store and in-memory header; log, trace and exception scrubbers; no key column | `ProviderKey_NeverPersistedOrLogged` canary scan (AC6) |
| Exactly-once | Idempotent `ai:<call_id>` key + `unique (org_id, call_id, kind)` + `ON CONFLICT DO NOTHING` | `Consume_Replay_OneEntry` (AC1/AC5) |
| No overdraw | Conditional `UPDATE … WHERE balance_micro >= @r RETURNING` row lock; no read-then-write | `Reserve_ConcurrentCalls_NoOverdraw` (AC4) |
| Integer math | `bigint` micro-units; conversion at the edge only; no float | `CreditMath_SumEqualsBalance` property test (AC8) |
| T60 | unmetered cost stored `null` with reason | AC9 |
| Stop within one request | Kill switch, global cap, tenant cap read inside the same request path, no cache longer than the request | `KillSwitch_StopsNextCall`, `CreditMath_SumEqualsBalance`, `UnmeteredCost_IsNull`, `AiCreditEntry_UpdateDelete_Rejected` (AC7–AC9) |
| PDPL | Opt-in, redaction and the cross-border evidence (08.5.3) gate every call; credit does not bypass them | `NoOptIn_NoProviderCall` (AC3) |

**Definition-of-Ready review answers**
1. **Authorization:** reads `usage:read`; grants/adjustments/caps `billing:write` (`billing_operator`), audited, two-person above the threshold; the gateway acts as a system principal, never as a tenant.
2. **Retention/deletion impact:** ledger-class entries survive tenant-artifact deletion as accounting records; `healing_llm_call` rows follow 08.5.1/11.8 rules; no prompt content is stored here.
3. **Telemetry:** `ai_credit_reserve_total{outcome}`, `ai_credit_consumed_micro_total`, `ai_spend_global_ratio`, `ai_call_blocked_total{reason}`; no tenant content or key in labels.
4. **Failure path:** provider error or timeout → refund once; worker crash → reaper refund; secret store unreachable → fail closed (`healing_unavailable`); DB failure on settle → entry stays `reserve`, reaper settles; ingest and evaluate are never affected (NFR-08-1).

- Rollback: migrations are forward-only (tables inert when unused); turn the flag off and use the kill switch; credit balances remain intact.
