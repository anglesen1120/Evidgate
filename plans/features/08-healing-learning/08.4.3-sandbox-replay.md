## 1. Goal and non-goals

**Goal.** Run baseline and candidate test on the **same** app digest, fixture and environment inside an isolated, one-shot sandbox; reject non-comparable runs; meter replay minutes against the project quota; and return a validation report with an explicit rejection taxonomy — the incident goes back to triage when validation can't prove anything.

**Non-goals.** The semantic checks executed inside the replay (08.4.2 defines them); the sandbox isolation hardening itself (11.2.1-T6 contract consumed); hosted runners (DECISIONS A5 forbids); the healer running in this sandbox (08.5.4); eliminating the residual risk of running untrusted-context patches next to CI secrets — T77 mitigates it (reference workflow + CLI refusal heuristics), the remainder is recorded in 11 §4 / 11.1.1, not engineered away here.

## 2. User stories and acceptance criteria

- As the healing pipeline, baseline and candidate always execute under identical conditions, so "candidate passes" actually means the mechanics fix works.
- As a project owner, replay spend is capped per day and every stop has a reason, so healing never burns unbounded CI minutes (NFR-08-3).

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | A replay job records `app_digest`, `fixture_hash`, `env_hash`, `engine` + pinned `engine_version`; two runs with differing digest/fixture/env are rejected `non_comparable` and never report a pass/fail |
| AC2 | Replay runs on the host selected in O10 — V1 default (a): a customer-CI job driven by the CLI `evidgate replay` path (`05.2.1-T4` CI-mode job contract), no hosted execution of customer code; the job follows the T77 reference workflow (`permissions: {}`, no `secrets:`, `workflow_dispatch` on an environment without secrets, network limited to the app under test) |
| AC3 | Sandbox guarantees (from 11.2.1-T6): one-shot identity, egress allowlist, no tenant secrets/env; the replay spec test asserts no secret-scoped env var is forwarded |
| AC4 | `replay_minutes_per_day` is consumed atomically via `UPDATE healing_quota … WHERE counters < cap RETURNING` (T32); cap reached → job rejected `quota_exceeded`, 429-equivalent internal code, no partial metering |
| AC5 | Baseline-fails → candidate-passes → `validated`; baseline-passes or both-fail → `insufficient_evidence` with `stop_reason` (`baseline_not_reproducible`, `candidate_failed`, `replay_error`, `deadline`, `quota_exceeded`); incident returns to `open`/`triaged` for the latter set |
| AC6 | Shadow-validation p95 stays under the NFR-08-2 budget: a replay round completes in ≤ 15 min wall clock on the pilot fixture (measured, recorded in the report) |
| AC7 | Validation report per round is written to `candidate_validation` (`sandbox_run_id`, verdict, `reason_code`, `stop_reason`, duration) — append-only, never overwritten |
| AC8 | A replay-tagged run (`run.purpose = 'replay'`, T67) is accepted only with a valid, unexpired `replay_grant_id` scoped to the candidate's project (else 422 `replay_grant_invalid`, 05.2.1-T5); such a run never creates an `incident` (08.1.1-T1), never produces a `live` evaluation row (07.2.2-T4 — `shadow` only) and is never bound to a `release` or counted as regression (05.2.1-T5, 07.5.3) — enforced structurally by 05/07, not by convention; this holds even for the baseline leg, which is expected to reproduce the original failure |
| AC9 | T77 refusal heuristic ⚠️: the CLI refuses `evidgate replay` (non-zero exit, reason printed) when the job's `GITHUB_TOKEN` carries write scopes or when secret-like env vars are exposed to the job; the refusal is heuristic — the residual risk is recorded in 11 §4 and the 11.1.1 threat model |

Mitigations owned here: a reference workflow (`permissions: {}`, no `secrets:`, `workflow_dispatch` on an environment without secrets, egress limited to the app under test) shipped for customers to copy, and a CLI refusal heuristic (`evidgate replay` refuses when `GITHUB_TOKEN` write scopes or secret-like env vars are exposed — ⚠️ heuristics, not a guarantee). ## 5. API shapes (commands, queries, endpoints)

- Internal commands (worker + CI-facing report intake):

| Shape | Detail |
|---|---|
| Command `EnqueueReplay` (`ICommand<uuid>`) | Mints `replay_job` + `task` row (natural key `(candidate_id, round_no, leg)` where `leg ∈ baseline\|candidate\|control`) and the **single** `replay_grant_id` (project/candidate/expiry, T67, stored on `replay_job`) for the executor to pass through unchanged at run create, consumes `replay_minutes_per_day` atomically (T32) in the same transaction; zero rows → 429-style `quota_exceeded` → `stop_reason` |
| Command `ClaimReplayJob` (internal) | `FOR UPDATE SKIP LOCKED` claim per 00 §5.3; hands the spec to the O10 executor adapter |
| Command `ReportReplayResult` (`ICommand<…>`) | Called from the O10(a) CLI path (`evidgate replay --report`): the CLI writes a `run` (`purpose='replay'`, carrying the `replay_grant_id` from the executor's spec, T67) + evidence through the normal ingest path (05.2.1-T4/T5), and the worker reconciles it back to `replay_job` via `spec.job_tag`; no new `/v1` write endpoint, the reconciliation is the `task` consumer |
| Query `GetReplayReport` (`IQuery`) | Dapper read; serves `GET /v1/healing/candidates/{c}` detail (08.3.x endpoint) — report id, verdict, stop reason, duration |
| `IReplayGrantValidator` (exported, `Evidgate.Modules.Healing.Contracts`) | Internal, no HTTP: `ValidateAsync(replayGrantId, projectId, candidateId)` — called by 05.2.1-T5 at run create; checks the grant exists, is unexpired and matches project/candidate; returns a typed result (`valid` / `replay_grant_invalid`), never a raw cross-module DB read (00 §5.5 module-shape rule) |
| Errors | `quota_exceeded` (429 pattern internal), `non_comparable`, `replay_unavailable` — mapped to candidate exits, never to HTTP on this story |

## 6. States and transitions

- `replay_job`: `queued → claimed → running → reported | failed` (`failed` covers crash/timeout/non-comparable — the `stop_reason` carries the taxonomy).
- Candidate transitions unchanged (00 §8.7): `proposed → validated` only when baseline-fails ∧ candidate-passes ∧ semantic checks pass; `insufficient_evidence` otherwise; `rejected` on validation-layer verdicts from 08.4.x.

## 7. Jobs and integrations

- `task` queue consumer `ReplayJobDispatcher` (Cronos-independent; fired by outbox `healing.candidate_changed`); deadline enforcement via `spec.deadline_at` — an overdue job is marked `failed`/`deadline` by a Cronos sweep `(schedule_name='replay-sweep', fire_at)` unique fire key.
- Executor adapter seam `IReplayExecutor`: V1 = `CiReplayExecutor` — receives the `replay_grant_id` minted once by `EnqueueReplay` (T1.1) and passes it through unchanged in the ingest-tagged run spec (`purpose='replay'`) for the customer CI job; it never mints its own grant. 05.2.1-T5 validates the grant at run create via the exported `IReplayGrantValidator`. The interface leaves room for O10(b) without changing T1/T3.
- 11.2.1-T6 reviews this spec: one-shot container, egress allowlist = app-under-test + artifact store only, no tenant secrets, no credential env vars.
- T77 customer-CI mitigation set (V1, O10 a): the shipped reference workflow runs the replay job with `permissions: {}` and no `secrets:` block, triggered by `workflow_dispatch` on a GitHub environment holding no secrets, network restricted to the app under test; `evidgate replay` refuses to run when it detects `GITHUB_TOKEN` write scopes or secret-like env vars (⚠️ heuristic). Residual risk recorded in 11 §4 / 11.1.1 (AC9).
- Replay minutes + counts metered to the 12.3.1 usage ledger shape; replay artifacts (report log, optional trace) upload through 06's presigned path with `sensitive` classification (T57).

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| DECISIONS A5 + O10 | No hosted execution of customer code; V1 replay runs in the customer's CI | `CiReplayExecutor` unit test + §3 O10 note |
| 11.2.1-T6 isolation | Spec asserts one-shot identity, egress allowlist, zero secret env forwarding | `ReplaySpec_HasNoSecrets` test (AC3) |
| T77 replay-host risk | Reference workflow carries `permissions: {}`/no `secrets:`/restricted egress; CLI refuses replay on `GITHUB_TOKEN` write scopes or secret-like env vars ⚠️ heuristic; residual risk documented in 11 §4 + 11.1.1 | `ReplayCliRefusalTests` (AC9), reference-workflow lint fixture |
| T32 quota | Replay minutes consumed atomically inside the enqueue transaction | `EnqueueReplay_QuotaCap_ReturnsExceeded` (AC4) |
| NFR-08-2 latency | Deadline cap + duration recorded; p95 checked on the load fixture | `ReplayRound_P95Budget` (AC6) |
| P5 | No network/DB lock while the test runs — worker holds no transaction across `running` (05.2.1-T4 pattern: claim → run external → report) | Transaction-scope assertion in dispatcher test |
| P3 | Result reconcile = bounded statements (job row, validation row, candidate update, outbox) | Command-counter assertion ≤ 5 |
| 00 §5.4 RLS | `replay_job` `org_id` + composite FK + `unique (org_id,id)` | Cross-tenant test + 02.6.1-T2 lint |
| S3 | Spec jsonb contains digests/hashes only; artifact refs by id; report bytes through the `sensitive` artifact path | Log-redaction test |
| T57 | Replay artifacts (trace/video/log) default `sensitive`; served via artifact viewer, not inline | Artifact-kind classification test |

- **Authorization:** every `purpose='replay'` run-create is accepted only with the server-issued `replay_grant_id`, valid, unexpired and scoped to the candidate's project, else 422 `replay_grant_invalid` (AC8, §3 T67, `IReplayGrantValidator` in §5); `replay_job` is org-scoped by RLS `evidgate.current_org_id()` + composite FK + `unique (org_id,id)` (§8 00 §5.4 row); the internal commands `ClaimReplayJob`/`ReportReplayResult` are worker/CLI-only and expose no HTTP surface (§5).
- **Retention/deletion:** this story writes `replay_job` rows, append-only `candidate_validation` report rows (never overwritten, AC7) and `sensitive` replay artifacts (report log, optional trace/video) through 06's presigned path (T57, §7); no retention window or deletion behaviour for those rows/artifacts is stated in this plan — [OPEN].
- **Telemetry:** metrics `evidgate.healing.replay_minutes_total{project}`, `replay_jobs_total{stop_reason}` and histogram `replay_duration_ms`, with the NFR-08-2 alert at p95 > 15 min (§11); replay minutes + counts are metered to the 12.3.1 usage ledger shape (§7); `spec jsonb` carries digests/hashes only and report bytes go through the `sensitive` artifact path (S3 log-redaction test, §8).
- **Failure path:** a failed replay job ends `failed` with a `stop_reason` from the closed taxonomy (`baseline_not_reproducible`, `candidate_failed`, `replay_error`, `deadline`, `quota_exceeded`, `non_comparable` — §4/§6); an overdue job is marked `failed`/`deadline` by the Cronos `replay-sweep` (§7); internal codes `quota_exceeded` (429 pattern), `non_comparable` and `replay_unavailable` map to candidate exits, never to HTTP (§5); while the O10 flag is `disabled` the executor yields `replay_unavailable` → `insufficient_evidence`, never a crash (§11); `insufficient_evidence` returns the incident to triage (AC5) and the CLI refusal exits non-zero with a printed reason (AC9).
