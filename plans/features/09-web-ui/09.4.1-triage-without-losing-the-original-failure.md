## 1. Goal and non-goals

**Goal.** From the failure inbox a triager can filter, open, label, assign and close a failure — root error separated from infrastructure error, log/trace/artifact evidence bounded and isolated-origin, related issue linked — while the original raw status and evidence revision of the failure stay intact and visible even after labelling, investigation, rerun comparison or (V2) a healing candidate exists (FR-09-3).

**Non-goals.** Incident creation and settlement logic (08.1.1/08.1.2, server-owned); candidate generation/validation (08.3.x/08.4.x); the shadow/approval review screens (09.5.1/09.5.2 own that UI); run detail internals beyond the deep links it exposes (09.3.1 owns them); healing kill-switch configuration (09.7.1).

## 2. User stories and acceptance criteria

- As a QA engineer, I open the inbox, filter by label/owner/severity/flaky and pick up the next failure to investigate, with my place kept on reload.
- As a triager, I label a failure with a reason and see whose label it is (rule, model or human) so I know which labels are ground truth.
- As an investigator, I compare the current failure against past revisions and reruns without ever losing the original raw report or evidence revision that first exposed it.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | The inbox list filters by status, label, owner, severity and flaky flag; the cursor and filters persist in the URL and restore identically on reload (Vitest `inbox-store.spec.ts`) |
| AC2 | Opening a failure shows root error and infrastructure error as two separate blocks, never merged (FR-09-3); a case with only an infra failure never shows a root-error block with invented content |
| AC3 | Labelling writes `POST /v1/projects/{p}/incidents/{i}/label`; the label chip shows `label_source ∈ {rule, model, human}`; only a human label is described as ground truth in the UI copy (Playwright `e2e/triage-label.spec.ts`) |
| AC4 | Reopening a labelled, closed or reassigned failure still renders the original raw status and evidence revision unchanged — labelling never rewrites or hides the original attempt data |
| AC5 | The investigation view diffs two evidence revisions of the same `execution_key`, showing per-case changes, not just totals (comparison step of 09 §4.3) |
| AC6 | Artifact/log viewing for a failure opens only on the isolated viewer origin; a sensitive artifact requires `artifact:read_sensitive` and a raw presigned URL is never shown as text (FR-09-14, T57) |
| AC7 | An insufficient-evidence state (unknown status, missing artifact, stale epoch) renders its own reason with a fix action, never as a plain empty screen |
| AC8 | Assign/close actions are permission-gated to `healing:triage`; an unauthorized user sees the control disabled/hidden, not a 403 toast on click |

## 3. Contracts touched

- 00 §9.3 endpoints consumed: `GET /v1/projects/{p}/incidents` (`healing:triage`, list + filters), `GET /v1/incidents/{i}` (`healing:triage`), `POST /v1/incidents/{i}/label` (`healing:triage`); `GET /v1/runs/{r}/reports/{report_id}/comparison` (`run:read`) for the rerun/evidence-revision diff; `GET /v1/artifacts/{a}/download-url` (`artifact:read` + `artifact:read_sensitive`).
- 00 §8.7 incident lifecycle rendered only: `open → triaged(label) → closed`; labels `product_defect | test_drift | environment | data_issue | unknown`; `label_source ∈ {rule, model, human}`; `unknown` never enables automation; one incident per `(org_id, run_id, execution_key)`, retries as `incident_attempt` (T34); context `pending → complete | partial` (T31).
- No new endpoint or state introduced. Assign/close copy stays within existing `healing:triage` scope — the area plan names no separate assignment permission, so this plan reuses `healing:triage` for assign/close and records the mapping in §5.
- Resolved (T66): assignee travels as optional `assignee_membership_id` on the existing `POST /v1/incidents/{i}/label` payload (label + assignee in one call, `healing:triage`), and closing uses the additive `POST /v1/incidents/{i}/close` (`healing:triage`, reason required, 00 §8.7 `triaged → closed`). No contract gap remains.

## 5. API shapes (commands, queries, endpoints)

| Route | Guard (`CanMatchFn`) | Store | Page |
|---|---|---|---|
| `projects/:projectId/inbox` | `healing:triage` | `InboxStore` | filtered, cursor-paginated failure list |
| `projects/:projectId/inbox/:incidentId` | `healing:triage` | `IncidentDetailStore` | failure detail, triage actions, investigation flow |

| Endpoint consumed | Permission | UI semantics |
|---|---|---|
| `GET /v1/projects/{p}/incidents` | `healing:triage` | filters status/label/owner/severity/flaky; `?cursor=&limit=50` |
| `GET /v1/incidents/{i}` | `healing:triage` | root/infra error split, `incident_attempt` rows, context `pending/complete/partial` |
| `POST /v1/incidents/{i}/label` | `healing:triage` | body `{ label, assignee? }`; response updates `label_source: human`; close is `label: closed`-equivalent state transition per 08's contract |
| `GET /v1/runs/{r}/reports/{report_id}/comparison` | `run:read` | per-case diff between two evidence revisions of the same `execution_key` |
| `GET /v1/artifacts/{a}/download-url` | `artifact:read` (+`artifact:read_sensitive`) | bounded viewer, isolated origin, URL refresh on expiry |

## 6. States and transitions

Rendered only (00 §8.7, no new states): incident `open → triaged(label) → closed`; labels `product_defect | test_drift | environment | data_issue | unknown` with `label_source ∈ {rule, model, human}` — only `human` is described as ground truth; `unknown` never triggers an automation hint; one incident per `(org_id, run_id, execution_key)`, retries shown as `incident_attempt` rows (T34); incident context `pending → complete | partial` settled at collection deadline + late window (T31) — while `pending` the detail view shows a "collecting context" notice, not an empty panel.

## 7. Jobs and integrations

- No client-triggered background jobs; incident settlement and context collection are server-owned (08.1.1/08.1.2/08.2.1).
- Investigation flow's evidence-revision diff reuses 09.3.1's evidence-revision selector and deep-link anchors (`#attempt-<execution_key>-<n>`) so a triager can jump straight to the run-detail attempt.
- Artifact viewer integration (09.4.1-T5) reuses the 06 isolated-origin bridge already wired by 09.1.1/09.3.1; no new bridge is built here.
- Consumed by: none listed (story blocks none per header); this story is a terminal leaf in the 09 dependency graph.
