## 1. Goal and non-goals

**Goal.** `apps/web` is a real Angular 22.2 standalone workspace project (replacing the 01.1.1-T3 placeholder) that builds a production bundle inside the W7 budgets, consumes the generated `@evidgate/sdk` through interceptors and feature data services, ships the app shell (layout, permission-aware guards, tenant/project switcher), the OIDC cookie-session login with XSRF wiring, the vi+en i18n foundation, the shared state components, the standard error patterns, web telemetry and the app-origin CSP + Trusted Types hardening. Vitest and Playwright run in CI.

**Non-goals.** Feature screens (09.2.1 onboarding, 09.3.1 run detail, 09.4.1–09.7.1); SDK generation itself (01.3.2-T1); the CI pipeline definition (01.7.1); production static hosting/CDN provisioning (owned by 10.2.1, which reuses this story's header config and E2E, T63); WCAG 2.2 AA full pass and axe suite (09.8.1); Playwright dogfooding into Evidgate ingest (09.8.1-T3).

## 2. User stories and acceptance criteria

- As a developer, `npm ci && npm run build -w apps/web` runs `ng build` and yields a production bundle inside W7 budgets, so every later web story starts from a green baseline.
- As a QA engineer, login, navigation and tenant switching work against the real session contract, so feature screens only add pages.
- As the Tech Lead, the spike ADR settles the four integration-fit questions before any feature code depends on them.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `npm ci && npm run build -w apps/web` exits 0 and produces a production bundle with initial JS ≤ 300 kB gzip and every lazy chunk ≤ 150 kB gzip; lowering a threshold in `angular.json` `budgets` below the current output size fails the build |
| AC2 | `npm run test -w apps/web` (Vitest, zoneless TestBed, no zone.js) and the Playwright config run green in CI on the built app; Vitest emits JUnit XML for dogfooding (T48) |
| AC3 | No hand-written wire DTO in `apps/web`: an ESLint rule bans `interface`/`type` declarations mirroring API payloads and any `HttpClient`/fetch use outside `core` data services and interceptors; a violating file fails lint |
| AC4 | A route guarded by `CanMatchFn` for `run:read` is not matched when the server-declared permission set lacks it and the user lands on the 403 pattern; a foreign-tenant id renders the 404 pattern, never "forbidden" (00 §9.2) |
| AC5 | A 401 during navigation triggers re-auth and returns to the original route; a cookie-authenticated mutation without `X-XSRF-TOKEN` yields the typed `csrf_failed` (403) error |
| AC6 | `ng build --localize` emits `/en/` and `/vi/` bundles; the key-completeness check exits 1 on a missing key in either locale; the locale switch navigates to the other prefix |
| AC7 | E2E asserts the app-origin CSP headers (no `unsafe-inline`/`unsafe-eval` in `script-src`, style nonce, `connect-src` allowlist, `frame-ancestors 'none'`) and a Trusted Types policy; a template injection probe cannot reach the DOM |
| AC8 | `DecisionChip` renders only the value it is given: a `pending` evaluation shows `pending` and no element renders `PASS`/`FAIL`; `EvidenceBadge` shows collection completeness with separate copy (FR-09-1, FR-09-2) |
| AC9 | Before any feature screen task starts, `docs/design/web/` holds owner-approved wireframes for the six core flows (onboarding, run detail, failure inbox, healing shadow review, settings, release view) and `apps/web/src/styles/tokens.css` defines every colour, type, spacing, radius, elevation and breakpoint token for light and dark themes; a lint rule fails on a raw hex colour or px spacing literal in a component style outside `tokens.css` |
| AC10 | `npm run start:fixtures -w apps/web` serves the app with no API running: every SDK call is answered from `fixtures/` golden responses by a dev-only fixture backend; the production build contains no fixture code (bundle grep), and a fixture that no longer validates against `contracts/openapi.yaml` fails `npm run test -w apps/web` |

## 4. Data model and migrations

None (no database objects). Web structure delivered instead (W1):

```
apps/web/src/app/
  core/            auth (SessionStore, guards, login flow), http/ (interceptors),
                   error mapping, i18n, layout (shell, nav, switchers)
  shared/ui/       presentational components: EvidenceBadge, DecisionChip,
                   status pills, missing-reason list, hash/revision chips,
                   waiver banner, label chips, empty/error/403/404/412/429 patterns
  features/<area>/ lazy route + SignalStore + pages (stubs only in this story)
```

Routes delivered: `/login`, `/auth/callback`, `/` (shell) with lazy `features/*` stubs behind `CanMatchFn` permission guards; wildcard → 404 pattern.

## 5. API shapes (commands, queries, endpoints)

No server endpoints. Client surface:

| Element | Shape |
|---|---|
| Route guards | `permissionGuard(perm: string): CanMatchFn` reading the server-declared permission set in `SessionStore`; non-match → 403 route; `authGuard: CanMatchFn` → `/login` with `returnUrl` |
| `SessionStore` (@ngrx/signals) | state: `user`, `memberships`, `permissions`, `currentOrg`, `currentProject`, `locale`, `sessionState`; methods: `login(returnUrl)`, `logout()`, `switchOrg(o)`, `switchProject(p)`, `reauth()` |
| Data services | one per feature domain over `@evidgate/sdk` generated functions; no wire types defined in `apps/web` (FR-09-10) |
| Interceptors (functional, `HttpClient`) | (a) `X-Request-Id`/`traceparent` on every call; (b) `Idempotency-Key` on mutations, generated once per user intent; (c) `withXsrfConfiguration` sends `X-XSRF-TOKEN`; (d) error mapper 00 §9.2 envelope → typed UI errors incl. 401, 403 `csrf_failed`, 404, 409 `idempotency_conflict`, 412 with `details`, 429 + `Retry-After`, 503 |

## 6. States and transitions

- Session: `anonymous → authenticating → authenticated → expired|revoked` (00 §8.9); `expired` re-auths preserving the route, `revoked`/logout lands on `/login`.
- UI request state per load: `idle → loading → ready | error(code)`; 412 and 429 are first-class states rendered by the standard patterns, never swallowed.

## 7. Jobs and integrations

- `packages/sdk` generated by 01.3.2-T1 from `contracts/openapi.yaml`; `apps/web` consumes it as a workspace dependency.
- Auth endpoints (`/v1/auth/*`, OIDC login + session cookie) come from 02.3.1-T1.
- npm registry only (`.npmrc`, `npm ci`); NuGet untouched here.
- Web-vitals (LCP/INP) and the API error funnel emit the SLIs plan 10 records (T39); CI runs Vitest + Playwright (01.7.1) and Vitest JUnit XML feeds the dogfood ingest later (T48, R10).

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| T38 / W6 session | `__Host-` `HttpOnly; Secure; SameSite=Lax` cookie set by the API; `withXsrfConfiguration` sends `X-XSRF-TOKEN`; no token stored client-side | AC5, `xsrf` E2E assertion |
| FR-09-15 / W6 app origin | strict CSP (no `unsafe-inline`/`unsafe-eval`, style nonce, `connect-src` allowlist, `frame-ancestors 'none'`) + Trusted Types, verified in E2E | AC7 |
| Sanitizer rule (F-09-4) | `angular-eslint` rule forbids `bypassSecurityTrust*` outside the reviewed viewer bridge | AC3 lint run, T10.1 |
| 00 §9.2 tenant privacy | foreign-tenant ids render 404, never 403; error screens never echo request bodies | AC4 |
| W7 / T39 budgets | `angular.json` `budgets` fail the build past 300 kB initial / 150 kB lazy gzip; `@for … track`, CDK virtual scroll primitive ready | AC1, NFR-09-1 |
| T40 supply chain | `npm ci` + committed `package-lock.json`; dependency-confusion-safe single registry; CycloneDX SBOM coverage is 11.6.1's, this story only keeps the lock clean | AC1 |
| T47 boundaries | `angular-eslint` enforces W1 (no feature→feature import) and the no-hand-written-DTO rule | AC3 |
| Telemetry privacy | vitals/error attributes carry ids only (project, run), never content or PII | `telemetry.spec.ts` |
| Retention/deletion | none; no data persisted beyond the profile locale preference (02 owns it) | — |

**DoR review answers** (00 §12, `plans/features/README.md` §6):

- **Authorization:** the app shell's `CanMatchFn` guards read server-declared permissions as a convenience only; every call is authorised by the API pipeline. The T12 fixture backend exists only in the `fixtures` build configuration and is absent from production bundles.
- **Retention/deletion:** none; the only persisted user setting is the locale preference stored by 02.3.1-T3.
- **Telemetry:** web vitals and the API error funnel (T9) with ids only, never content or PII.
- **Failure path:** 401 → re-auth returning to the same route, 403/404/412/429 rendered by the shared patterns of T8; a failed locale save keeps the current prefix and shows the error.
