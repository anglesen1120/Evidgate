## 1. Goal and non-goals

**Goal.** Every dependency Evidgate ships or hosts — NuGet and npm alike — is a recorded, licence-checked, version-pinned decision: CI refuses an unlocked restore, an unreviewed licence, or an unpinned GitHub Action, and every release carries a CycloneDX SBOM plus a documented vulnerability triage cadence.

**Non-goals.** Choosing the CI pipeline itself (01.7.1); the compatibility/licence ADR-0002 register and per-package evidence collection (01.1.1-T1, 01.9.1); CodeQL/SAST scanning (11.7.1-T2); container base image selection and digest pinning (10.2.1); the untrusted-CI fork-PR credential boundary (11.2.1).

## 2. User stories and acceptance criteria

- As the Tech Lead, I cannot merge a PR that adds an unlocked or unlicensed dependency in either ecosystem, so a licence or supply-chain problem is caught before it ships.
- As a release engineer, I can hand a customer or auditor a signed SBOM for any tagged release and point to a documented patch cadence.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `npm ci` and `dotnet restore --locked-mode` both fail (non-zero exit) when `package-lock.json` / `packages.lock.json` is stale relative to the manifest; CI job `supply-chain` runs both on every PR |
| AC2 | A PR adding an npm or NuGet package with a licence outside the allowlist (MIT, Apache-2.0, BSD-2/3, ISC, MPL-2.0 and other DECISIONS §4 approved SPDX ids) fails the `licence-gate` CI job with the package name and licence in the log |
| AC3 | Every workflow file under `.github/workflows/` references third-party actions by full 40-character commit SHA (`actions/checkout@<sha>  # vX.Y.Z`), never a tag or branch; `scripts/check-action-pins.sh` fails on a tag/branch reference |
| AC4 | Dependabot (or equivalent) is configured for `npm`, `nuget` and `github-actions` ecosystems in `.github/dependabot.yml`; a manual trigger opens update PRs for at least one outdated package in a seeded fixture repo |
| AC5 | Tagging a release (`git tag vX.Y.Z`) runs a CI job that publishes `sbom-nuget.cdx.json` and `sbom-npm.cdx.json` (CycloneDX 1.6) as release assets; both validate against the CycloneDX JSON schema |
| AC6 | Published CLI/adapter/SDK npm packages carry build provenance (npm's `--provenance` via the "Trusted Publishing" OIDC flow ⚠️ verified against npm's current provenance docs in T3.2); `npm audit signatures` on a fresh install reports the packages as provenance-verified |
| AC7 | A documented vulnerability triage SLA (`docs/security/vuln-triage-sla.md`) states time-to-fix per severity (critical/high/medium/low) and a base-image refresh cadence; a critical finding raised past its SLA window fails a scheduled CI check that diffs finding age against the SLA table |

## 4. Data model and migrations

None. No database objects in this story; all artifacts are files in the repository and CI job outputs (SBOM JSON, SLA markdown).

## 5. API shapes (commands, queries, endpoints)

None. Developer/CI-facing commands only:

| Command | Effect |
|---|---|
| `npm ci` / `dotnet restore --locked-mode` | AC1 lockfile-drift gate |
| `scripts/check-licences.sh --ecosystem npm\|nuget` | AC2 licence-allowlist gate, exit 1 listing offending packages |
| `scripts/check-action-pins.sh` | AC3 SHA-pinning gate |
| `dotnet list package --vulnerable --include-transitive --deprecated --outdated` (or `dotnet nuget audit`) | NuGet vulnerability/deprecation scan feeding T4.1 triage |
| `scripts/generate-sbom.sh --ecosystem npm\|nuget --out sbom-<ecosystem>.cdx.json` | AC5 SBOM generation on tag |
| `scripts/check-vuln-sla.sh` | AC7 SLA-age gate, scheduled |

## 6. States and transitions

None. Dependabot update PRs and vulnerability findings are tracked as GitHub issues/PRs with their own native open/closed lifecycle; no Evidgate-owned state machine.

## 7. Jobs and integrations

- CI job `supply-chain` (PR-triggered): `npm ci`, `dotnet restore --locked-mode`, `scripts/check-licences.sh` for both ecosystems, `scripts/check-action-pins.sh` (AC1–AC3).
- CI job `sbom` (tag-triggered): CycloneDX generation for both ecosystems + npm provenance publish (AC5, AC6).
- Scheduled CI job `vuln-triage` (daily): `dotnet list package --vulnerable`, `npm audit`, diffs open findings against `docs/security/vuln-triage-sla.md` (AC7); posts to the security-events channel used by 11.5.1.
- Dependabot config (`.github/dependabot.yml`) opens update PRs for npm, nuget, github-actions weekly; each PR re-runs `supply-chain` (self-reinforcing with AC1–AC3).
- Consumed by: 01.9.1 (ADR-0002 register cross-checked against the licence allowlist), 10.2.1 (base-image digest refresh feeds T4.2), 11.7.1-T2 (CodeQL runs alongside `supply-chain` in the same workflow file, no duplicate checkout).

## 9. Test plan

| Behaviour / boundary / failure | Test |
|---|---|
| Lockfile drift rejected (both ecosystems) | AC1: bump a version in `package.json`/`Directory.Packages.props` without regenerating the lock file, expect non-zero exit |
| Disallowed licence rejected (both ecosystems) | AC2: add a fixture package with an AGPL `licence` field/SPDX id, expect `licence-gate` exit 1 with the package name |
| Unpinned action rejected | AC3: add a workflow step referencing `actions/checkout@v4` (tag, not SHA), expect `check-action-pins.sh` exit 1 |
| Dependabot wired for all three ecosystems | AC4: `dependabot.yml` schema-validated; manual "Check for updates" run against a fixture repo with one outdated npm package opens a PR |
| SBOM produced and schema-valid on tag | AC5: push a fixture tag, assert both `sbom-*.cdx.json` release assets exist and pass `cyclonedx validate` |
| npm provenance on publish | AC6: publish a fixture package through the Trusted Publishing flow, run `npm audit signatures`, expect "verified" |
| SLA breach detected | AC7: seed a fixture finding dated past its severity's SLA window, run `check-vuln-sla.sh`, expect exit 1 naming the finding |

No product tests (no product code in this story; all checks run in CI against the repository and its manifests).

## 11. Rollout

- No feature flag (CI/release tooling only, no runtime behaviour). Merge order: T1 → T2 in one PR series (lockfiles + pinning are prerequisites for every later PR); T3 and T4 land before the first tagged release, in either order.
- Monitoring: `vuln-triage` scheduled job result surfaces in the security-events feed (11.5.1); SBOM publish failure blocks the release workflow.
- Rollback: revert the workflow/script PR; no data or deployed state is affected. A licence-gate false positive is fixed by updating the allowlist in the same PR that surfaced it, never by disabling the gate.
