## 1. Goal and non-goals

**Goal.** Make auditability a product guarantee: fix the audit-event taxonomy and immutability approach (append-only, hash-linked per T8, stated retention); verify support access is scoped, expiring, tenant-visible and per-read audited on top of 02.8.1; turn the 11.1.1-T4 security-event baseline into alerts with an on-call route; write the break-glass and quarterly operator-access-review procedures; and ship `GET /v1/orgs/{o}/security-events` so a `tenant_admin` can answer "who saw what" from the API.

**Non-goals.** The audit core tables/writer (02.7.1), the support-grant endpoints (02.8.1), the audit/security-events web views (09.7.1-T6/T9), the alert routing machinery (10.3.1-T5 — this story defines the rules), breach procedure (11.9.1-T2).

## 2. User stories and acceptance criteria

- As a `tenant_admin`, I list my org's security events filtered by project/type/severity/time, so suspicious access is visible to me, not just to Evidgate.
- As the Tech Lead, the audit log's append-only chain is mechanically verifiable, so tamper-evidence is provable.
- As a customer, every operator access into my tenant carries a scope, an expiry and an audit row I can see.

## 4. Data model and migrations

Owned by this story (T5), `migrations/NNNN_security_security_event.sql` (placeholder number):

```sql
create table security_event (
  id          uuid primary key,              -- UUIDv7
  org_id      uuid not null,
  project_id  uuid,
  type        text not null,                 -- auth_failure | cross_tenant_probe | secret_scanner_alert | kill_switch_used | support_access | injection_attempt (V2)
  severity    text not null,                 -- info | warning | critical
  actor       jsonb not null,                -- kind, id; no secrets
  details     jsonb not null default '{}',   -- hashes/counts only, never raw payload/secret
  request_id  text,
  created_at  timestamptz not null default now(),
  updated_at  timestamptz not null default now(),
  version     int not null default 1,
  unique (org_id, id)                        -- T3 composite-FK target
);
alter table security_event enable row level security;
alter table security_event force row level security;   -- DECISIONS F5
create policy tenant_isolation on security_event
  using (org_id = evidgate.current_org_id());          -- T2 helper
create index security_event_list_idx
  on security_event (org_id, project_id, type, severity, created_at desc, id);  -- P4: serves AC3 filters + keyset order
```

Reviewed (owner 02.7.1): `audit_event` — `unique (org_id, seq)` + `unique (org_id, id)`, `prev_hash`/`row_hash`, `REVOKE UPDATE, DELETE` from the app role (immutability enforced in SQL per C6), chain serialised by `pg_advisory_xact_lock(hashtext('audit:' ‖ org_id))` last before commit (T8). Reviewed (owner 02.8.1): `support_grant` — scope/expiry columns, states per 00 §8.9, `unique (org_id, id)`, audited transitions.
