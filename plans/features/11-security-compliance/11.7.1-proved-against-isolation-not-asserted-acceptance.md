## 1. Goal and non-goals

**Goal.** Tenant isolation is demonstrated, not claimed: an automated red-team suite attacks every cross-tenant path (API, foreign keys, RLS, read-model views, list/search, presigned URLs, artifact ids) on real PostgreSQL and runs green in CI; static and dynamic analysis covers both codebases; and an external penetration test with closed criticals/highs stands as a pilot-exit gate.

**Non-goals.** Building the RLS/tenancy machinery itself (01.4.1, 02.6.1, 02.9.1); the threat model that enumerates what to attack (11.1.1); fixing findings in other modules (each finding lands in its owning module's backlog — this story owns the harness and the gate); the sandbox/VM boundary verification for hosted multi-tenant execution (11.2.1-T5, V3).

## 4. Data model and migrations

None. The suite seeds fixture data through the normal API/domain paths into the existing schema (two orgs, projects, runs, artifacts, memberships, support grants). No new tables or migrations; test databases are disposable Testcontainers instances reset with Respawn between test classes.

## 5. API shapes (commands, queries, endpoints)

None added. The suite *consumes* existing endpoints as an attacker would:

| Surface attacked | Probe |
|---|---|
| Read endpoints (`GET /v1/runs/{r}`, `/decision`, `/artifacts/{a}/download-url`, project lists, case lists) | org-A principal + org-B id → expect 404 |
| Mutations (`POST /v1/runs/{r}/cancel`, `/events`, `/finalize`, candidate/waiver/quarantine writes) | org-A principal + org-B id → expect 404/403, verify zero writes via probe query |
| Cursor/list/search endpoints | assert every returned `items[]` row belongs to the caller's org (response and raw view compare) |
| Presigned URL path | `GET /v1/artifacts/{a}/download-url` for foreign id refused; replayed foreign URL serves nothing |
| Raw DB path | direct Npgsql calls as the app role: cross-tenant `SELECT` → 0 rows, cross-tenant `INSERT`/`UPDATE` → RLS/FK violation |

## 6. States and transitions

None owned. The suite exercises existing state machines adversarially (e.g., cancel a foreign run, finalize a foreign producer slot per T9, read a foreign artifact mid-`pending_delete`) but adds no states.

## 7. Jobs and integrations

- CI job `isolation-redteam` (every PR + nightly against `develop`): builds the suite, provisions Testcontainers.PostgreSQL, runs all AC1–AC5 cases; wired into the same workflow as `supply-chain` (11.6.1) — no duplicate checkout.
- CI job `codeql` (PR + schedule): GitHub CodeQL for C# and TypeScript; results feed the vuln triage SLA (11.6.1-T4).
- Scheduled `dast-baseline` job (weekly): OWASP ZAP baseline scan ⚠️ tool choice and licence recorded in ADR-0002 against the staging deployment (10.1.1, 10.2.2).
- Pen-test facilitation during the M3 window: a named responder lane triages findings daily; criticals get an immediate fix lane, not a backlog ticket.
- Consumed by: 11.1.1 (threat-model rows point at these suite cases as their controls), the M3 pilot-exit gate (AC7), and 09.7.1 (security-events surfaced to tenants are among the probed read surfaces).

- **Authorization:** the probes run as the non-owner app role against real principals and assert the 404/403 split per route (AC2); this hand-over adds no route and no grant — the CSRF sub-item tests an existing policy decision, not a permission.
- **Retention/deletion:** none; the hand-over adds a test and a policy test, and the findings live in the existing triage document (`docs/security/sast-dast-triage.md`) under the 11.6.1-T4 SLA.
- **Telemetry:** none new; a failed CSRF assertion fails the suite like any other test and is reported through the existing CI and DAST triage path (no new counter, no new event type).
- **Failure path:** with the pair required for cookie+`Authorization` requests, a missing or wrong pair must answer the existing 403 `csrf_failed` and must not rotate the session — the sub-item asserts exactly that (no session row changes, no `Set-Cookie`).
