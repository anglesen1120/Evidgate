## 1. Goal and non-goals

**Goal.** A team starting on Evidgate can seed history from past JUnit XML or Playwright JSON reports. Each imported report set becomes a run with `purpose = import`, an explicit commit, branch and time supplied by the importer, parsed by the normal adapter parsers (04.4.x), stored as immutable evidence, projected into `case_result_history` (03.9.1) as baseline seed, and **never** evaluated, bound to a release, or turned into a decision. Today `ingest_only` needs a live run and manifest (review D10); this adds the missing path.

**Non-goals.** Import of results into an existing live run; import of artifacts (screenshots, traces) beyond the report files themselves; retroactive release decisions; Git history crawling (the importer supplies commit/branch/time); billing and quota policy design (12; this story only guarantees usage rows are its own); reprocess of stored reports (04.4.2).

## 2. User stories and acceptance criteria

- As a QA lead, I upload last month's reports with commit, branch and time so the first real run shows "new failure vs failing on main".
- As a release manager, I am sure imported data can never turn a gate green or red.
- As an engineer, I can dry-run an import locally and see what would be created before sending anything.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `POST /v1/projects/{p}/imports` with an archive and a metadata list `[{path, commit_sha, branch, started_at, finished_at}]` creates one run per distinct `(commit_sha, branch, finished_at)` group with `purpose = import`, `ci_run_ref = null`, and an `import_batch_id`; response 202 `{batch_id, runs_planned}` |
| AC2 | Missing or malformed commit, branch or time, a time in the future or older than the history window, or a file path outside the archive root returns 422 `schema_invalid` naming the entry; nothing is created (all-or-nothing validation before any write) |
| AC3 | Imported runs are never evaluated: no `evaluation` row is created, `POST /v1/runs/{r}/finalize` and any release binding on an import run return 409 `run_purpose_forbidden`, and the evaluation scheduler excludes `purpose = import` by a predicate covered by a test |
| AC4 | Imported results appear in `case_result_history` with `is_import = true`; they seed the baseline classification but are not counted as accepted execution coverage (03.1.4) and never as flake input beyond what 07 later decides |
| AC5 | The same archive imported twice (same content hash and metadata) returns the first batch (idempotent via the idempotency store, T11) and creates no new run or history row; a changed metadata for the same file hash is a new batch, flagged `duplicate_content` |
| AC6 | Caps are enforced before parsing: archive size, file count, and decompressed size ratio (zip-bomb) return 413 `payload_too_large` with the limit; defaults `[INFERENCE]`: 100 MB archive, 5 000 files, ratio 20:1 (P8) |
| AC7 | `evidgate import-history <dir|zip> --commit --branch --time --dry-run` prints runs, case counts and warnings and sends nothing; without `--dry-run` it uploads, and exceeds-cap input is refused locally with exit code 2 |
| AC8 | An import never changes any existing decision, evaluation or quota ledger row; the only ledger effect is its own usage rows (`usage_kind = import`) ; a before/after snapshot of all other rows is byte-identical |
| AC9 | Tenant isolation and permission: needs `run:import` ([OPEN] O-03.9.2-1, new string), 403 otherwise; a foreign project is 404; imports are audited with actor, batch id and file hashes |

## 6. States and transitions

Batch: `validating → accepted → done`, or `validating → rejected`; terminal states are final; repeated calls are idempotent no-ops (T82). Each import run goes `created → complete` directly after its single evidence revision is written (no `queued/running/collecting`), with `completeness` per 00 §8.5 (`unknown_manifest`), and never leaves `complete`. Reprocess (04.4.2) of an import run keeps `purpose = import`. No transition into evaluation exists for this purpose.

## 7. Jobs and integrations

- Validation in the request (cheap: caps, metadata, path checks); parsing and projection in a task-queue job after commit (P5), chunked per file so a 5 000-file archive streams (review D5).
- Parsers: the 04.4 JUnit XML and Playwright JSON parsers in `ingest_only` mode with an explicit parser version recorded; unknown or corrupt files become per-file warnings and the batch still completes if at least one file parsed ([INFERENCE]; [OPEN] O-03.9.2-4 whether any bad file should reject the whole batch).
- Case identity for imported names uses the provisional key `(producer, suite, name)` of 03.1.2; unmapped cases stay `unmapped` and appear in history only after mapping.
- CLI (T2): zip or directory walk, size and file caps before upload, `--dry-run` parsing locally with the CLI's parsers (04.2.3 spool is reused for upload retry).
- ⚠️ Exact JUnit/Playwright JSON field coverage for old reports is unverified; the T1 corpus decides it.

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| Authorization | `run:import` only, tenant-scoped, audited | AC9, 403 test |
| Evidence integrity | imports never touch existing manifests, revisions or evaluations; import runs are separate immutable runs | AC8 snapshot test |
| No decision effect | scheduler predicate + DB guard + endpoint 409 | AC3 tests |
| Untrusted input | caps before parsing, no XML external entities, path traversal and symlink rejection, zip-bomb ratio, content-type check | `Import_ZipSlip_Rejected`, `Import_XxeReport_Rejected`, AC6 |
| Privacy/redaction | report text passes the same redaction (00 §5.7, 04 redactor) as live ingest before storage; archives are not kept after parse beyond the raw-report retention | redaction test |
| Quota/abuse | per-org import rate and daily volume limit through the quota path; 429 never a silent drop | `Import_OverQuota_429` |
| P1/P2/P8 | batched inserts, streaming parse, bounded memory | 5 000-file fixture test with memory ceiling |

DoR review answers. **Authorization:** `run:import` (pending contract). **Retention/deletion impact:** import runs follow run retention; raw report files follow the raw-report policy (06.4); batches and runs are deleted with the org; history rows cascade (03.9.1). **Telemetry:** `import_batches_total{result}`, `import_files_parsed_total{result}`, `import_runs_created_total`, `import_duration_seconds`; trace attribute `import.batch_id`. **Failure path:** validation failure creates nothing; a parse failure per file is a warning; a job crash retries idempotently by `(batch_id, file_hash)` and then dead-letters with an alert; the user sees batch `state` and warnings.
