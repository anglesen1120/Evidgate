## 1. Goal and non-goals

**Goal.** A worker-side GitHub write service that, given a `dry_passed` (or `allow_unverified`) draft, mints a short-lived installation token and creates the branch, commit and pull request on the bound repository — idempotently, never touching a protected or default branch, and never persisting the token.

**Non-goals.** The public route `POST /v1/drafts/{d}/pull-request`, the draft state guard and the `allow_unverified` decision live in 03.6.1-T3 (this story provides the GitHub mechanics it calls); webhook signature verification and catalog sync are 03.4.1; merge/close reconciliation is 03.6.1-T4; GitHub App registration and the minimal permission list are 03.4.1-T1 (write scopes `contents:write` + `pull_requests:write` ⚠️ confirmed there before publish — Q5).

## 2. User stories and acceptance criteria

- As a `qa_engineer`/`test_maintainer`, my approved draft reaches the repository as a reviewable PR, so nothing bypasses the customer's normal code-review process (D10).
- As a security auditor, I can confirm no Git credential or installation token is ever stored, logged or sent inside a database transaction.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | Given draft `d` on repository bound by `git_repo_binding`, the PR task creates ref `evidgate/drafts/{d}` (never the default/protected branch), one commit with the draft files, and one PR whose body contains the draft id, `dry_run` result link and `ai_run_id` when present; `draft` row ends `pr_open` with `pr_branch`, `pr_commit_sha`, `pr_url`, `pr_number` set |
| AC2 | Re-running the task (or a duplicate `Idempotency-Key` upstream) after AC1 returns the same PR (`pr_number` unchanged, no second commit) — idempotent by `(branch, commit)` |
| AC3 | Any code path that would push to `git_repo_binding.default_branch` or a branch outside the `evidgate/` prefix aborts with `protected_branch` before any GitHub write call is made |
| AC4 | A GitHub 422 "pull request already exists" resolves to the existing PR (same `pr_number`); a 401/403 → task failure `github_forbidden`; 429/5xx → task retry with `Retry-After` backoff (dead-letter after cap, 00 §5.3) |
| AC5 | The installation token is minted per task execution from the RS256 app JWT, held only in memory for the call, and never appears in logs, `draft`, `webhook_delivery` or any table (asserted by a log-redaction test and a schema grep) |

## 3. Contracts touched

- 00 §5.3 — PR creation runs as an idempotent `task` row (`draft.pr_requested` natural key = `(org_id, draft_id, pr_commit_sha)`), never a network call inside the command's DB transaction (P5).
- 03 §4.1 — reads `git_repo_binding` (`installation_id`, `repository_id`, `default_branch`); writes the `pr_*` columns on `draft` (owned by 03.6.1-T1 schema).
- No public endpoint, no new permission, no schema change of its own.
- ⚠️ verified in 03.4.1-T1 — 03 §6 marks the App write-permission list unverified (Q5); this story assumes `contents:write` + `pull_requests:write` — confirm in 03.4.1-T1 before the App ships.

## 4. Data model and migrations

None. The PR bookkeeping columns (`pr_branch`, `pr_commit_sha`, `pr_url`, `pr_number`) live on `draft` and are created by 03.6.1-T1's migration. The task row uses the shared `task` queue (01).

## 5. API shapes (commands, queries, endpoints)

No `/v1` endpoint of its own. Internal surface, module `Evidgate.Modules.Catalog`:

| Shape | Detail |
|---|---|
| `DraftPullRequestRequested` outbox payload | `{ org_id, project_id, draft_id, base_commit, allow_unverified, reason }` written by 03.6.1-T3's command in the same transaction |
| `DraftPullRequestTaskHandler` (`Infrastructure/`) | Claims the task row; loads `git_repo_binding` inside a tenant scope (C3); runs the GitHub sequence **outside** the transaction; commits the result (`pr_open` fields or error) in a second short transaction |
| `IGitHubRepoWriter` (internal) | `CreateOrGetRef`, `CreateCommit`, `CreateOrGetPullRequest` over the typed `HttpClient` + RS256 app JWT from 03.4.1-T1 (T46); path guard rejects non-`evidgate/` branches |

GitHub calls (all `IHttpClientFactory`, timeouts + resilience handlers, P6): `POST /app/installations/{i}/access_tokens` → `POST …/git/refs` (or reuse existing `evidgate/drafts/{d}` head) → `POST …/git/blobs`, `…/git/trees`, `…/git/commits` → `POST …/pulls` (422 → `GET …/pulls?head=` for the existing PR).

## 6. States and transitions

Drives `draft`: `dry_passed | dry_failed(allow_unverified) → pr_open` (00 §8.10; the transition is committed by this task, requested by 03.6.1-T3). On terminal GitHub failure the draft state is unchanged and the task lands in `dead_letter` for operator replay; the draft keeps its last `pr_*` values untouched.

## 7. Jobs and integrations

- `task` queue handler `catalog.draft_pull_request` (00 §5.3): claimed `FOR UPDATE SKIP LOCKED`, natural idempotency key `(org_id, draft_id, pr_commit_sha)`, bounded retries → `dead_letter`.
- GitHub REST API only, via the 03.4.1 typed `HttpClient`; token TTL ≤ 1 h, minted per execution.
- Emits nothing to 06/07 — a dry run never produces official evidence; the PR body carries links only.

## 9. Test plan

| Behaviour / boundary / failure | Test |
|---|---|

| Idempotent re-run: same PR, no new commit | `CreatePullRequest_Idempotent_ByBranchCommit` |

| 429 with `Retry-After` → backoff retry | `CreatePullRequest_RateLimited_Retries` |

## 11. Rollout

- Ships with 03.6.1-T3 behind the same V2 draft workflow; no separate flag — the `task` handler is inert until the first `draft.pr_requested` row exists.
- Monitoring: `dead_letter` depth on `catalog.draft_pull_request`, GitHub 429/5xx rate, token-mint failures (metrics per 00 §11).
- Rollback: stop the handler (task rows accumulate harmlessly); no data migration to reverse; open PRs already created stay in the customer's repo by design.
