## 1. Goal and non-goals

**Goal.** The V2 authoring loop: a `draft` row edited under optimistic concurrency, exercised in a tenant-secret-free sandbox `dry_run`, and shipped to the repository only as a pull request (03.4.2); after merge or close the draft is reconciled to the catalog rows the next sync creates.

**Non-goals.** The GitHub write mechanics themselves (03.4.2-T1); AI draft provenance and permission policy (03.7.1, which consumes this draft surface); the runner/pool machinery (05.7.3/05.7.4 provide the sandbox executor contract); web screens (09.6.1); official evidence semantics (a `dry_run` never produces run evidence — 06/07 own that rule).

## 2. User stories and acceptance criteria

- As a `qa_engineer`, I edit a draft file set and my concurrent edits are protected by `ETag`/`If-Match`, so nobody silently loses work.
- As a `test_maintainer`, I dry-run the draft in a sandbox that sees no tenant secrets and produces a pass/fail result I can link in the PR.
- As an auditor, every draft reaching the repository went through a PR that names the draft and its dry-run result — nothing is pushed directly.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `PATCH /v1/drafts/{d}` with a stale `If-Match` → 412 and `error.details` carries the current `version`; with the current ETag → 200 and `version` increments |
| AC2 | `POST /v1/drafts/{d}/dry-run` on a `draft`-state draft creates one `dry_run` row + a `task` row; the sandbox gets an ephemeral `data_namespace`, a downgraded capability document, and zero tenant secrets (asserted by inspecting the dispatched payload) |
| AC3 | `POST /v1/drafts/{d}/pull-request` on a `dry_failed` draft → 422 `draft_not_dry_passed` unless the caller is `tenant_admin` and passes `allow_unverified: true` + `reason`, which is recorded on the draft and in the PR body (Q4; T46 flag name) |
| AC4 | PR creation is idempotent: a second `POST /v1/drafts/{d}/pull-request` (same `Idempotency-Key` or after a retry) returns the same `pr_url`/`pr_number` and creates no second GitHub object |
| AC5 | A merged PR (webhook `pull_request.closed` with `merged_at` + catalog sync of the merge commit) transitions `pr_open → merged` and links the new `test_case`/`test_revision` ids on the draft; a closed-unmerged PR transitions to `closed` |
| AC6 | Two concurrent `PATCH`es on one draft produce exactly one winner; the loser gets 412 (no lost update) |

## 4. Data model and migrations

`migrations/NNNN_catalog_draft.sql` (T1):

```sql
create table draft (
  id uuid primary key,
  org_id uuid not null, project_id uuid not null,
  author_membership_id uuid not null,
  kind text not null check (kind in ('template','ai','regression')),
  base_commit text not null,
  status text not null default 'draft'
    check (status in ('draft','dry_running','dry_passed','dry_failed','pr_open','merged','closed')),
  version integer not null default 1,            -- ETag source, IsConcurrencyToken
  content jsonb not null,                        -- {files: [{path, body_sha, body_ref}]}
  provenance jsonb null,                         -- template_id, ai_run_id, incident_id
  ai_run_id uuid null, dry_run_id uuid null,
  allow_unverified boolean not null default false, unverified_reason text null,
  pr_branch text null, pr_commit_sha text null, pr_url text null, pr_number integer null,
  linked_case_id uuid null, linked_revision_id uuid null,
  created_at timestamptz not null default now(), updated_at timestamptz not null default now(),
  unique (org_id, id),                           -- T3, composite FK target
  foreign key (org_id, linked_case_id) references test_case (org_id, id)
);
create index draft_project_list on draft (org_id, project_id, created_at, id);      -- P4 list query
create index draft_status on draft (org_id, project_id, status);                    -- UI filter
alter table draft enable row level security;                                      -- FORCE + tenant policy
```

`migrations/NNNN_catalog_dry_run.sql` (T2):

```sql
create table dry_run (
  id uuid primary key,
  org_id uuid not null, project_id uuid not null,
  draft_id uuid not null, foreign key (org_id, draft_id) references draft (org_id, id),
  sandbox_ref text not null,                     -- executor and job ref from 05.7.4-T2
  namespace_id uuid null,                        -- ephemeral data_namespace
  state text not null check (state in ('queued','running','passed','failed','error','timeout')),
  result_evidence jsonb null,                    -- pass/fail + output refs; never official evidence
  started_at timestamptz null, finished_at timestamptz null,
  unique (org_id, id)
);
create index dry_run_draft on dry_run (org_id, draft_id, created_at, id);
alter table dry_run enable row level security;
```

## 5. API shapes (commands, queries, endpoints)

| Shape | Type | Endpoint | Permission · codes |
|---|---|---|---|
| `CreateDraft` | `ICommand<Guid>` | `POST /v1/projects/{p}/drafts` | `draft:write` · 201; `Idempotency-Key` required (T11) · 422 `draft_invalid` |
| `UpdateDraft` | `ICommand<int>` (new `version`) | `PATCH /v1/drafts/{d}` | `draft:write` · 200 / 412 stale ETag (`details.current_version`) / 404 |
| `ListDrafts`, `GetDraft` | `IQuery` (Dapper, read-only) | `GET /v1/projects/{p}/drafts`, `GET /v1/drafts/{d}` | `case:read` · cursor pagination `(created_at, id)`, index `draft_project_list` |
| `RequestDryRun` | `ICommand<Guid>` | `POST /v1/drafts/{d}/dry-run` | `draft:dry_run` · 202 + `dry_run_id`; 409 `draft_state_conflict` unless `draft`/`dry_failed` |
| `ListDryRuns` | `IQuery` | `GET /v1/drafts/{d}/dry-runs` | `case:read` |
| `RequestPullRequest` | `ICommand` | `POST /v1/drafts/{d}/pull-request` | `draft:merge_request` · 202; 422 `draft_not_dry_passed` without `allow_unverified`+`reason` (Q4); `Idempotency-Key` |

`RequestDryRun` and `RequestPullRequest` are enqueue-only commands: they write the `dry_run` row / `draft.pr_requested` outbox row in the same transaction (C7); all network work happens in the task handler (P5).

## 6. States and transitions

`draft`: `draft → dry_running` (dry-run requested) `→ dry_passed` or `dry_failed` (task result) `→ pr_open` (PR task committed) `→ merged` or `closed` (reconcile, T4). Refinements: `dry_failed → dry_running` on re-request; `pr_open → draft` when the PR is withdrawn before merge. `dry_run` lifecycle: `queued → running → passed`/`failed`/`error`/`timeout`; a `dry_run` is append-only evidence of the attempt — re-runs create a new row and repoint `draft.dry_run_id`. Every draft transition writes an audit row via 02.7.1-T2.

## 7. Jobs and integrations

- `catalog.dry_run_dispatch` task: claims the queued `dry_run`, allocates an ephemeral `data_namespace` (`expires_at = sandbox deadline + grace`, reusing 03.3.1-T2), submits the job to the 05.7.4-T2 executor with a downgraded capability document and **no tenant secret resolution**, then collects the result into `result_evidence` and transitions the draft.
- `catalog.draft_pull_request` task: hands off to 03.4.2-T1's GitHub writer (idempotent by `(branch, commit)`).
- `catalog.draft_reconcile` task: on webhook `pull_request.closed` (03.4.1-T2 receiver) or post-merge `catalog_sync` completion, links `linked_case_id`/`linked_revision_id` and sets `merged`/`closed`.
- `draft_expiry_sweep` Cronos schedule (00 §5.3, unique `(schedule_name, fire_at)`): abandons drafts `pr_open`/`draft` untouched > N days (N to be set with 09 UX) — V2 optional, listed for capacity planning.

## 11. Rollout

- Whole story is V2/M4; draft endpoints land behind the `draft:*` permissions seeded with the role data (02); UI ships in 09.6.1 after these endpoints exist.
- Monitoring: `dry_run` state distribution, sandbox executor latency, `catalog.dry_run_dispatch`/`draft_pull_request`/`draft_reconcile` dead-letter depth, draft→PR conversion time.
- Rollback: feature-flag the three write endpoints off (or revoke `draft:*` grants); `draft`/`dry_run` rows stay readable; no migration rollback needed (additive tables).
