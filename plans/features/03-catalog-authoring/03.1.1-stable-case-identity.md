## 1. Goal and non-goals

**Goal.** A test case has one durable UUID identity per project that survives file renames and moves. The id comes from the `evidgate.id` annotation or, equivalently, from a per-directory sidecar manifest `evidgate.cases.yaml` sitting next to the test files it describes (T55); both present and different is a conflict, never a silent pick (00 §7, D1). The identity source and every rename/move are recorded for audit and for the 09 UI.

**Non-goals.** `test_revision` immutability and hashing (03.1.3); provisional identities for imports without ids and their mapping UI contract (03.1.2); webhook reception and tree walking (03.4.1); suite membership (03.2.1); any screen (09.2.1 renders this contract).

## 2. User stories and acceptance criteria

- As a QA engineer, I rename or move a test file and its history, runs and evidence stay attached to the same case, so refactors are free.
- As a test maintainer, I can see *why* a case is the same case (which source produced the id), so duplicate-id mistakes are diagnosable.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | A file annotated `evidgate.id: <uuid>` registers one `test_case` row with `annotation_id` = that UUID; a later commit that only renames/moves the file produces **no** new `test_case` and exactly one `case_rename_history` row (`from_path`, `to_path`, `commit_sha`) |
| AC2 | Two files declaring the same id in one commit produce a `duplicate_case_id` conflict entry per offending path in the sync report; neither file writes a `test_revision`; previously stored revisions and case state are untouched |
| AC3 | A sidecar manifest `evidgate.cases.yaml` in a directory maps the test files in that directory (`file` paths relative to the manifest's own directory) to `evidgate.id` values; it is an equivalent source, and its entries create `case_identity_source` rows with `source = 'sidecar'` |
| AC4 | Annotation and sidecar present with different ids for the same file → conflict `id_source_conflict`, no silent pick, no revision written |
| AC5 | A malformed annotation or a sidecar entry naming a non-existent file produces a sync warning (`invalid_annotation` / `invalid_sidecar_entry`), no case is created for it, and all other files are still processed |
| AC6 | `UPDATE test_case SET annotation_id = …` or `file_path`/`first_seen_commit` as the app role raises `case_identity_immutable` (trigger); metadata columns (`name`, `owner_membership_id`, `status`) stay writable |
| AC7 | `GET /v1/projects/{p}/cases` lists cases ordered `(created_at, id)` with cursor pagination; `GET /v1/cases/{c}` in another org returns 404; a stale `If-Match` on `PATCH /v1/cases/{c}` returns 412 with the current `version` in `error.details` |

## 4. Data model and migrations

`migrations/NNNN_catalog_case_identity.sql` (DbUp, owner role):

```sql
create table test_case (
  id uuid not null, org_id uuid not null, project_id uuid not null,
  annotation_id uuid not null, name text not null, framework text not null,
  language text, file_path text,
  status text not null default 'active' check (status in ('active','missing','archived')),
  owner_membership_id uuid, first_seen_commit text not null, last_seen_commit text,
  created_at timestamptz not null default now(), updated_at timestamptz not null default now(),
  version int not null default 1,
  primary key (org_id, id), unique (org_id, id),              -- T3: composite-FK target
  unique (org_id, project_id, annotation_id),
  foreign key (org_id, project_id) references project (org_id, id),
  foreign key (org_id, owner_membership_id) references membership (org_id, id)
);
create index test_case_list on test_case (org_id, project_id, status, created_at, id); -- serves GET cases (P4)

create table case_identity_source (
  id uuid not null, org_id uuid not null, case_id uuid not null,
  source text not null check (source in ('annotation','sidecar','imported')),
  raw_key text not null, commit_sha text not null,
  created_at timestamptz not null default now(),
  primary key (org_id, id), unique (org_id, id),
  foreign key (org_id, case_id) references test_case (org_id, id)
);
create index case_identity_source_case on case_identity_source (org_id, case_id);

create table case_rename_history (
  id uuid not null, org_id uuid not null, case_id uuid not null,
  from_path text not null, to_path text not null,
  commit_sha text not null, detected_at timestamptz not null default now(),
  primary key (org_id, id), unique (org_id, id),
  foreign key (org_id, case_id) references test_case (org_id, id)
);
create index case_rename_history_case on case_rename_history (org_id, case_id, detected_at);
```

- RLS on all three: `FORCE ROW LEVEL SECURITY` + policy `org_id = evidgate.current_org_id()` (T2); they are **not** on the platform-catalogue exception list, so the 02.6.1-T2 lint must pass them.
- Immutability: trigger `catalog_case_identity_guard` raises `case_identity_immutable` on UPDATE touching `id`, `org_id`, `project_id`, `annotation_id`, `first_seen_commit`; `case_identity_source` and `case_rename_history` get `revoke update, delete` from the app role plus the same trigger (append-only, C6).
- `name` uniqueness is deliberately absent: two same-named tests are normal (D2); identity is `annotation_id` only.

## 5. API shapes (commands, queries, endpoints)

| Shape | Endpoint / caller | Rule |
|---|---|---|
| `ListCasesQuery : IQuery<Page<CaseListItem>>` | `GET /v1/projects/{p}/cases` · `case:read` | Dapper, read-only tx (C5); `?status=&framework=&cursor=&limit=`; 200; filters covered by `test_case_list` index |
| `GetCaseQuery` | `GET /v1/cases/{c}` · `case:read` | 200 or 404 (other-tenant indistinguishable, S-by-convention) |
| `GetCaseRevisionsQuery` | `GET /v1/cases/{c}` revisions · `case:read` | 200 `[]` until 03.1.3 writes `test_revision` rows |
| `UpdateCaseCommand : ICommand<CaseHead>` | `PATCH /v1/cases/{c}` · `case:write` | `If-Match` on `version` required → 412 stale (00 §9.1); mutates `name`, `owner_membership_id`, `status` (`active`/`archived` only; `missing` is system-set), labels; id/path/`annotation_id` fields rejected 422 `case_field_immutable` (new code, registered in `contracts/openapi.yaml`) |
| `ICaseIdentityService.RegisterDiscoveredAsync(commit, DiscoveredCase[])` | called by 03.4.1-T3 sync handler, same tenant transaction | upserts `test_case` + `case_identity_source`, appends `case_rename_history`, sets `status`, returns per-file result `registered | renamed | duplicate_case_id | id_source_conflict | warning` |

Annotations: `evidgate.id` accepted in line/block comments of the supported source languages and in framework decorators; exactly one annotation per file; a second annotation in the same file is `id_source_conflict` (never a silent pick).

## 6. States and transitions

`test_case.status`: `active → missing` (file vanished from synced tree), `missing → active` (id reappears), `active | missing → archived` (PATCH only; `archived` cases stay readable). `case_identity_source` and `case_rename_history` are append-only with no state. `case_import_identity` states belong to 03.1.2.

## 7. Jobs and integrations

- No jobs of its own: `RegisterDiscoveredAsync` runs inside the 03.4.1-T3 `catalog_sync` task transaction; the T2 detection logic is exercised through that service, so this story is fully testable before the webhook exists.
- Audit: PATCH and every sync-driven status change emit audit rows via 02.7.1-T2.
- 04.3.2-T1 consumes the annotation/sidecar rules to compute producer-side identity.
