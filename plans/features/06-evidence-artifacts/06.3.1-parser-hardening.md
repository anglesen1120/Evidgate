## 1. Goal and non-goals

**Goal.** Every parse of untrusted artifact bytes inside the server — XML/JUnit reports, JSON payloads, zip archives (Playwright trace, report bundles) — goes through one enforced safe-parser profile in `Evidgate.Modules.Evidence`: external entities and DTDs are impossible, the depth, size and entity caps are hard limits and the 30 s time cap is cooperative (checked between reads and per node; hard isolation is 06.3.6), archive extraction never writes outside its root, and the sniffed signature must match the declared media type. A hostile artifact costs bounded CPU and memory and ends `rejected`, never `ready`.

**Non-goals.** The hostile fixture corpus and fuzz run (06.3.2); the isolated viewer origin and per-kind serving (06.3.3, 06.3.4); the JUnit event mapping and report comparison logic itself (04.4.1); secret scanning of content (06.2.3); adapter-side parsing in the Node CLI (04, separate runtime).

## 2. User stories and acceptance criteria

- As the Tech Lead, I want every code path that opens untrusted XML/JSON/zip bytes to be physically unable to resolve external entities, so XXE and SSRF-via-parser are structurally excluded.
- As a reviewer, I want the caps enumerated and tested, so a regression in any guard fails the build.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | An XML body containing `<!DOCTYPE`/`<!ENTITY` is rejected: `XmlReader` is created with `DtdProcessing.Prohibit` and `XmlResolver = null` (the guards asserted on the one settings object the profile builds), and a hostile DTD/entity payload is refused `dtd_prohibited` with bounded allocation — no external-resolution call can occur because the profile exposes no resolver and no fetch API |
| AC2 | Depth, size and wall-time caps are enforced: input deeper than the profile depth (default 64), larger than the kind's `max_bytes` from `artifact_kind_policy`, or slower than the parse timeout returns `Result` failure (`artifact_invalid` / `payload_too_large`, 00 §9.2), never an unhandled exception. The wall-time cap is cooperative — checked between reads and per node, so it cannot interrupt a blocking `Stream.Read` or one `JsonDocument.Parse` call (06.3.6) |
| AC3 | A zip with more than the entry cap (10 000), total expanded size above the cap (512 MiB), a per-entry compression ratio above 100:1, or a nested-archive depth above 2 is rejected before any entry is written to disk |
| AC4 | Archive entry names are normalized and entries containing `..`, an absolute path, a drive letter or `\` separators are rejected; no byte lands outside the extraction root |
| AC5 | The sniffed magic bytes must match the declared `media_type`; a mismatch at `complete` leaves the artifact `rejected` with `failure_code = media_type_mismatch` and is never counted as evidence |
| AC6 | Parsing is streamed and bounded: a guard test parses the largest allowed fixture while asserting peak managed allocation stays under the per-kind cap ×2 |

## 4. Data model and migrations

None. The profile reads `artifact_kind_policy.max_bytes` / `media_types` (table owned by 06.1.1, unchanged) and stores rejections in `artifact.failure_code` (existing column). Cap defaults that are not per-kind live as module constants (`ParsingLimits`: `MaxDepth = 64`, `MaxZipEntries = 10_000`, `MaxExpandedBytes = 512 MiB`, `MaxCompressionRatio = 100`, `MaxNesting = 2`, `MaxEntryNameLength = 1024`, `MaxEntryNameSegments = 64`, `ParseTimeout = 30 s`).

## 5. API shapes (commands, queries, endpoints)

No new endpoint. The profile is invoked inside existing command/handlers:

| Consumer | Use |
|---|---|
| `CompleteArtifactCommand` handler (06.1.2) | sniffs magic bytes vs declared `media_type` on the `pending/` object stream before `ready`; mismatch → `rejected` (`media_type_mismatch`) |
| `IParsing.ParseXmlReport` (04.4.1 raw-report parse, `reprocess`, comparison) | `XmlReader` profile over a capped stream |
| `IParsing.EnumerateArchive` (06.3.4 trace/report serving, 06.4.3 sweeper) | entry allowlist + path normalization + caps |
| `IParsing.ParseJson` | `JsonDocument` with `MaxDepth`, duplicate property names rejected (`AllowDuplicateProperties = false`) and a pre-read size cap |

Failures are `Result` values mapped once to the 00 §9.2 envelope (C8); no `ProblemDetails`, no parser exception escaping a handler.

## 6. States and transitions

None new. The story only writes `artifact.state = rejected` + `failure_code` through the existing `uploaded → rejected` transition (00 §8.4, 06 §4 states). `rejected` remains terminal.

## 7. Jobs and integrations

- `CompleteArtifactCommand` (06.1.2-T2) calls the sniffer inside its handler; the `HEAD`/object read is a storage call and stays outside the DB transaction (P5): open the object stream, sniff the first bytes, then run the state update in the tenant transaction.
- `IParsing` is consumed by 04.4.1 (report parse at `reprocess` and comparison), 06.3.4-T2 (trace zip serving) and 06.2.3's scanner (bounded readers for content scan).
- The Node-side CLI/reporter does its own validation in TypeScript (04); this story covers the server runtime only — the wire contract is unchanged.

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| 00 §5.7 S5 | `XmlReaderSettings` `DtdProcessing.Prohibit` + `XmlResolver = null` + entity/depth/size/time caps; zip entry/ratio/nesting caps; `JsonDocument.MaxDepth` with duplicate property names rejected | `SafeXmlReaderTests`, `SafeZipArchiveTests`, `SafeJsonTests` (AC1–AC4) |
| 00 §5.7 S3 | parse errors return `artifact_invalid` + a generic reason; parser output never includes artifact bytes or paths in logs/messages | `ParseErrorRedactionTests` asserts message content |
| 00 §5.7 S4 | `XmlResolver = null` and no fetch API in the profile make outbound requests impossible, not just disallowed | `ReaderProfileProhibitsDtdAndCarriesNoResolver` (the settings object carries `XmlResolver = null`) |
| 00 §5.7 P1 | `complete` is a listed hot endpoint; sniffing reads a bounded prefix (≤ 4 KiB) and archive walks abort at first cap | AC6 allocation/timing guard test |
| 00 §5.7 P5 | storage `HEAD`/stream reads run before/outside the tenant transaction; no DB tx is held while bytes are walked | `CompleteArtifactCommandTests` ordering assertion |
| 00 §5.5 C8 | all rejection paths are `Result` → 00 §9.2 envelope (422/413) | endpoint tests in 06.1.2 re-run against hostile fixtures |
| Tenant isolation | no new reads/writes; runs under the caller's tenant transaction like any handler code | existing RLS integration suite |
| Privacy | parses bytes but extracts nothing to logs or to disk outside the extraction root | AC4 |
| Retention/deletion impact | none | — |

- **Authorization:** none new — the profile adds no endpoint or handler and is invoked inside existing, already-authorised handlers (06.1.2's `complete` under `artifact:write`; 04.4.1's parse later), running in the caller's tenant scope.
- **Telemetry:** no new metric; a rejection is recorded in the existing `artifact.failure_code` and counted by the `artifact-failure rate` SLI (00 §11); parser messages carry a generic reason only and never artifact bytes or paths (00 §5.7 S3).
- **Failure path:** every parse/sniff refusal is a `Result` value mapped once to the 00 §9.2 envelope (C8) — 422 `artifact_invalid` or 413 `payload_too_large` — and no parser exception escapes a handler; a sniff mismatch at `complete` is a committed 200 with `state: rejected` + `media_type_mismatch`, never an unhandled exception.

| Sub-task | Work | Size | Done when |

| 06.3.1-T1.1 | `Infrastructure/Parsing/SafeXml` (`XmlReaderSettings`: `DtdProcessing.Prohibit`, `XmlResolver = null`, `MaxCharactersFromEntities = 1` (a positive cap; `0` means no limit — `DtdProcessing.Prohibit` is the real guard), `MaxCharactersInDocument` from kind cap, depth counting in the read loop over element nodes only (exactly 64 element levels, like JSON), `CancellationToken` timeout) + `SafeJson` (`JsonDocument` `MaxDepth` with duplicate property names rejected, bounded stream) + `ParsingLimits` constants | S | `SafeXmlReaderTests` + `SafeJsonTests` green; AC1, AC2 pass |

1. **Sniff table is partial by design.** T1 sniffs only the XML family (`application/xml`, `text/xml`, `application/*+xml`), the JSON family (`application/json`, `application/*+json`) and `text/html`; every other declared media type returns `SniffResult.NotSniffed`. 06.3.1-T2.2 (with 06.1.2-T3) completes the magic-byte table (PNG/JPEG/MP4/zip) and makes `NotSniffed` fail closed at `complete`. Hand-over: 06.3.1-T2. [DECISION] Closed by 06.3.1-T2 (this PR): the sniff table now covers every allowed `media_types` entry and a declared type outside it fails closed as `media_type_mismatch` (the T1 `NotSniffed` verdict is removed).
2. **`IParsing` ships `ParseXmlReport`/`ParseJson`/`SniffMediaType` only.** `EnumerateArchive` is not on the interface yet; 06.3.1-T2.1 adds it with `SafeZipArchive` (T2 is outside T1 scope). Hand-over: 06.3.1-T2. [DECISION] Closed by 06.3.1-T2 (this PR): `IParsing` ships `EnumerateArchive` backed by `SafeZipArchive`.
3. **Sniff runs on the staging object before the copy and again on the final object, outside the tenant transaction, for the sniffed families only.** The prefix is read through the new `IObjectStorage.ReadPrefixAsync(key, 4096, ct)` (ranged `bytes=0-4095` GET, `maxBytes` 1..65536, null when the object is absent, an empty array for a zero-byte object, key validation identical to `HeadAsync`): first on the verified staging object so a mismatching artifact is never promoted to the final key, then again on the final object after copy + re-`HEAD` (the copy has no source precondition, S-F2) and on the retry path. Storage I/O stays outside the tenant tx (00 §5.7 P5) and the thin `CompleteArtifactUpload` writer is unchanged. [DECISION] Update by 06.3.1-T2 (this PR): a declared type outside the sniff table now rejects `media_type_mismatch` at `complete` with no prefix GET at all (`MediaSniffer.IsSniffed` and the not-reported-`object_missing` caveat are gone).
4. **HTML is size + sniff only.** A declared `text/html` kind is validated by size and sniff and never parsed into DOM/CSS on the server. [DECISION]
5. **`artifact_invalid` is registered, but no HTTP route returns it yet.** The 422 code is in `contracts/openapi.yaml` (the `complete` description), 00 §9.2 and 00 §15; at T1 only in-process parser callers produce it and the 04.4.1 callers map it. [INFERENCE] no HTTP surface exists before 04.4.1.

8. **`IParsing` is synchronous and its 30 s cap is cooperative.** `ParseXmlReport`/`ParseJson` return only after the whole document/payload has been validated, and the timeout is checked between reads and per node, so it cannot interrupt a blocking `Stream.Read` or one `JsonDocument.Parse` call. A caller MUST pass an already-buffered, bounded stream; hard isolation from a runaway parse is 06.3.6. Hand-over: 04.4.1 (T2 reads), 06.3.6. [DECISION]
9. **`ParsedXmlReport.OpenReader` is a synchronous reader.** The handle's factory builds a sync `XmlReader` (`Async = false`) over the profile's own bounded bytes; 04.4.1's mapper walks it with sync reads, or asks for an async variant. Hand-over: 04.4.1. [DECISION]
10. **UTF-16/UTF-32 XML is not sniffed, and its DTD reason is `malformed`.** The sniffer recognises UTF-8 (with or without BOM) only, so a UTF-16/UTF-32 XML body returns `Mismatch`; 06.3.1-T2.2 decides the encoding table, and 04.4.1's UTF-16 AC8 cannot trigger until then. For such an encoding the byte-level DTD scan does not fire, so a declared DTD reads `malformed`, not `dtd_prohibited`; 06.3.2's corpus must not assert `dtd_prohibited` for them. Hand-over: 06.3.1-T2.2, 06.3.2, 04.4.1. [DECISION] Closed by 06.3.1-T2 (this PR): the encoding table now sniffs UTF-16/UTF-32 XML by BOM (so 04.4.1 AC8 can trigger); the `malformed` DTD reason for a wide-encoded declared DTD is unchanged and must be verified in 06.3.2.
11. **A JSON escaped lone surrogate parses but makes `GetString` throw.** A `\ud800`-style escape inside a JSON string survives the profile, and `JsonElement.GetString()` on it throws `InvalidOperationException`; 04.4.1's consumer uses `TryGetString` or handles the exception. Hand-over: 04.4.1. [DECISION]
12. **The prefix GET is not ETag-pinned.** `IObjectStorage.ReadPrefixAsync` issues a ranged GET with no `IfMatch`, so the checksum signed at presign — not the prefix read — is the control; pinning the prefix read is a hand-over to 06.3.1-T2.2 together with fail-closed `NotSniffed`. [DECISION] Closed by 06.3.1-T2 (this PR): the prefix read is pinned to the `HEAD` ETag via `IfMatch` (a `412` is a terminal `object_missing`; a store that reports no ETag leaves the read unpinned and bounded by the SHA-256 re-check).
13. **AC6 peak memory is demonstrated for benign shapes only.** Token-dense JSON (`JsonDocument` metadata ~12 B/token) and huge-attribute XML amplification are measured by 06.3.2/06.3.6, which cap the per-kind `max_bytes` in 04.1.3. Hand-over: 06.3.2, 06.3.6, 04.1.3. [INFERENCE]

### 06.3.1-T2 — Archive limits + MIME sniffing (M)

Depends on: 06.3.1-T1.

| Sub-task | Work | Size | Done when |
|---|---|---|---|
| 06.3.1-T2.1 | `SafeZipArchive` over `System.IO.Compression.ZipArchive`: entry-count cap, cumulative expanded-size cap, per-entry ratio cap, nesting cap for zip-in-zip, entry-name normalization rejecting `..`/absolute/drive-letter/backslash, extraction confined to a root it owns | S | `SafeZipArchiveTests` green; AC3, AC4 pass |
| 06.3.1-T2.2 | `MediaSniffer`: magic-byte table for every allowed `media_types` entry (PK zip, PNG, JPEG, MP4, XML, JSON, HTML); enforced in `CompleteArtifactCommand` → `rejected`/`media_type_mismatch`; `ParsingBudgetTests` | S | `MediaSnifferTests` + `CompleteArtifactCommandTests.MismatchedMediaIsRejected` green; AC5, AC6 pass |

**Re-estimate:** sub-tasks sum to T1 1.0 + T2 1.0 = 2 d = area plan (M + M). No change to 00 §14.

Notes (06.3.1-T2 delivery, S40, branch `feature/06.3.1-T2-s40`): the archive arm and the fail-closed magic-byte table ship in `Infrastructure/Parsing/{SafeZipArchive,MediaSniffer}.cs`, `ParsingLimits` gains `MaxEntryNameLength`/`MaxEntryNameSegments`, `IParsing` gains `EnumerateArchive`, and the 06.1.2 `complete` verifier pins both prefix reads to the `HEAD` `ETag`. No endpoint, schema or permission change. [DECISION]s and hand-overs:

1. **The sniff fails closed for every type outside the table.** [DECISION] 06.3.1-T2.2 removed T1's `NotSniffed` verdict: a declared media type the table does not name is `SniffResult.Mismatch` at `complete`, so the artifact ends `rejected` with `failure_code = media_type_mismatch`. `image/svg+xml`, `text/plain`, `application/pdf`, `application/octet-stream`, `video/webm`, `image/webp` and every other undeclared type are rejected this way, never waved through.
2. **The accepted table.** [DECISION] XML family (`application/xml`, `text/xml`, `application/*+xml`) by BOM-aware UTF-8/UTF-16/UTF-32; JSON family (`application/json`, `application/*+json`) UTF-8 only; `text/html`; `application/zip` = `PK\x03\x04`, or `PK\x05\x06` for an empty archive; `image/png` = all eight bytes `89 50 4E 47 0D 0A 1A 0A`; `image/jpeg` = `FF D8 FF`; `video/mp4` = a `ftyp` box (`ftyp` at offset 4, big-endian box size 8..16 MiB, printable-ASCII major brand).
3. **Both prefix reads are ETag-pinned.** [DECISION] `IObjectStorage.ReadPrefixAsync` takes the `ETag` the preceding `HeadAsync` reported and sends it as `If-Match`; a store that refuses the conditional read with `412 PreconditionFailed` is a terminal `object_missing` (the verified object was replaced), never a 500 and never `ready`. A store that reports no `ETag` leaves the read unpinned, and the presign-signed SHA-256 comparison the caller already ran remains the control; the pinned read narrows, never replaces, that comparison.
4. **`SafeZipArchive` bounds the object, then probes the whole archive before extracting.** [DECISION] The walk buffers the archive into one bounded buffer under the kind's `max_bytes` (never trusting the declared stream length), runs the central-directory pass first (declared entry count from the EOCD/ZIP64 record, each name normalized and bounded by `MaxEntryNameLength`/`MaxEntryNameSegments`, duplicates, symbolic links, file-shadows-folder), then measures the content-derived caps (cumulative expanded bytes from bytes actually read, per-entry ratio on consumed bytes, zip-in-zip nesting ≤ 2). `Extract` runs a full non-extracting pass first, so a content-derived breach never materializes a root; the root is a unique owner-only temp directory (0700, files 0600) deleted on dispose. `IParsing.EnumerateArchive` (metadata only, no extraction) has no production caller yet (04.4.1, 06.3.4 and 06.2.3 are its consumers), and `Extract` is exercised by tests only.
5. **The archive reader is stricter than `System.IO.Compression` on three shapes.** [DECISION] (a) The declared entry count is read from the same end-of-central-directory record `ZipArchive` picks (the last `PK\x05\x06` in the last 22 + 65535 bytes, the ZIP64 record whenever the locator points at one, plus any real classic count, each refused above 10 000) and refused before `ZipArchive` is constructed; a chosen record that does not close at the end of the object (a fake record inside a comment, or trailing bytes after the comment) is refused `malformed` even though `ZipArchive` alone would read it. (b) Entry names are refused when they carry Unicode `Format` characters (including ZWJ/ZWNJ and bidi controls), line/paragraph separators, private-use characters or unpaired surrogates, or when a segment ends in `.` or a space; this can refuse a legitimate archive whose names use ZWJ/ZWNJ (emoji sequences, Persian or Indic names), the AC4 hardening choice. (c) Names are capped at 1024 characters and 64 segments. Relax (b) only in a task that names the scripts to allow.

Hand-overs (each also recorded in STATUS.md §6 "Archive parser hand-overs (06.3.1-T2 hand-over, from S40)"):

- **[DECISION] 04.4.1 + 06.3.4 consumers MUST NOT trust the extraction.** A consumer that feeds an extracted file to a parser MUST run it back through this profile, and nested-zip detection is by the entry's leading `PK` magic only, never by its name (an entry named `.zip` whose content is not a zip is not recursed into, and one that is a zip is recursed whatever it is called). 04.4.1's trace/report mapper and 06.3.4-T2.1's trace/report-bundle reader must not re-open an extracted file or a nested entry as an archive without re-running the profile. Receiver: 04.4.1 plan §10 T2 Notes; 06.3.4 plan §10 T2 Notes.
- **06.3.6 spools large/nested archives and bounds concurrency.** The walk holds the whole object in one buffer plus one nested archive in memory, so peak memory is about the kind cap plus up to `MaxExpandedBytes` (512 MiB) plus `MemoryStream` growth per walk [INFERENCE: not measured]; 06.3.6 must spool a large or nested archive to a seekable temp file and bound parser concurrency (it owns the process-wide memory and concurrency limits this profile deliberately does not). Receiver: 06.3.6 plan §10 T3 Notes.
- **[DECISION] 06.3.2 corpus: verify the DTD reason for wide encodings, and expect SVG rejection.** UTF-16/UTF-32 XML is now sniffed, so the corpus must not assert `dtd_prohibited` for a wide-encoded declared DTD — its reason is still `malformed` unless the T1 byte scan covers them (`verify`); and `image/svg+xml` fixtures must now expect rejection. Receiver: `plans/features/06-evidence-artifacts/06.3.2-hostile-input-fixtures.md` §10 Notes (06.3.1-T2 hand-over).
