## 1. Goal and non-goals

**Goal.** `Evidgate.Modules.Evidence` owns an `artifact` row whose object key is minted only by the server (`org/<org_id>/project/<project_id>/run/<run_id>/attempt/<execution_key>/<attempt_no>/<artifact_id>`), unique per org, so that 06.1.2 can stage uploads and 05 can resolve evidence without ever trusting a client-chosen key.

**Non-goals.** Upload/complete endpoints and the presign flow (06.1.2); sensitivity *enforcement* on reads (06.2.1); masking scan (06.2.3); retention/deletion columns are created here but the jobs live in 06.4.x; the freeze interface (06.5.1). No endpoint is exposed by this story beyond the internal command.

## 2. User stories and acceptance criteria

- As the ingestion pipeline, I mint an artifact row for a planned `(execution_key, attempt_no)` before the `case_attempt` exists, so uploads never wait on attempt resolution (T17).
- As the Tech Lead, I know no client input can name, collide with or traverse an object key, so cross-tenant probing through storage is impossible.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | A `CreateArtifactRecord` command carrying a client-supplied `object_key` is rejected: HTTP-layer equivalent 422 `object_key_not_allowed` (the command itself returns a `Result` error `object_key_not_allowed`, C8) |
| AC2 | A created row has `object_key` matching `org/{org_id}/project/{project_id}/run/{run_id}/attempt/{execution_key}/{attempt_no}/{artifact_id}`, `state = pending_upload`, `scan_state = pending`, `sensitivity` = the kind default, `attempt_id IS NULL` |
| AC3 | `UNIQUE (org_id, object_key)` holds: a second row with the same key in the same org fails with a unique violation; the same key shape in another org is allowed |
| AC4 | `UNIQUE (org_id, id)` exists (T3) so `artifact` can be the target of composite FKs; the 02.6.1-T2 lint passes |
| AC5 | With `evidgate.org_id` unset or set to another org, `SELECT` on `artifact` returns zero rows (RLS via `evidgate.current_org_id()`, T2); `FORCE ROW LEVEL SECURITY` is on |
| AC6 | `kind` outside the 00 §7 closed list (`trace`, `video`, `screenshot`, `raw_report`, `dom_snapshot`, `a11y_snapshot`, `patch`, `ui_hierarchy`) and `sensitivity`/`scan_state`/`state` outside their enums are rejected by CHECK constraints |

## 3. Contracts touched

- 00 §8.4 artifact state machine — implemented, not changed (`pending_upload` is the only initial state).
- 00 §7 identifier contract — `kind`, `sensitivity` enum values pinned as CHECK constraints; no new enum values.
- 06 §4 `artifact` and `artifact_kind_policy` — both tables are created by this story's migration so that 06.1.2-T1 (wave M2-10) and 06.2.1-T1 (wave M2-8) — which both depend on 06.1.1-T1 but not on each other — can consume the policy table. `artifact_kind_policy` columns `capture_enabled`, `reject_on_secret`, `default_sensitivity` are written by 06.2.x stories; this story only creates the schema.
- Resolved (00 §7): every table carries `created_at`, `updated_at`, `version`; 06 §4's shorter `artifact` column list is superseded — this plan adds `created_at`, `updated_at` (00 §7 naming).

## 4. Data model and migrations

DbUp migration `migrations/NNNN_evidence_artifact.sql` (number allocated at build time; runs as the migration owner role, app role gets DML only):

```sql
create table artifact (
  id            uuid primary key,                 -- UUIDv7, application-generated
  org_id        uuid not null,
  project_id    uuid not null,
  run_id        uuid not null,
  execution_key text not null,                    -- sha256 hex (00 §7)
  attempt_no    int  not null,
  attempt_id    uuid,                             -- resolved at evidence freeze (T17)
  kind          text not null check (kind in ('trace','video','screenshot','raw_report','dom_snapshot','a11y_snapshot','patch','ui_hierarchy')),
  object_key    text not null,
  media_type    text not null,
  bytes         bigint,
  checksum      text not null,                    -- 'sha256:<hex>' declared at mint
  sensitivity   text not null check (sensitivity in ('normal','sensitive')),
  scan_state    text not null default 'pending' check (scan_state in ('pending','clean','flagged')),
  state         text not null default 'pending_upload' check (state in ('pending_upload','uploaded','ready','rejected','pending_delete','deleted')),
  expires_at    timestamptz,
  failure_code  text,
  version       int not null default 0,
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now(),
  unique (org_id, id),                            -- T3
  unique (org_id, object_key),                    -- FR-06-1
  foreign key (org_id, run_id) references run (org_id, id)  -- composite FK, 00 §5.4.1
);
create index artifact_run_idx on artifact (org_id, run_id) where state <> 'deleted';  -- serves freeze + reconcile reads
create index artifact_expiry_idx on artifact (expires_at) where state = 'ready';       -- serves the retention job (06.4.2)
alter table artifact enable row level security;
alter table artifact force row level security;      -- 00 §5.4.3
create policy artifact_tenant on artifact
  using (org_id = evidgate.current_org_id())
  with check (org_id = evidgate.current_org_id());

create table artifact_kind_policy (
  id            uuid primary key,
  org_id        uuid not null,
  project_id    uuid not null,
  kind          text not null,
  max_bytes     bigint not null,
  media_types   text[] not null,
  default_sensitivity text not null check (default_sensitivity in ('normal','sensitive')),
  reject_on_secret boolean not null default false,
  capture_enabled boolean not null default true,
  unique (org_id, id),                            -- T3
  unique (org_id, project_id, kind)
);
alter table artifact_kind_policy enable row level security;
alter table artifact_kind_policy force row level security;
create policy artifact_kind_policy_tenant on artifact_kind_policy
  using (org_id = evidgate.current_org_id())
  with check (org_id = evidgate.current_org_id());
```

EF Core 10 write entity `Artifact` + `ArtifactKindPolicy` (snake_case naming convention, `version` `IsConcurrencyToken`, no navigation beyond one level, C4). No `attempt_id` FK: the `case_attempt` target does not exist at mint time (T17); the link is written at freeze.

## 5. API shapes (commands, queries, endpoints)

No `/v1` endpoint yet; the command is invoked by 06.1.2's `upload-url` handler.

| Type | Name | Shape |
|---|---|---|
| `ICommand<Result<ArtifactRecord>>` | `CreateArtifactRecord` | `{run_id, execution_key, attempt_no, kind, media_type, declared_bytes, checksum, client_object_key?}` → `{artifact_id, object_key, state}`; handler = EF Core write inside the C2 pipeline's tenant transaction |
| domain service | `ArtifactKeyMinter` | pure function `Mint(org, project, run, executionKey, attemptNo, artifactId)` → the §2 key; unit-tested, no I/O |

Error codes returned (00 §9.2): `object_key_not_allowed` (422), `kind_unknown` (422), `checksum_invalid` (422, not `sha256:<64-hex>`), `size_out_of_range` (422, declared_bytes ≤ 0). Commands carry no `Idempotency-Key` here — the wrapping `upload-url` endpoint owns idempotency (06.1.2).

## 6. States and transitions

Creates rows only in `pending_upload` (00 §8.4). `scan_state` starts `pending` (T19). No other transition is possible from this story; the guard table is 06.1.3.

## 7. Jobs and integrations

- Consumed by `upload-url` (06.1.2-T1), `complete` (06.1.2-T2), freeze (06.5.1) and the sweeper (06.4.3).
- No outbox row is written at mint: nothing downstream reacts to `pending_upload`.
