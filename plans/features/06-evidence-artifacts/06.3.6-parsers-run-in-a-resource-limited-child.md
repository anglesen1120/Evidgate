## 1. Goal and non-goals

**Goal.** Untrusted bytes are never parsed inside the shared `Evidgate.Worker` process. Each parse (XML/JSON report, zip index, secret-scan reader) runs in a short-lived child process with hard memory, CPU and wall-time limits and no network, started by a task-queue handler; a crash, OOM kill or timeout becomes a `rejected` artifact with a stable reason and never takes the worker down. A per-tenant concurrency cap with fair scheduling stops one tenant from occupying every parse slot.

**Non-goals.** The parser profile itself — DTD off, depth/entity caps, zip-slip rules (06.3.1, reused inside the child); streaming consumption of report entries (04.1.3); the viewer origin and rendering (06.3.3/06.3.4); a general code-execution sandbox for customer code (not a product feature); container-level isolation per tenant (rejected, see §3).

## 2. User stories and acceptance criteria

- As an operator, a memory bomb or a pathological file costs one failed parse, not a worker restart.
- As a tenant, my 10 000 queued parses do not delay another tenant's single parse beyond the fair-share bound.
- As a CI owner, a rejected report tells me why (`parse_oom`, `parse_timeout`, ...) without exposing internals.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | Every parse call site reaches the parser only through `IParseRunner`; an `Architecture.Tests` rule fails if `XmlReader`/`ZipArchive`/`JsonDocument.Parse` over artifact bytes is used outside the child entry point and `Infrastructure/Parsing` |
| AC2 | The child runs with a memory limit (default 512 MiB), CPU time limit (default 20 s CPU), wall-time limit (default 30 s, same as `ParseTimeout`) and no network; limits are configuration with those defaults `[INFERENCE]` |
| AC3 | Exit mapping: normal result → parsed output; exit by memory limit → `rejected` `parse_oom`; wall/CPU limit → `rejected` `parse_timeout`; non-zero or signal exit → `rejected` `parse_crashed`; malformed output on the pipe → `rejected` `parse_crashed`; none leaves the artifact `ready` or `uploaded` |
| AC4 | A parse attempting any outbound connection (DNS or TCP) fails inside the child and the attempt is logged as a security event; the artifact is `rejected` |
| AC5 | With per-tenant cap `N` (default 2 concurrent parses per org, global slots `G`), tenant A with 50 queued parses never holds more than `N` slots; tenant B's parse starts within one scheduling interval when a slot is free, and waits at most `ceil(parses_ahead / G)` rounds under load |
| AC6 | Wait time is observable: histogram `parse_queue_wait_seconds{tenant_tier}` (no tenant id label) and gauge of slots in use; an alert fires when p95 wait exceeds the target for 10 minutes |
| AC7 | Hostile-input suite (06.3.6-T3): memory bomb, deep nesting, huge attribute, billion-laughs, zip bomb — the worker process pid and uptime are unchanged, each hostile artifact ends `rejected` with the mapped reason, and a parallel parse from another tenant completes within its normal time |
| AC8 | A worker killed while a child runs leaves no orphan child (child exits when the parent pipe closes) and the task is retried by the queue visibility timeout; the artifact is parsed once (idempotent result write) |

- **Decision (D-06.3.6-1, `[DECISION]` default).** Options considered: (a) in-process with `AssemblyLoadContext`/timeouts — rejected, cannot bound memory or survive OOM; (b) a child *process* of the same worker image started per parse with OS limits (Linux cgroup v2 `memory.max`, `RLIMIT_CPU`, no-network namespace or seccomp) — chosen; (c) a container/pod per parse (Kubernetes Job) — stronger but cold-start and orchestration cost not justified for V1, kept as upgrade path; (d) a separate long-lived parser service — shared-state risk, more ops. ⚠️ Whether the managed runtime exposes cgroup limits and `unshare(CLONE_NEWNET)` to an unprivileged container is unverified; T1.1 verifies on the dev stack image and records the result in DECISIONS §6. Fallback if network namespaces are unavailable: `seccomp` deny of `socket`/`connect`, else the child runs with no inherited sockets and the egress-deny at the container network policy (10.x) is the second layer.

## 5. API shapes (commands, queries, endpoints)

No new public endpoint. Internal:

| Kind | Name | Surface | Notes |
|---|---|---|---|
| Command | `ParseArtifact` task handler | `task` queue `parse` | payload `{org_id, artifact_id, parser, limits_profile}`; sets `rejected` or stores the parsed result |
| Interface | `IParseRunner.RunAsync(ParseRequest, ct) → Result<ParseOutput>` | internal to `Evidgate.Modules.Evidence` | spawns the child, streams the NDJSON result, enforces limits and maps exits |
| Child entry | `Evidgate.Parser` (small console project, same image) | `evidgate-parser --profile xml-report` reading bytes from stdin/fd, writing NDJSON to stdout | no network libraries referenced; Architecture rule bans `System.Net.*` in this project |

Customers see only the existing artifact `rejected` state with `failure_code`.

## 6. States and transitions

Artifact states per 00 §8.4 are unchanged: `uploaded → ready | rejected`. The parse step sits inside the `complete` → `ready` path (sniff, then parse where the kind needs it). New: a parse task is `claimed → running → done | retry | dead_letter` under the 01.5.1 task machine; limit hits are *results* (`rejected`), not retries, because a retry of a hostile file cannot succeed. Infrastructure failures (cannot spawn the child, queue lease lost) retry with backoff then dead-letter with the alert sink (01.5.1-T4). Transitions idempotent (T82).

## 7. Jobs and integrations

- **Spawn.** The `parse` handler writes nothing before the child finishes; it opens the object read stream with a byte cap and pipes it to the child's stdin. The child applies the 06.3.1 profile (defence in depth), emits NDJSON entries and a final `{"done": true, "count": n}` line; a missing final line = `parse_crashed`.
- **Limits.** Memory via cgroup v2 where available, else `RLIMIT_AS` (⚠️ behaves differently for a managed runtime heap; verify in T1.1) plus `DOTNET_GCHeapHardLimit` as the first line; CPU via `RLIMIT_CPU`; wall via parent timer that kills the process group. Child runs as an unprivileged uid with read-only root filesystem and an empty temp dir deleted after exit.
- **Fairness.** Claim query selects the oldest runnable task per `fair_key` round-robin, skipping orgs at their cap `N` (counted from `running` tasks); global slots `G` come from per-queue concurrency (01.5.1-T1). Alternative considered: one sub-queue per tenant — rejected, unbounded queue count. Starvation bound documented in the runbook.
- **Callers.** `CompleteArtifact` (06.1.2) enqueues `parse` for kinds that need parsing; 04.4.1 raw-report parse and 06.2.3 content scanner use the same queue and runner. [INFERENCE] interactive callers (a user waiting on a comparison) share the queue in V1; a priority lane is deferred.
- **Streaming.** The NDJSON pipe is the hand-off that lets 04.1.3 stream entries to the mapper in bounded pages.

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| S5 untrusted parsers | memory/CPU/time limits, unprivileged uid, read-only FS, no network; hardened profile still enforced inside | AC2, AC4, AC7 |
| Blast radius | child crash cannot corrupt worker state; no shared mutable state across parses; temp dir wiped | AC7, AC8 |
| Tenant isolation | child receives one artifact's bytes only; fair scheduling keyed on `org_id`; metrics carry no tenant id; claim query returns task payload only | isolation test, AC5 |
| S3 no leakage | stderr of the child is captured, truncated and never stored or logged verbatim; reasons are the three codes | `ParseErrorRedactionTests` extended |
| Audit | repeated `parse_crashed` for one project raises a security event (`artifact.parse_rejected`) through 02.7.1/11.5.1 | event test |
| Performance | spawn cost measured; a small-report fast path is allowed only if measured spawn overhead exceeds a budget (`[INFERENCE]` 50 ms p95) — default is always out-of-process | spawn benchmark in T1.4 |

DoR review answers. **Authorization:** internal handler, no new permission; callers already hold `artifact:write` paths (06.1.2). **Retention/deletion impact:** no persistent data beyond `artifact.failure_code`; temp files removed per parse; parse tasks purged by the 01.5.1 task purge. **Telemetry:** `parse_queue_wait_seconds`, `parse_runs_total{result}`, `parse_child_peak_rss_bytes`, `parse_slots_in_use`, trace span `parse.child` with exit class; alert on wait p95 and on `parse_crashed` rate. **Failure path:** limit hit → `rejected` with reason; spawn failure → retry with backoff → dead letter + alert; worker kill → child dies with pipe, task reclaimed.
