## 1. Goal and non-goals

**Goal.** One reusable harness so every module's integration tests boot PostgreSQL 18 in a container, apply the real migrations once, reset with Respawn between tests, and always run through the app role with RLS on — plus a `fixtures/` corpus format shared by .NET and TypeScript, a required tenant-isolation suite, and a Playwright workspace ready for 09's screens.

**Non-goals.** The fixtures themselves of modules 03–06 (loader + one sample only); actual screens or E2E flows (09); performance/load tests (10); coverage tooling (licence pending, flagged ⚠️ below).

## 2. User stories and acceptance criteria

- As a developer, `dotnet test` on any `*.IntegrationTests` project boots PostgreSQL 18 and runs against real migrations and RLS, so "works on my machine" means the same thing everywhere.
- As a developer, a `.NET` and a `TS` loader read the same `fixtures/` files, so the validator parity corpus (T42) and golden reports are defined once.
- As the Tech Lead, any code path that lets one org see another org's row fails a required check, so tenant isolation is enforced, not hoped for.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `dotnet test tests/Evidgate.Foundation.IntegrationTests` on a machine with Docker: boots `postgres:18` pinned by digest, runs the Migrator once per assembly, passes — no manual database setup |
| AC2 | Respawn resets all data between tests: `Respawn_TwoTestsSeeEmptyDb` inserts a row in test A and observes an empty table in test B; the migration journal is preserved |
| AC3 | Connections come from the **app** role (`evidgate_app`), not owner: `Harness_UsesAppRole` asserts `current_user`; a migration attempting to grant the test role `BYPASSRLS` fails review and the convention test `AppRole_HasNoBypassRls` |
| AC4 | `TenantTestScope` opens a real `ITenantScope` for a seeded org; `TenantScope_MissingOrgContext_Throws` shows the C3 interceptor firing on a command outside it |
| AC5 | Tenant-isolation suite is a required check: a deliberately planted cross-tenant query (temporarily commented policy) makes `Isolation_CrossTenant*` tests fail |
| AC6 | A fixture directory (`fixtures/<domain>/<name>/` with `input.*`, `expected.json`, `meta.json`) loads identically from .NET (`FixtureLoader`) and TS (`loadFixture`), proven by the loader round-trip test and the golden-file helper asserting canonical-JSON equality |
| AC7 | `npx playwright test` in `apps/web` runs one smoke test against a trivial served page; the CI job exists (wired in 01.7.1-T1, enabled here as a non-blocking job until 09 has screens) |

## 3. Contracts touched

- 00 §5.4 — the harness exists to enforce rules 2/3/6/7 in tests: app-role connections, `FORCE` RLS, helper functions, `unique (org_id,id)` lint hooks.
- 00 §5.5 C3 — `TenantTestScope` wraps `ITenantScope.BeginAsync`; tests never open raw owner connections for assertions that go through the read/write path (a dedicated assertion connection is allowed for seeding only, marked in code).
- 00 §5.6 W9 — Vitest for TS units, Playwright E2E; component harnesses convention recorded for 09.
- 00 §11 — the isolation suite is the local evidence for "no cross-tenant path"; 11 inherits it (area §10).
- No table, endpoint or contract file changes.

## 4. Data model and migrations

None. The harness applies the migrations owned by other stories; it adds no schema of its own. Test projects create no production artifacts. `fixtures/` layout:

```
fixtures/
  contracts/        # accept/reject corpus for Corvus↔Ajv parity (T42, owned by 01.3.2-T2)
  reports/junit/    # raw producer reports → expected normalised events (04 consumes)
  <domain>/<name>/{ input.*, expected.json, meta.json }
```

`meta.json` = `{ "domain", "kind", "source", "added_by" }`; loaders refuse unknown shapes (`meta.json` required, `expected.json` canonical RFC 8785 when present).

## 8. Security, privacy and performance

| Rule | How this story meets it | Proven by |
|---|---|---|
| 00 §5.4.3 / DECISIONS F5 | app role never `BYPASSRLS`; tests exercise RLS rather than bypassing it | AC3, `AppRole_HasNoBypassRls` |
| 00 §11 (tenant isolation) | dedicated suite over API, EF write and Dapper read paths, plus id-guessing (random uuid of other org → 404/empty) | AC5; `Isolation_*` tests in T4 |
| 00 §5.7 S3 | seeded data uses synthetic ids/emails only; no real customer data in `fixtures/` (`meta.source` records provenance) | fixture review checklist in T3 |
| 00 §5.7 P- discipline | Respawn between tests keeps suite time bounded; parallelise across collections, serialise within the shared database | suite wall-time < 10 min locally, measured in T2 |
| W9 | Vitest config shared; Playwright smoke only (screens are 09) | AC7 |
| Secrets | harness reads DSNs from Testcontainers/env, never committed; `fixtures/` is public-safe | repo scan in CI (11) |
| Retention | none — test databases are ephemeral | — |
| Authorization | Test-only harness: no endpoint or permission; tests run under the app role, never `BYPASSRLS`, and exercise RLS instead of bypassing it | AC3, `Harness_UsesAppRole`, `AppRole_HasNoBypassRls` |
| Telemetry | No runtime telemetry (test code); suite wall-time is printed and CI duration is tracked (NFR-01-1 < 10 min, §11) | 01.6.1-T2.4 timing output |
| Failure path | Missing Docker or a failed Migrator run makes `DatabaseFixture.InitializeAsync` throw, which fails every test in that assembly (no silent skip); `Category=Docker` tests are skipped only by `EVIDGATE_VERIFY_SKIP_DOCKER=1` in `scripts/smoke-clean-build.sh` | AC3; smoke-clean-build gap noted under 01.6.1-T2 |

The story *is* the test plan for the repo; its own verification:

| Behaviour / boundary / failure | Test |
