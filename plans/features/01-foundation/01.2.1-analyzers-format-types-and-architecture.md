## 1. Goal and non-goals

**Goal.** `scripts/verify.sh` fails on a module-boundary violation, an unformatted file, an un-awaited task, a nullable warning and a TypeScript `strict` error — so code-quality invariants are machine-enforced from the first real module PR.

**Non-goals.** The CI workflow that invokes `verify.sh` (01.7.1); the licence/vulnerability scan jobs (01.7.1-T4, 11.6.1); test conventions and fixtures (01.6.1); any product rule beyond the five violations above.

## 2. User stories and acceptance criteria

- As a developer, one script tells me everything CI will check, so review rounds are about design, not style.
- As the Tech Lead, module boundaries (T47) and strict typing are enforced by the build, not by code review.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | Seeding a direct project reference from `Evidgate.Modules.Orchestrator` to `Evidgate.Modules.Ingestion` (bypassing `.Contracts`) makes `Architecture.Tests` fail and names both projects |
| AC2 | `dotnet format --verify-no-changes` exits non-zero on an unformatted `.cs` file; `prettier --check` exits non-zero on an unformatted `.ts` file; `scripts/verify.sh` fails on either |
| AC3 | A `Task`-returning method call without `await` fails the .NET build (`AnalysisLevel=latest-recommended` async rules as errors); a floating promise in `packages/*` fails ESLint (`no-floating-promises`, `--max-warnings 0`) |
| AC4 | A nullable reference warning anywhere in the solution fails the build (`TreatWarningsAsErrors` + nullable enable from 01.1.1-T2); a `tsc -b` error under `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` fails the TS build |
| AC5 | `Architecture.Tests` also fails on `Domain` referencing `Infrastructure`, on a `public` type outside `.Contracts`/`Endpoints`, and on a Mediator handler without a permission declaration (T47, C2/S2) |
| AC6 | `scripts/verify.sh` runs build + analyzers + format + unit + architecture + contract drift for both ecosystems and exits non-zero if any stage fails (FR-01-1) |

## 3. Contracts touched

- 00 §5.5 module shape — enforced here for the first time (project-reference graph + reflection checks); the rule itself is unchanged.
- 00 §5.6 W-rules — ESLint scope covers `apps/web` and `packages/*` only; server boundaries are **not** linted by ESLint (T47).
- `.editorconfig` becomes the single formatting source for both `dotnet format` and IDE; no contract change.
