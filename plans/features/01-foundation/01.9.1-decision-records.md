## 1. Goal and non-goals

**Goal.** `docs/adr/` exists with a template, an index and a merge-blocking rule: every irreversible choice gets an ADR with context, options, decision, consequences, licence evidence and a dated status. ADRs 0001–0006 capture the choices already made in `plans/01-foundation.md` §3 so they are referenceable by id; doc conventions say where runbooks, module READMEs, `contracts/README` and feature plans live, and a link check keeps them honest.

**Non-goals.** DECISIONS.md itself (product/verified-facts register owned by the TL — ADRs cite it, they do not duplicate it); module ADRs beyond the initial six (created as later areas make choices); a docs site generator.

## 2. User stories and acceptance criteria

- As a developer, `docs/adr/README.md` tells me exactly when I must write an ADR and gives me the template, so the rule is mechanical.
- As a reviewer, every big choice in plan 01 §3 maps to a numbered ADR I can cite in review, and a dead link in any doc fails CI.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | `docs/adr/` contains `README.md` (rule + lifecycle), `0000-template.md` and an index table; `scripts/check-adr.sh` fails when a `NNNN-*.md` file is missing from the index or lacks required sections (status, date, context, decision, consequences) |
| AC2 | ADRs 0001–0006 exist, each listing alternatives + rejection reasons, licence evidence (✅/⚠️ per README legend) and a dated status; each is cross-referenced from the area-plan decision it records |
| AC3 | `docs/README.md` fixes the locations: runbooks under `docs/runbooks/` (10), module READMEs `src/Modules/*/README.md`, `contracts/README.md`, feature plans `plans/features/`; a link checker (`lychee` or equivalent, licence-checked) runs in CI and fails on a dead internal link |
| AC4 | A PR that adds a new `NuGet`/`npm` dependency without an ADR-0002 matrix row is already blocked by `check-adr-matrix.sh` (01.1.1-T1) — re-verified here as the rule's enforcement story |
