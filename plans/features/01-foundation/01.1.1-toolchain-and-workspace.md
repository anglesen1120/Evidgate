## 1. Goal and non-goals

**Goal.** A clean clone of the repository restores and builds every .NET project and every npm workspace with pinned, licence-checked tool and package versions, in the exact layout of 00 §5.2, so that every later story starts from the same ground.

**Non-goals.** Analyzer/lint rules and architecture tests (01.2.1); CI pipeline (01.7.1); module contents (02–08); the Angular app itself beyond an empty workspace entry (09.1.1); container images (10.2.1).

## 2. User stories and acceptance criteria

- As a developer, I clone the repo and run two commands to get a green build, so onboarding takes minutes, not a day.
- As the Tech Lead, I can see why every package and version was chosen and that its licence allows closed-source SaaS, so a later upgrade or licence change (e.g. MediatR 13+) is caught.

| # | Acceptance criterion (testable) |
|---|---|
| AC1 | On a machine with only the .NET 10 SDK (any 10.0.x patch) and Node 26 installed: `dotnet restore --locked-mode && dotnet build -c Release` and `npm ci && npm run build --workspaces --if-present` both exit 0 |
| AC2 | Changing any `PackageVersion` in `Directory.Packages.props` without regenerating lock files makes `dotnet restore --locked-mode` fail (NU1004) |
| AC3 | A `<PackageReference Version=…>` inside a project file (bypassing CPM) fails the build (`ManagePackageVersionsCentrally` + NU1008) |
| AC4 | `global.json` pins SDK `10.0.x` with `rollForward: latestFeature` and `allowPrerelease: false` (`latestPatch` stays inside one feature band, so a host with only 10.0.4xx would fail AC1; ADR-0002); a `version` outside the installed 10.0 line, or an 11.0 preview SDK only installed, fails with the SDK-not-found message |
| AC5 | The directory tree matches 00 §5.2 exactly (`scripts/check-layout.sh` compares `git ls-files` top-level dirs and the project list in `Evidgate.slnx` with the contract list) |
| AC6 | `docs/adr/0002-compatibility-and-licence-matrix.md` lists every package in `Directory.Packages.props` and every direct npm dependency with version, licence (SPDX or file), evidence link and date; a package missing from the ADR fails `scripts/check-adr-matrix.sh` |

## 7. Jobs and integrations

- NuGet.org and registry.npmjs.org are the only package sources (`nuget.config` with `<clear/>` + one source; `.npmrc` `registry=`), so a dependency-confusion package from another feed cannot be restored.
- Consumed later by 01.7.1-T1 (CI restore/build) and 01.7.1-T2 (licence gate reads the same matrix policy).
