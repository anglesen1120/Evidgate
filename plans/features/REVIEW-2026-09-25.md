### F-01-1 [H] Epic 01.5 / FR-01-8 still build on pg-boss; own `task` queue table missing from owned schema

`01-foundation.md:181-190` — ruling: CR-D-1 §5.3; T49

CR-D-1 removed pg-boss: 00 §5.3 now reads "dispatcher moves it into the task queue table (owned by 01, FOR UPDATE SKIP LOCKED claim, available_at backoff)" with Cronos + pg_try_advisory_lock scheduling, but this plan still says "transactional outbox + pg-boss skeleton" (§1), "dispatched to pg-boss at least once" (FR-01-8), and tasks "pg-boss 12 bootstrap in apps/worker" (01.5.1-T1) / "enqueues one pg-boss task per row" (01.5.1-T3). Replace: epic → outbox + `task` queue + dead_letter state + Cronos scheduler on advisory lock; T1 size M→L (+1, we now build what pg-boss provided), T3 L→M (−1, same-transaction insert replaces cross-system enqueue).

### F-01-2 [H] Kysely/withTenant/SET LOCAL must become EF Core + Dapper + ITenantScope; Mediator pipeline task missing

`01-foundation.md:174-179` — ruling: CR-D-1 §5.5 C2/C3; T49

01.4.2-T1 specs "Kysely 0.29 setup with pg … withTenant(orgId, projectId?, fn) issuing SET LOCAL evidgate.org_id" and `withTenant()` recurs in §2 acceptance, §4 flow 2, §5 and §7. New contract: `ITenantScope.BeginAsync` issues parameterised `set_config('evidgate.org_id', @org, true)` (00 §5.4.2 — SET LOCAL cannot bind a parameter, so the literal form would violate S1 'no string-built SQL'), EF Core 10 write model + Dapper read model share that one connection/transaction (`Database.UseTransaction`), and the outside-transaction guard becomes a `DbCommandInterceptor` (C3). Additionally no task in this plan builds the Mediator 3 pipeline behaviours mandated by C2 (telemetry → validation → authorization → idempotency → tenant tx → handler → outbox flush → commit); add one (~M–L). Net size delta: T1 likely L→XL (+1) plus the new pipeline task.

### F-01-3 [H] FR-01-4/01.3.2-T2 assume one shared validator across api/worker/CLI — impossible across runtimes

`01-foundation.md:42` — ruling: T42

"Runtime validation = Ajv 8 (2020-12 mode)" and "one shared validator module for api/worker/CLI" (01.3.2-T2) can no longer hold: server-side wire validation is Corvus.Json.Validator 5.6 (+ FluentValidation 12 for command rules) while the CLI/adapters stay TypeScript and need their own validator (e.g. Ajv). Two JSON Schema engines may disagree on 2020-12 edge cases over the same event envelope; mitigate with a shared golden fixture corpus and differential tests rather than claiming a shared validator. FR-01-4 wording and 01.3.2-T2 must be rewritten.
