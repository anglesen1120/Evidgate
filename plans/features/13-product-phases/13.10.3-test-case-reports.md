## 1. Goal and non-goals

A project author can give a reviewer one report showing what was planned, which requirements have tests, and what execution evidence was available when the report was built. Web, PDF, DOCX and XLSX are different renderings of the same immutable `test_report`, not four queries against current project data (plan 13 FR-13-11).

[DECISION] D-REALIGN: only a **release scope** displays the bound release's recorded decision. Reports do not calculate release decisions, trigger aggregation, open tracker issues or run tests. Creating a report or sharing it changes neither an evaluation nor a consumed decision. No repository connection is required.

## 2. User stories and acceptance criteria

| ID | Given / when | Then |
|---|---|---|
| AC1 | An author selects feature nodes, requirements, a manual run or a release; selects sections and `vi` or `en`; requests a report | An async job produces one complete snapshot. A later requirement edit, relink, result or decision does not change its contents or `content_hash`. A new report can capture the later state. |
| AC2 | The author selects test plan, test cases and traceability | The plan lists scope, requirements, priorities, strategy and environment. Cases include steps, data and expected results by feature/requirement. The matrix flags uncovered requirements and unlinked cases separately; a link pinned to a superseded requirement version is stale, not current coverage. |
| AC3 | Execution is selected for a non-release scope, including a manual run that happens to be release-bound | Show counts by status labelled **“no release decision”**. Before any manual execution, show **“no manual execution recorded”**, never “0 failed”. |
| AC4 | Execution is selected for a release | Show the bound release decision (PASS / FAIL / INCONCLUSIVE) with its reasons, as recorded. If aggregation is pending or has not produced a decision, show that absence, not a synthetic verdict. Only closed, release-bound manual evidence contributes through 07.5.5; an open run is not release evidence. |
| AC5 | A reader opens the same snapshot as web, PDF, DOCX or XLSX after the project has changed | Every format uses the pinned language, sections, values, gaps and decision reasons. Renderers never consult live project rows or interpret user-supplied text as formulas or markup. |
| AC6 | A project writer issues a link, then later revokes it or lets it expire | The bearer can view only that snapshot while the link is valid, without a session. Expired, revoked and unknown tokens reveal neither a report nor whether it exists. Sharing is off by default. |
| AC7 | The P2 automated results section is selected for a release with CI or hosted evidence | Show each release component's run decision and its automated case results grouped by requirement. Keep unmapped results visible as unlinked and distinguish missing results from passing ones. Non-release scopes do not show this section. |

## 3. Contracts touched

Use plan 00 §2 permissions, §5.4 tenancy, §8.5/§8.6 decision semantics and §9 API conventions; add report operations and their permission metadata to OpenAPI at implementation. The canonical report payload is the only input to every renderer, including the public page. Record scopes, section identifiers, language and the snapshot schema version so existing reports remain readable after T7 adds a section.

13.10.1 supplies versioned requirements and their case links. 13.10.2 supplies manual results when available; 07.5.3 and 07.5.5 supply the release decision and reasons, including `manual_*` reasons. Report builders consume those contracts, not Policy tables they own or update. When 13.10.4-T8 provides linked open bugs, capture their display data at build time; do not refresh tracker data while rendering or sharing.

## 4. Data model and migrations

- `test_report`: immutable project-scoped row, written complete by the job. Store scope and selected ids, ordered sections, `language`, pinned requirement and case versions, selected section data and `content_hash`. Capture applicable manual result identities and values, and the bound release decision reference, value and reasons if present. Persist display values, not just ids whose live contents could change.
- `test_report_share`: project-scoped FK to one `test_report`, unique token hash, `expires_at`, nullable `revoked_at`. Revocation changes this row, not the snapshot. Keep `org_id`, composite scope FKs and FORCE RLS on both tables. Index report history by project and the share lookup by token hash.
- Read source data at one consistent point; canonicalize the payload (including language, scope and selections) before hashing. Record job progress on the task queue, never by partially filling or revising the snapshot. Rendering the same content as different formats does not imply identical file bytes.

## 5. API shapes (commands, queries, endpoints)

| Operation | Input and output | Access |
|---|---|---|
| Create report | One scope kind with matching project ids, nonempty section selection, `vi`/`en`, optional strategy/environment text. Return accepted job reference; completion provides the report id. Reject foreign ids and unsupported scope/section combinations before exposing data. | `authoring:write` |
| Read history, report, job outcome or download | Project-scoped, paged history; read one completed snapshot or render its selected format. A failed job has a failure reason but no downloadable or shareable partial report. | `authoring:read` |
| Issue / revoke link | Issue for one completed report with expiry; show the secret token once. Revoke one link without affecting other reports. | `project:write` |
| Read shared report | Only the opaque token resolves the public snapshot. No client-selected project, nested resource, report id override or session is accepted as additional authority. | Valid, unexpired, unrevoked share token only |

## 6. States and transitions

Queue acceptance → build → complete or failed. Publication is atomic; replaying a successful queue delivery cannot publish a second snapshot for that job. A source change after publication never regenerates the snapshot. Share state is separate: no link → issued → expired or revoked. Either terminal condition denies the next fetch, including exactly at expiry.

Manual execution and release policy are separate axes: a release can have automated evidence without manual execution. In that case show the pinned release decision if present **and** the manual empty state. For non-release scopes, a manual failure is a count, not a policy FAIL.

## 7. Jobs and integrations

Use the 01.6.1 task queue to build snapshots. Collect the relevant requirement versions and manual cases in sets, preserve uncovered and unlinked rows, and derive section counts from the same pinned inputs. Renderers read only the completed report. XLSX and DOCX reuse the hand-written `AuthoringExporter` OOXML writer; PDF follows the ADR-0002 decision in T4. No third-party document conversion service receives report text.

T7 reads the bound release's components and their run decisions. Join the pinned requirement/case links through `manual_case_link` → `test_case` to the component's automated case results. Do not attribute attempts from another release or component; where one case covers two requirements it may appear in both groups but counts once in its component total. Treat hosted and CI runs alike. Under D-NO-GITHUB any displayed producer-supplied branch/commit is **declared**, not verified.

## 8. Security, privacy and performance

- **Authorization:** Apply the §5 permission on each private route and enforce org/project scope in the worker. Share issuance is not implied by report authorship. Use at least 128 bits of random token entropy; store only the hash. The public read serves just the frozen projection, with `noindex`, no session cookie, no external subresources, and no links granting access to private artifacts or project APIs.
- **Retention/deletion:** Snapshots are immutable project content, not exempt from authorized tenant/project erasure. Purge their shares with the report; disable public caching so revocation takes effect on the next read. Expiry defaults to 30 days; OI-13-604 tracks the proposed maximum. Revocation cannot recall an already downloaded copy.
- **Personal data:** Requirements, test data, strategy, environment and notes may identify people. Include only selected section content, escape it for the target format and warn before sharing. No raw content, share URLs, token values or request paths bearing tokens in logs, traces or audit.
- **Telemetry:** Audit report creation and share issue/revocation by actor, project, report id, time and outcome. Measure build duration, size and failures using bounded labels (scope/format/outcome), not free text or tokens.
- **Failure path:** Validation refusals and failed/oversize jobs expose no snapshot. Couple bounded source reads and renderer limits to an explicit outcome, never silently truncate a matrix or omit a component (OI-13-731). A denial on a private route does not reveal another project's report; a public miss uses the same response for invalid, expired and revoked tokens.

## 9. Test plan

| Boundary | Observable check |
|---|---|
| Snapshot and isolation | Build in one project; change requirement text, a manual result and a release decision; inspect the prior report in all formats. Pins, displayed values and hash stay fixed. Re-deliver the job and force an interrupted build: respectively one report and no partial report. Foreign org and sibling project reads, downloads, builds and share mutations expose nothing. |
| Scope and missing evidence | Cover each scope, stale links, uncovered requirement, unlinked case, no manual run, open run bound to release, pending release, and each recorded decision with reasons. No missing input renders PASS; a non-release report never borrows a release verdict. |
| Export fidelity and safety | Build two snapshots from the same source data, one `vi` and one `en` (each pins its own language and hash). Compare parsed DOCX headings/text, XLSX sheets/cell values, PDF or print output and web text of each format against **its own snapshot's** labels and values, never against the other language's. Pass formula-like and markup-like strings through every section; verify text cells, escaped markup, no external fetch and no extra section. |
| Share boundary | Test read vs write vs project-write roles, issue with default expiry, immediately before and at expiry, revoke with an active browser session, token reuse against a sibling report, and log/cookie/cache/indexing headers. The token cannot read history or source evidence. |
| Automated evidence | Two components with different run decisions, a multi-linked case, an unlinked result and a component lacking evidence. Compare CI and hosted fixtures; verify grouping, reasons and totals without a write to policy. |

## 11. Rollout

At P1/G1, land T1 then T2; T5 can follow T1 independently. Release the export formats after their parity checks and the UI after the design pass. A project with requirements but no run can immediately publish a test plan and a traceability matrix with explicit gaps. Public sharing remains off until a project writer issues a link. At P2/G2, add T7 once component decisions are available. Enable manual evidence display as 13.10.2 and 07.5.5 supply it; never rewrite older snapshots on rollout.
