## 1. Goal and non-goals

A tester runs selected cases by hand against a named build, records what happened and can close the run against an identified release. Closing freezes evidence; it does not calculate a verdict. A closed unbound run is useful in a report but is not release evidence. Opening a run, recording a result and closing a run never create or edit an automated `evaluation` or rewrite a consumed release decision.

This story does not execute scripts, create tracker issues or render exported reports. Policy owns decisions, 06 owns artifact storage and access, and 05 owns releases. No repository is required.

## 2. User stories and acceptance criteria

| ID | As a tester or reviewer, I can… | Observable acceptance |
|---|---|---|
| AC1 | Start from a feature node, requirement or explicit case list | Resolve the selection in the project, deduplicate by case identity and pin each case's authoring version. A later case edit does not change what the tester sees. |
| AC2 | Record and correct a result | `passed`, `failed`, `blocked` and `skipped` are the only results. A correction appends another row. The latest committed row wins; an unexecuted case has no result, not `skipped` or `passed`. |
| AC3 | Attach evidence without publishing private files | Reference 06 artifacts, not file bytes or permanent URLs. Pending scan, rejected upload, insufficient sensitivity permission and foreign references never disclose bytes. |
| AC4 | See what ran and what remains | Summaries show latest result per case plus not-executed counts by feature node and requirement. A case linked to two requirements counts once in run totals. |
| AC5 | Finish a run and know exactly what was frozen | Bound close commits state, release component-set hash, one immutable `manual_evidence_revision` and one `policy.release_aggregate` outbox request together. An unbound close also freezes, with null release fields and no release job. |
| AC6 | Trust terminal state | A fresh result request after close gets `409 manual_run_closed`. A result racing close either commits before the freeze and is represented, or is refused; there is no accepted result outside the snapshot. Repeated close cannot duplicate revisions or jobs. |
| AC7 | Choose a release without a repository | Create through 05.6.1 with user-named components (key, free label, optional digest); bind at creation or while open before close. A label alone never binds the run or verifies a build digest. |
| AC8 | Work without a mouse | Run list, execution, attachment and summary are usable by keyboard in vi and en, including correction, failed upload, read-only and concurrent-close states; WCAG 2.2 AA. |

## 4. Data model and migrations

| Relation | Required data and invariants |
|---|---|
| `manual_run` | `org_id`, project, name, `build_label` (≤128 NFC code points), optional scoped `environment_revision_id`, optional scoped `release_id`, `state`, close time and `release_components_hash` (set at bound close only). Enforce only `open → closed`; reject edits to the binding after close. |
| `manual_run_case` | Run, `manual_test_case_id` and its pinned authoring version; unique case per run. Resolve the version under the same project and identity. |
| `manual_result` | Append-only; run-case, closed status vocabulary, note ≤4,000 NFC code points, server-derived `executed_by` membership and `executed_at`; stable append order per case under the run lock. Store scoped artifact references separately from bytes. |
| `manual_evidence_revision` | Append-only; unique per `manual_run_id`; `release_id`, `release_components_hash`, results JSONB and `content_hash`. Include every selected case ID/version, with latest result ID/status or explicit absence. Hash the canonical snapshot (00 §7); sort by stable case identity, not screen order. |

Use composite tenant/project FKs and FORCE RLS throughout. Index run-case/result lookups for latest-per-case and bound revisions for ordered `(release, closed_at, revision_id)` reads. The release owner supplies the canonical component set: keys, labels, digests (including absence) and the component environment identity where present. Use the same stable component ordering and hash function at close and at aggregation. Do not hash mutable timestamps or display ordering into that set.

## 5. API shapes (commands, queries, endpoints)

Proposed operations for the implementation OpenAPI; use session CSRF and the normal idempotency envelope (00 §9.1–§9.2).

| Operation | Inputs and effect |
|---|---|
| `POST /v1/projects/{p}/manual-runs` | `manual_run:write`; name, build label, one selection, optional environment revision and release. Return run ID, pinned selection and `open`; reject invalid or inaccessible selection rather than silently dropping cases. |
| `POST /v1/manual-runs/{r}/results` | `manual_run:write`; run-case ID, status, optional note and scoped artifact references; `Idempotency-Key`. While open, identical retry produces one result; changed payload with the same key conflicts. A new submission after close returns `409 manual_run_closed`. |
| `POST /v1/manual-runs/{r}/release` | `manual_run:write`; explicit release ID while open. Resolve through 05 in the same project; reject a closed run or an ineligible release. No build-label lookup. |
| `POST /v1/manual-runs/{r}/close` | `manual_run:write`; freeze and return the revision ID, release ID if bound, and `content_hash`; returning a receipt does not mean Policy has finished. |
| Project run list; run detail, summary and coverage queries | `authoring:read`; cursor-page lists. Return pinned case versions, nullable latest result, counts and run state. Artifact bytes and Policy decision details keep their own permission checks. |
| `POST /v1/projects/{p}/releases` | Existing 05.6.1 release creation permission `run:create` applies. T7 extends the component shape for user-named builds without weakening automated digest matching. `manual_run:write` does not grant release creation. |

## 6. States and transitions

`open` accepts append and bind. Serialize append, bind and close on the same scoped run row; acquire the lock before validating the state. Close reads latest rows and the release identity consistently, writes one revision and changes the state to `closed` in the same transaction. Failure before commit leaves the run open and schedules no work. `closed` is terminal: no rebind, reopen or silent correction. Start a new run if the release or the evidence needs correcting.

## 7. Jobs and integrations

Only a bound close enqueues `policy.release_aggregate` for that release; it carries scoped identifiers, not test notes or file bytes. The Policy worker rereads all eligible revisions instead of trusting event arrival order. It must not see a revision without its close or miss a committed wake-up. A retry may redeliver the job, not create a second revision or modify an earlier decision. The 06 upload/secret-scan jobs remain independent of Policy.

## 8. Security, privacy and performance

- **Authorization:** Check `manual_run:write` before create, append, bind and close; `authoring:read` before read. Cross-tenant IDs return 404; scope all joins, including authoring versions, releases, results and files, to the project. Test missing roles, forged case IDs and a sibling project's artifact. No raw blob read through this API.
- **Retention/deletion:** Notes and files may contain personal data. Apply project purge and 06 retention to their respective owners. A file that expires becomes unavailable; it cannot change the pinned result or retroactively change a decision. No app-role update/delete of result or revision rows.
- **Telemetry:** Audit actor, project, action, run, revision, release, outcome and request ID; never log notes, labels, file names, signed links or bytes. Measure close duration and outbox lag without high-cardinality IDs in labels.
- **Failure path:** Validate caps and references before appending; return a scoped error without a partial row. On close rollback leave no revision or enqueue. After commit, an unavailable worker leaves the decision pending or at its last persisted revision, never an optimistic PASS. Use set-based pinned-case and result reads, not one query per case.

## 9. Test plan

- Schema/isolation: cross-tenant and same-tenant cross-project FK probes; cap boundaries (128/129, 4,000/4,001 normalized code points); unknown status, illegal transition, immutable result and revision.
- Integration: all three selection modes; pinned case edit; duplicate result key, append correction, no-result case and duplicate requirement links. A pending or foreign artifact cannot be downloaded through run detail.
- Transaction tests: run append and close in both lock orders; race bind and close; interrupt freeze before the outbox insert; retry close. Assert revision contents, enqueue count and run state, not just status codes.
- Seam with 07.5.5: open failing result cannot alter a decision. Closing an unbound run cannot alter it. Close a bound run under manual policy and drain the job: a new decision can differ, but the previously consumed decision ID/hash/bytes and the automated evaluation rows are unchanged.
- UI acceptance: keyboard-only create → select → record → attach → close → summary; labels, focus, errors and counts in vi and en. Repository-less release with a null digest exercises the same flow; automated binding never treats null as a digest match.
